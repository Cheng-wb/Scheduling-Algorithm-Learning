# Day 5：Simulated Annealing（模拟退火）

[周计划](../README.md)

## 学习目标与基本思想

普通局部搜索只接受严格改进，因此无法沿着 $30\to33\to27\to22$ 这样的路径前进。随机重启通过更换起点探索其他区域；模拟退火（SA）则修改接受规则，在同一次搜索中以一定概率接受较差候选。

物理退火的直觉是高温时状态变化活跃，降温后逐渐稳定。优化中对应高温扩大探索、低温减少较差移动。允许变差只是提供离开当前区域的机会，不保证一定找到更好的解。

## Current、Best 与 Delta

| 变量 | 含义 |
| --- | --- |
| Current | 当前搜索位置，可以因探索而变差 |
| Best | 搜索以来发现的最好解，只在严格改善时更新 |
| Neighbor | 从 Current 随机产生的候选 |
| Delta | 候选目标值减去当前目标值 |

对最小化问题：

$$
\Delta=f(\pi')-f(\pi).
$$

$\Delta<0$ 表示改善，$\Delta=0$ 表示等值，$\Delta>0$ 表示变差。Delta 与 Current 比较，而不是与历史 Best 比较。

例如 Best 为 20，Current 接受值为 25 的候选后，Best 仍为 20；后续 Current 降至 18，Best 才更新为 18。最终返回历史 Best，同时保留最终 Current 供分析。保存二者时复制列表，避免共享可变排列。

## 接受概率与手算

实现采用：

$$
P(\text{accept})=
\begin{cases}
1,&\Delta\le0,\\
\exp(-\Delta/T),&\Delta>0.
\end{cases}
$$

较差候选生成随机数 $u\in[0,1)$，仅当 $u<P$ 时接受。等值候选直接接受，计入 `accepted_equal`，不计入差解接受次数。

当 $\Delta=5$：

| 温度 $T$ | 接受概率 |
| ---: | ---: |
| 100 | 0.9512 |
| 10 | 0.6065 |
| 1 | 0.0067 |

温度越高，同一差解越容易接受；固定温度时，Delta 越大越难接受。概率是单次判断的阈值，不意味着每若干次必须接受固定数量。

## Temperature 与 Cooling Schedule

每评价一个随机候选后进行几何降温：

$$
T_{k+1}=\alpha T_k,\qquad 0<\alpha<1.
$$

本实现无论候选是否接受都降温，每个温度只尝试一个邻居。更换降温频率会改变算法行为，不能只比较同名参数。

初温过低时很少接受差解，接近随机贪心改进，但仍会接受等值移动，也不会像 Best Improvement 那样完整扫描邻域。初温过高可能花较多预算进行近似随机游走。温度应与目标差值的尺度匹配，不存在通用最优初温。

$\alpha$ 越接近 1，降温越慢；固定迭代上限时不一定增加实际评价次数，但预算结束时可能仍处于较高温度。若主要由最低温度停止，慢降温通常意味着更多候选评价。

## 随机邻居与 SA 流程

复用 `random_swap_neighbor(current, rng)`：随机抽取两个不同位置，交换后返回新列表，不修改 Current。

```text
初始解 → Current = Best = 初始解
      → 随机 Swap → 解码评价 → 计算 Delta
      → 判断接受 → 更新 Current → 必要时更新 Best
      → 降温 → 下一次候选
```

核心接受逻辑：

```python
delta = neighbor_score - current_score
probability = 1.0 if delta <= 0 else exp(-delta / temperature)
accepted = delta <= 0 or rng.random() < probability
if accepted:
    current, current_score = list(neighbor), neighbor_score
if current_score < best_score:
    best, best_score = list(current), current_score
```

搜索函数接收初始排列、解码器、目标函数和随机邻居函数，不依赖 SPT 或特定调度指标。实验选择 SPT 起点、随机 Swap、最小总延期。

## 停止条件与迭代含义

- `max_iterations`：最多评价指定数量的随机候选，拒绝也算一次迭代。
- `min_temperature`：准备下一次候选时，温度已低于阈值则停止。
- `no_neighbors`：少于两个任务，无法进行随机 Swap。

默认 $T_0=100$、$\alpha=0.95$、最低温度 $10^{-6}$、候选上限 1000。实际先触发温度停止，只评价 360 个候选，而不是 1000 个。

SA 的迭代次数与局部搜索的“成功更新次数”含义不同，不能直接比较。SA 停止也不构成局部最优证明，因为没有完整检查最终邻域。

初温和最低温度必须为有限正数；降温率必须在 $(0,1)$ 内。候选上限为零时保留初始解，不执行随机操作。温度阈值检查避免除零和极低温下继续无效迭代。

## Search History 与差解统计

每个候选记录：`iteration`、`temperature`、`neighbor_score`、`delta`、`probability`、`draw`、`accepted`、`current_score`、`best_score`。

记录的温度是该轮接受判断所用温度；Current 与 Best 是判断后的值。History 不额外包含初始行，初始值通过 `initial_score` 保存。

Current 允许上下波动，Best 只能不变或下降。`accepted_worse` 仅统计 $\Delta>0$ 且被接受的候选；改善、等值接受分别统计。

默认实例前几轮中，Current 从 413 上升到 543、602，而 Best 仍为 413，体现了接受较差解与保存历史最好解的区别。

## 实验设置与默认轨迹

沿用 `restart_jobs(data_seed=42)` 的 20 任务实例，$p_i\in[1,20]$、$d_i\in[20,150]$、$r_i=0$，SPT 初始总延期为 413。搜索种子为 42。

默认 SA 最好值为 **284**，改善量为 **129**，最终 Current 也为 284。共评价 360 个候选，接受 10 次差解；前半段有 127 个较差候选、接受 10 个，后半段有 161 个较差候选、接受 0 个。

这种分布符合降温后更保守的行为，但单次路径中的 Delta 分布也在变化，不能只用接受数量推断温度的全部作用。

## Seed 与结果稳定性

局部 RNG 同时用于随机 Swap 和较差候选的接受抽样，不修改全局随机状态。相同输入、参数、种子与实现可复现轨迹；不同参数可能改变随机数消耗和路径，同一个 seed 不保证候选序列完全一致。

固定默认参数，搜索种子 0～4 的最好值依次为 **290、310、281、271、296**：最好 271，均值 289.60，最差 310。每次均使用 361 次目标评价。

单次幸运结果不能代表算法稳定性；这组统计也只描述该实例和所选种子。

## Local Search / Multi-start / SA 对比

使用同一实例、总延期目标与 Swap 操作。单次 LS 和 SA 使用相同 SPT 起点，多起点使用搜索种子 42 的 20 个随机排列。

| 方法 | 最好值 | 相对 SPT 改善量 | 目标评价次数 | 耗时示例（秒） |
| --- | ---: | ---: | ---: | ---: |
| SPT | 413 | 0 | 1 | — |
| SPT + Best LS | 296 | 117 | 1521 | 0.37 |
| 20-start LS | 260 | 153 | 61580 | 13.65 |
| SPT + SA | 284 | 129 | 361 | 0.08 |

多起点评价次数包含各次初始值。计时包含搜索内解码、校验和目标计算，不包含打印和结束后的复核，也不包含生成 SPT 的时间；具体秒数随环境变化。

LS 只接受严格改进，多起点通过换起点探索，SA 在路径中概率接受差解。该表是指定配置的运行对照，预算并不相等，不能据此作公平的算法强弱排名，也未证明 260 为全局最优。

## 公平预算与实现检查

更严格的评测应统一目标评价上限或墙钟时间，并使用相同实例集、多个种子，报告实际消耗和停止原因。相同 `max_iterations` 不等于相同预算：LS 一轮可能枚举整个邻域，SA 一轮只评价一个候选，且温度阈值可能提前停止。

实现需避免 Delta 方向写反、与 Best 计算 Delta、拒绝后不降温、把等值移动计为差解、原地修改 Current，以及最终只返回 Current。

实验直接核对接受记录、Current/Best 更新关系、返回排程合法性与目标值一致性；另外验证固定种子的复现、输入不变、温度下降、零迭代及空/单任务情况。概率与温度依赖数据尺度，参数实验不能替代正确性检查。

## 项目接口与后续评测

核心算法位于 `search/simulated_day5_simulated_annealing.py`，返回最好解、最终 Current、历史、接受统计、评价次数和停止原因。`experiments/day5_simulated_annealing.py` 负责轨迹展示、参数实验、跨种子统计及方法对照。
