# Day 4：局部最优、随机初始解与 Multi-start

[周计划](../README.md)

## 学习目标与前置知识

局部搜索从初始排列出发，反复接受更好的邻居，直到当前邻域没有严格改进。随机重启保留这套搜索逻辑，通过多个起点探索不同区域，并保存历史最好结果。

实验固定单机、不可抢占、任务可自由排列、释放时间为零，目标为最小总延期，邻域为 Swap，单次搜索使用 Best Improvement。

## Local Optimum 与 Global Optimum

令 $\Omega$ 为全部可行排列，$N(\pi)$ 为排列 $\pi$ 的邻域。最小化问题中：

$$
\text{局部最优：}\quad f(\pi)\le f(\pi'),\quad\forall\pi'\in N(\pi),
$$

$$
\text{全局最优：}\quad f(\pi^*)\le f(\pi'),\quad\forall\pi'\in\Omega.
$$

局部最优允许邻居同分，只要求没有严格更好的邻居。全局最优一定也是给定可行邻域下的局部最优，反过来不成立。局部最优可能恰好是全局最优，但普通局部搜索不能据此证明。

达到迭代上限也不等于达到局部最优。代码保留每次搜索的 `stop_reason`，只有完整扫描后无改进才标记 `no_improvement`。

## 搜索地形与吸引域

可以将目标值想象成高度，将一次 Move 视为地形上的一步。严格下降搜索只走向更低的位置，到谷底后停止；更深的谷底可能需要先经过较高位置或等值平台才能到达。

真实排列空间不是连续曲线，哪些解相邻由 Move 定义。改变 Swap 为 Insert，相当于改变一步可达关系。

在目标、邻域、枚举顺序和并列处理都固定时，收敛到同一个终点的起点集合称为该终点的**吸引域（Basin of Attraction）**。一个较差终点也可能拥有较大的吸引域，因此随机起点可能多次落到较差区域。

相同目标值不代表相同终点。实验按最终目标值统计频次只能描述分数分布，不能直接当作吸引域大小。

## Initial Solution 的影响

不同起点决定不同的搜索路径，可能收敛到不同局部最优。比较 FCFS、SPT、EDD、Random 时，应固定任务数据、目标、邻域与单次搜索算法。

随机初始化不是一种必然优于规则的排序策略，其价值是增加起点的多样性。

```python
def random_solution(jobs, rng):
    solution = list(jobs)
    rng.shuffle(solution)
    return solution
```

复制后打乱只改变排列，不改变任务属性和原始输入。随机起点可能重复，并不保证每次访问新的吸引域。

## Multi-start 的流程

```text
随机起点 → Local Search → 本次结果 ─┐
随机起点 → Local Search → 本次结果 ─┼→ 比较并保存历史最好结果
随机起点 → Local Search → 本次结果 ─┘
```

核心逻辑为重复调用已有搜索：

```python
for restart in range(num_restarts):
    initial = random_solution(jobs, rng)
    result = local_search(initial, build_schedule, objective)
    if result["score"] < best_score:
        best_solution = list(result["solution"])
        best_score = result["score"]
```

本项目 `num_restarts=20` 表示总共执行 20 次随机起点搜索，包含第一次，不是首次之外再运行 20 次。预算必须为正整数；同分保留最先发现的结果。

## 当前结果、历史最好与 Restart History

第 $k$ 次搜索的最终值 $f_k$ 可以高于或低于上一次结果，但历史最好值满足：

$$
b_k=\min(b_{k-1},f_k),\qquad b_k\le b_{k-1}.
$$

因此单次局部搜索的目标历史严格下降，重启之间的最终值可以波动，而 `best_score` 单调不增。

| 字段 | 含义 |
| --- | --- |
| `restart` | 从 1 开始的起点编号 |
| `initial_solution`、`initial_score` | 本次随机起点与目标值 |
| `solution`、`final_score` | 本次搜索返回的排列与目标值 |
| `best_score` | 截至本次的历史最好值 |
| `iterations` | 本次接受改进的次数 |
| `neighbor_evaluations` | 本次搜索评价的邻居数 |
| `stop_reason` | 无改进或达到上限 |
| `elapsed` | 从整次 Multi-start 开始的累计耗时 |

返回结果还包含最好排列、最好值、首次获得最好值的 `best_restart`、搜索种子和总耗时。

## Seed 与可复现性

使用局部 `Random(seed)`，在一次 Multi-start 开始时初始化，之后连续调用同一个 RNG。若每次重启都重新设置相同种子，就会重复同一个随机起点。

数据种子控制任务属性，搜索种子控制排列。固定数据，只改变搜索种子，才能观察搜索的随机性；同时改变任务数据会混入实例差异。

相同输入顺序、随机种子、生成逻辑、搜索规则及兼容的运行环境可复现起点和搜索结果，耗时不要求相同。代码不修改全局随机状态。

## 完整实验设置

20 个任务，$p_i\in[1,20]$、$d_i\in[20,150]$、$r_i=0$，数据种子为 42；单次搜索上限为 1000 次成功更新。

1. 比较 FCFS、SPT、EDD、Random 起点的同一 Swap + Best 搜索。
2. 搜索种子为 42，运行 50 个随机起点，保存逐次历史。
3. 取前 1、5、10、20、50 次结果，比较嵌套预算。
4. 固定同一实例，搜索种子分别取 0～4，按预算统计最好、平均、最差结果。

单次 Random 搜索与 50-start 的第一轮使用相同起点。各预算来自同一序列的前缀，增加预算才严格包含已有结果。不同种子下两次独立运行不具备这种包含关系。

## 单次搜索与多起点结果

默认实例的单次搜索：

| 起点 | 初始总延期 | 最终总延期 | 更新次数 | 邻居评价次数 |
| --- | ---: | ---: | ---: | ---: |
| FCFS | 811 | 260 | 15 | 3040 |
| SPT | 413 | 296 | 7 | 1520 |
| EDD | 358 | 260 | 8 | 1710 |
| Random，seed=42 | 928 | 296 | 12 | 2470 |

初始分数更好不一定意味着最终分数更好，例如 FCFS 初始值差于 SPT，却得到更好的终点。

搜索种子 42 的多起点预算比较：

| 起点数 | 历史最好总延期 | 累计邻居评价次数 | 累计耗时示例（秒） |
| ---: | ---: | ---: | ---: |
| 1 | 296 | 2470 | 0.55 |
| 5 | 262 | 15390 | 3.41 |
| 10 | 260 | 31350 | 6.99 |
| 20 | 260 | 61560 | 13.70 |
| 50 | 260 | 151810 | 33.90 |

第 6 个起点首次得到 260。后续 44 次没有改善历史最好值，50 次结果中有 12 次最终值为 260。Multi-start 改善了这次随机单起点结果，但没有优于 FCFS/EDD 的单次结果。

260 只是在这些实验中找到的最好值，未经全局最优证明。额外起点可能没有明显收益，但一次没有收益也不能证明继续搜索永远无效。

## Runtime 与计算代价

若第 $k$ 次 Best 搜索接受 $t_k$ 次改进，并因无改进正常停止，Swap 邻居评价总数为：

$$
\sum_{k=1}^{R}(t_k+1)\frac{n(n-1)}2.
$$

其中每次最后的无改进扫描也计入。实际耗时还包含随机初始化、每个候选的解码、校验和评价，以及历史记录。

实验计时不包含打印和搜索结束后的独立复核。预算表的耗时来自同一次运行的累计时间，不是分别重新启动程序测量；具体秒数受运行环境影响。

## 稳定性、代码组织与验证

多次独立搜索应同时比较最好值、均值和最差值，不能只挑一次幸运结果。小样本的表现只描述固定实例及所选种子，不代表所有调度实例。

同一实例、搜索种子 0～4 的结果如下；每个统计样本是对应预算的一次 Multi-start 最好值：

| 起点数 | 跨种子最好值 | 均值 | 最差值 |
| ---: | ---: | ---: | ---: |
| 1 | 260 | 275.20 | 296 |
| 5 | 260 | 260.80 | 262 |
| 10 | 260 | 260.40 | 262 |
| 20 | 260 | 260.00 | 260 |
| 50 | 260 | 260.00 | 260 |

各次搜索均正常停止。该样本中，增加起点数降低了平均值与最差值；20 与 50 起点的结果相同。五个种子结果一致只表示本组实验较稳定，不构成全局最优证明。

`scheduling/dispatching.py` 提供随机起点；`search/local_search.py` 组合多次已有搜索；`experiments/day4_random_restart.py` 配置数据、打印历史和统计结果。

实验核对任务完整性、输入不变性、最终排程与目标值、每次无改进终点的邻域，以及历史最好值是否等于已完成各次结果的最小值。固定种子的复现比较忽略耗时字段；达到上限的结果保留原停止原因。

## 与 Simulated Annealing 的衔接

Random Restart 在一次搜索结束后更换起点，单次搜索仍只接受严格改进。Simulated Annealing 则在搜索过程中按一定概率接受较差候选，以尝试离开当前区域，因此必须区分 Current 与历史 Best。

两者都增加探索机会，但都不能仅凭启发式运行结果宣称全局最优。
