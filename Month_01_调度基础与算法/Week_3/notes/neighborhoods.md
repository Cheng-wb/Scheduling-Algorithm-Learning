## 1. 解与邻域

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| Solution | 当前任务排列 | A B C D E |
| Move | 对排列执行的一次操作 | 交换位置 1 和 3 |
| Neighbor | 执行 Move 后的排列 | A D C B E |
| Neighborhood | 按指定操作可得到的全部邻居 | 所有交换两个不同位置得到的排列 |

单机、任务可自由排序且使用固定解码器时，可以用任务排列表示解。$n$ 个不同任务共有 $n!$ 种排列，而一层邻域只检查其中的一部分。

```text
当前排列 → Move → 邻居排列 → build_schedule → objective
```

邻域生成负责修改顺序，调度模块重新计算时间，评价模块计算目标值。改变顺序后，不能直接交换旧排程中的完工时间。

## 2. 三种 Move

索引从 0 开始，以 A B C D E 为例：

| 操作 | 结果 | 含义 |
| --- | --- | --- |
| `swap(1, 3)` | A D C B E | 交换两个位置 |
| `insert(3, 1)` | A D B C E | 取出 D，插入最终位置 1 |
| `insert(1, 3)` | A C D B E | 取出 B，插入最终位置 3 |
| `reverse(1, 3)` | A D C B E | 翻转闭区间 [1, 3] |

Insert 的目标索引指**结果中的最终位置**。实现为先 `pop(from_idx)`，再 `insert(to_idx, job)`，不再额外调整目标索引。Swap 只交换两个任务；Insert 保持其余任务的相对顺序；Reverse 反转整个区间。

所有操作返回新列表，任务对象不变。`Job` 是不可变数据类，浅复制列表即可。直接调用时相同索引返回独立的等值列表；邻域枚举跳过这种不改变排列的操作。负索引与越界索引均不接受。

## 3. 邻域生成与规模

Swap 只枚举 $i<j$，避免 `swap(i,j)` 与 `swap(j,i)` 重复，也排除 $i=j$。

$$
|N_{swap}|=\frac{n(n-1)}2.
$$

| 任务数 | Swap 邻居数 |
| ---: | ---: |
| 5 | 10 |
| 6 | 15 |
| 10 | 45 |
| 100 | 4950 |
| 1000 | 499500 |

Insert 有 $n(n-1)$ 个非平凡操作，但相邻任务的前移和后移会产生同一排列。对不同任务组成的排列，去重后为 $(n-1)^2$ 个邻居（$n\ge1$）。代码跳过 `from_idx == to_idx + 1`，保留对应的相邻后移。Reverse 枚举所有长度至少为 2 的区间，邻居数也为 $n(n-1)/2$，但集合通常与 Swap 不同。

`generate_neighbors(solution, kind)` 返回生成器，通过 `yield` 逐个生成新列表；当前排列在遍历过程中保持不变。空序列和单任务序列没有邻居。

邻居数为 $O(n^2)$，复制每个排列需要 $O(n)$。仅生成整个邻域就需要 $O(n^3)$ 时间；逐个消费时，候选列表占用 $O(n)$ 额外空间。实际还需叠加每个排程的解码、校验和评价成本。生成器节省同时存储候选的内存，不减少候选数量。

完整枚举可以找到一层邻域中的最佳候选；随机 Swap 只采样一个邻居。传入 `Random(seed)` 可复现采样结果，少于两个任务时无法进行随机交换。

## 4. 目标值与最佳邻居

采用最小总延期目标：

$$
f(\pi)=\sum_i\max(0,C_i(\pi)-d_i).
$$

`evaluation/objective.py` 从 `evaluate(schedule)` 中提取 `total_tardiness`，所有候选使用相同目标。

最佳邻居为 $\arg\min_{\pi'\in N(\pi)}f(\pi')$，它可能优于、等于或差于当前解。只有 $f(\pi')<f(\pi)$ 才属于严格改进。邻域为空时不存在最佳邻居，不能用当前解冒充。

$$
\Delta=f(\pi)-f(\pi'),\qquad
\text{改善比例}=\frac{\Delta}{f(\pi)}.
$$

$\Delta>0$ 表示改进，$\Delta<0$ 表示退步；初始目标为零时，改善比例记为 `N/A`，避免除零。

最佳邻居不等于全局最优。某个邻域没有严格改进，也不代表其他邻域没有改进。反复接受邻居并重新生成邻域才构成局部搜索；一层实验只比较候选，不更新当前解。

## 5. 六任务实验

实验入口为 `experiments/neighborhoods.py`，默认枚举 Swap 邻域，可用 `--neighborhood insert` 或 `--neighborhood reverse` 比较其他邻域。

任务按 J1～J6 输入，$p=[8,3,6,2,7,4]$，$d=[12,7,20,15,14,10]$，$r_i=0$。

SPT 初始排列为 J4 → J2 → J6 → J3 → J5 → J1，完工时间为 $[2,5,9,15,22,30]$，总延期为 $8+18=26$。

完整扫描 15 个 Swap 邻居：

| 比较结果 | 数量 |
| --- | ---: |
| 优于初始解 | 2 |
| 等于初始解 | 2 |
| 差于初始解 | 11 |

最佳邻居由 `swap(3,4)` 得到：J4 → J2 → J6 → J5 → J3 → J1。完工时间为 $[2,5,9,16,22,30]$，总延期为 $2+2+18=22$，绝对改善为 **4**，改善比例为 **15.38%**。

SPT 最小化总完工时间，并不保证总延期最小，因此以总延期为目标仍可能找到改进。两种排列的 Makespan 都为 30，无法用它区分延期表现。

所有候选均重新构造排程并校验任务完整性。在任务可自由排列的单机场景下，这些 Move 保持可行；若存在工序先后或机器适配约束，仍需额外保证邻居满足约束。
