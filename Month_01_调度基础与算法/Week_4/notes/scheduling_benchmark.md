## 1. 统一工作流

```text
生成 Jobs → Algorithm → Schedule → Validation → Evaluation
                              └→ Gantt          └→ Benchmark Table
```

| 模块 | 职责 |
| --- | --- |
| `models.py` | 定义任务与排程的数据结构 |
| `exact/`、`heuristics/` | 接收任务，返回 `Schedule` |
| `generators/job_generator.py` | 按参数和随机种子生成实例 |
| `validation.py` | 对照输入检查任务完整性、属性、时长、释放时间和机器冲突 |
| `metrics.py`、`evaluator.py` | 计算并汇总指标 |
| `benchmark.py` | 统一运行、计时、记录失败、计算 Gap 与分组统计 |
| `visualization/gantt.py` | 将 `Schedule` 画成甘特图 |
| `experiments/benchmark_suite.py` | 配置实验组、注册算法、保存数据和结果 |

算法只负责排程。运行时间由外部测量，数据导出和打印由实验入口负责。

## 2. 公平比较与可复现性

- 同一实例使用相同的任务属性、输入顺序、机器数和约束。各算法得到独立列表，避免排序修改影响后续算法。
- 单机重点比较 $\sum C_i$、$\sum w_iC_i$、$\sum T_i$、$\sum w_iT_i$；并行机重点比较 $C_{\max}$、负载下界和利用率。
- MILP 的最优性只针对建模目标：最小加权延期不代表总延期或总完工时间也最小。
- 固定种子并保存实际任务、生成参数和依赖版本。相同种子不保证不同生成器实现产生相同数据。
- Runtime 包含算法调用内部的建模、求解和排程提取；不包含外部校验、评价、打印和绘图。耗时会随机器和运行环境变化。

最小化目标的相对差距：

$$
Gap=\frac{f_{alg}-f^*}{f^*}.
$$

仅使用同一实例、同一目标且已证明最优的 $f^*$。没有最优基准时记为 `N/A`；$f^*=0$ 时，算法值也为零则记为 0，否则记为无穷大。数值容差内的微小差异视为零。

对全部任务在零时刻可用的相同并行机：

$$
LB=\max\left\{\max_i p_i,\frac{\sum_i p_i}{m}\right\},\qquad
U=\frac{\sum_i p_i}{mC_{\max}}.
$$

整数加工时间可以对平均负载向上取整。下界与最优值是不同概念，只有排程达到下界时才能直接证明最优。

## 3. 实验设置与结果

所有实验均取 $r_i=0$、$p_i\in[1,20]$。固定实例使用 `seed=42`。

| 实验组 | 设置 | 比较内容 |
| --- | --- | --- |
| 单机规则 | 20 个任务，$d_i\in[20,100]$，$w_i\in[1,10]$ | FCFS、SPT、EDD、WSPT |
| 单机精确比较 | 6 个任务，$d_i\in[10,40]$，$w_i\in[1,10]$ | 四种规则与最小加权延期 MILP |
| 并行机 | 20 个任务、3 台机器 | Greedy、LPT、最小 Makespan MILP |
| 批量比较 | 单机 6 个任务；并行机 20 个任务、3 台机器；种子 1～5 | 各组分别计算均值与最差 Gap |
| 规模比较 | 10、20、50、100 个任务，5 台机器 | Makespan 与运行时间 |

固定单机 20 任务中，SPT 的总完工时间为 **1714**，WSPT 的加权完工时间为 **7583**，分别是对应指标的最优值：这里满足单机、同时释放、无额外约束的适用条件。EDD 不保证总延期或加权延期最优。

固定单机 6 任务中，EDD 的加权延期为 **431**，MILP 为 **270**。甘特图展示两者不同的任务顺序；应结合交期和权重解释，而不能只看排程长度。

固定并行机实例中，Greedy、LPT、MILP 的 Makespan 分别为 **58、55、55**，下界为 **55**；Greedy 的 Gap 为 **5.45%**。

并行机批量结果：

| 算法 | 平均 Makespan | 平均 Gap | 最大 Gap |
| --- | ---: | ---: | ---: |
| Greedy | 78.6 | 7.03% | 10.17% |
| LPT | 74.2 | 0.81% | 1.69% |
| MILP | 73.6 | 0% | 0% |

这 5 个实例的 MILP 均证明最优。LPT 在固定实例上最优，但在批量实例上仍存在差距；少量样本只能描述这组数据的表现。

## 4. 结果解读与扩展

`benchmark.csv` 保存每次运行的指标、耗时、状态及失败原因；`summary.csv` 按问题类型、规模、机器数、目标和算法分组。指标均值仅统计成功结果，平均耗时包含失败调用，Gap 单独记录可用样本数，不能把失败当作零分。

甘特图以时间为横轴、机器为纵轴，矩形长度表示加工时间。同一实例中的任务颜色保持一致，便于比较顺序、负载与空闲；可视化辅助检查，合法性仍由校验器判定。

精确方法提供最优基准，规则和启发式以较低计算成本获得排程。新增算法只需遵守 `jobs → Schedule` 接口并加入算法表，即可复用校验、指标、统计和绘图流程。
