## 1. 今日学习目标

完成今天的学习后，你应该能够：

1. 用一句话说清「运输模型的一条变量就是网络的一条边」，并把一张运输表拆成节点、边、流量三样东西。
2. 独立写出两仓两客的运输模型，只用「令 $x_{11}=q$」这一步就把四个变量压成一个自由变量，并手算到最优方案与最优费用。

6. 准确复述全幺模的定义：**所有**方形子矩阵的行列式都取自 $\{-1,0,1\}$，而不是「用到的那个基行列式为 $\pm1$」。

8. 读一次项目脚本的运输与指派结果，把状态、目标值、约束残差和对偶不变量分开核对，而不是只看最后一个数字。

## 2. 为什么第 3 天要把「结构」单独拿出来

Day 1 把业务翻译成 LP，Day 2 把 LP 交给求解器并学会读结果。那两天的模型都是「一列一种活动、一行一种资源」。今天换一类模型：写起来几乎一模一样，但**读结果的方式完全不同**。

1. **同一种写法，不同的含义。** 生产计划的一列是「生产 A 多少」，运输模型的一列是「从仓库 1 到客户 2 运多少」。两者都能写成 $Ax=b$ 加 $x\ge0$，但运输模型的每一行是**一个节点的流量守恒**，而每一条变量恰好出现在两条行里（一条供给行、一条需求行）。这个「每条变量只进两行」的性质，是后面一切结论的来源。
2. **结构决定了「不声明整数也可能拿到整数」。** 指派模型业务上明明是 0–1 决策，把整数要求去掉直接解 LP，却常常返回 0/1。这不是运气，也不是求解器偷偷做了四舍五入，而是极点结构决定的。把这一点读错，就会把「这一次恰好是整数」当成「这个模型永远给整数」。
3. **结构也会被一次随手的加约束破坏。** 很多人喜欢在指派模型上再补一条预算或工时约束，然后继续期待整数解 —— 这正是今天要防的错误。
4. **结构对后面的排程同样重要。** 单机排序、时间索引的调度模型里有大量「本来就是 0–1」的变量，能不能先解 LP 松弛、松弛解会给出什么，是判断「要不要上 MILP」的关键一步。

一句话：**Day 1 与 Day 2 学的是「怎么把一件事写成 LP」，今天学的是「写出来的 LP 是什么形状，这个形状会给你什么、又会拿走什么」。** 今天要留在笔记里的产出有两样：一张**二部图**（第 4 节，一条变量画成一条边）和两条**勘误**（第 7、8 节）—— 勘误记的不是新知识，而是最容易讲错的边界。

## 3. 运输模型：一条变量就是一条边

### 3.1 从「资源」换成「网络」

供应方集合 $I$（仓库、工厂、产地），需求方集合 $J$（客户、门店、销地）。$a_i$ 是 $i$ 的供应量，$b_j$ 是 $j$ 的需求量，$c_{ij}$ 是从 $i$ 到 $j$ 的单位运费，$x_{ij}\ge0$ 是从 $i$ 发往 $j$ 的货量。模型是：

$$\min\ \sum_{i\in I}\sum_{j\in J}c_{ij}x_{ij}$$
$$\sum_{j\in J}x_{ij}=a_i\quad(\forall i\in I),\qquad \sum_{i\in I}x_{ij}=b_j\quad(\forall j\in J),\qquad x_{ij}\ge0.$$

前 $|I|$ 条是「每个仓库发出去的货等于它的供应量」，后 $|J|$ 条是「每个客户收到的货等于它的需求量」。它们全都是等式，所以要求总供应等于总需求：

$$\sum_{i\in I}a_i=\sum_{j\in J}b_j .$$

先把它和前两天的模型摆在一起看，差别立刻清楚了：

| | 生产计划（Day 1–2） | 运输模型（今天） |
|---|---|---|
| 索引 | 产品、资源 | 供应方 $i$、需求方 $j$ |
| 一条变量是什么 | 一种产品的产量 | 二部图上一条边上的流量 |
| 一行是什么 | 一种资源的用量上限 | 一个节点的流量守恒 |
| 一条变量进几行 | 该产品消耗几种资源就进几行 | **恰好两行**：一个源、一个汇 |
| 右端项 | 资源总量，约束是 $\le$（可以有剩余） | 供应量、需求量，约束是 $=$（必须出清） |
| 系数矩阵从哪来 | 消耗系数表，任意非负整数 | 二部图的节点–边关联矩阵，元素只有 0 与 1 |

第三行和第四行是今天的全部重点。生产计划里一条变量可以出现在很多行（一件产品同时吃机器、人工、原料）；运输里一条变量**只**出现在两行，这正是「网络结构」四个字的操作含义。

### 3.2 供需不平衡时怎么办

等式模型要求产销平衡。现实里常常不平衡，这时**不是数学问题，是业务问题**：多出来的货去哪儿、少的货怎么补，必须由业务决定，再翻译成模型。

| 业务情形 | 建模做法 | 虚拟边的费用必须表达什么 |
|---|---|---|
| 供应多于需求，允许库存 | 加一个虚拟客户，吸收掉多余供给 | 仓储费、资金占用成本 |
| 需求多于供应，允许缺货 | 加一个虚拟仓库，补足缺口 | 缺货惩罚（延期交付的赔偿） |
| 允许外购 | 加一个虚拟仓库，成本取采购价 | 采购价，必要时再加把货从别处运来的运费 |
| 都不允许 | 不加虚拟节点，让模型不可行 | 不可行是有用的结论，不要用零成本把它掩盖成可行 |

最后一行值得多说一句。**虚拟边的费用不能随意设零**：一条零费用的虚拟边等于宣称「缺货不花钱、库存不花钱、外购不要钱」，模型会毫不犹豫地把所有缺口都塞给它，算出来的最优值比真实成本低一大截，而表面上一切正常。虚拟边的费用是一个**业务参数**，和真实运费一样要能说出出处。

项目里对这个决策的处理方式是「不替使用者做决定」：`build_transportation_lp` 在总供应与总需求相差超过容差时直接抛出 `ValueError`，而不是悄悄补一个虚拟节点。原因写在源码注释里：自动补节点会在调用方不知情的情况下改变模型规模与变量含义，而「补哪一侧、费用定多少」是建模决策，应该由建模的人写下来。

## 4. 手算：两仓两客，四个变量只剩一个自由变量

这是教材第 1 章 1.7 节的小例，今天的全部手算都围绕它。两个仓库供应 3、2，两个客户需求 2、3，单位费用为：

| | 客户 1 | 客户 2 | 供应 |
|---|---:|---:|---:|
| 仓库 1 | 1 | 4 | 3 |
| 仓库 2 | 3 | 2 | 2 |
| 需求 | 2 | 3 | 5 |

模型写全：

$$\min\ x_{11}+4x_{12}+3x_{21}+2x_{22}$$
$$x_{11}+x_{12}=3,\qquad x_{21}+x_{22}=2,$$
$$x_{11}+x_{21}=2,\qquad x_{12}+x_{22}=3,\qquad x_{ij}\ge0\ (i,j=1,2).$$

四个变量、四条等式。如果这四条等式互相独立，四个变量就被唯一确定，谈不上「优化」；实际自由度是 1，原因是第 5 节要讲的冗余。把这一步完整摊开：

```text
第 1 步：取 x11 = q 作为那个自由变量。
第 2 步：用供给行 1      x11 + x12 = 3   ->  x12 = 3 - q
第 3 步：用需求行 1      x11 + x21 = 2   ->  x21 = 2 - q
第 4 步：用供给行 2      x21 + x22 = 2   ->  x22 = 2 - x21 = q
第 5 步：用需求行 2 复核 x12 + x22 = (3 - q) + q = 3   ✓ 自动成立
第 6 步：非负性给出 q 的取值范围
         x11 = q   >= 0  ->  q >= 0
         x12 = 3-q >= 0  ->  q <= 3
         x21 = 2-q >= 0  ->  q <= 2   <- 最紧的一条
         x22 = q   >= 0  ->  q >= 0
         合起来：0 <= q <= 2
第 7 步：把四个变量代回目标
         q + 4(3-q) + 3(2-q) + 2q
       = q + 12 - 4q + 6 - 3q + 2q
       = 18 - 4q
第 8 步：18 - 4q 关于 q 的斜率是 -4 < 0，目标越小越好，
         所以 q 取可行区间的上界 q = 2。
第 9 步：最优方案
         x11 = 2   x12 = 1
         x21 = 0   x22 = 2
         最优费用 = 18 - 4*2 = 10
第 10 步：把方案逐条代回原始约束复核
         仓库 1 发出 2 + 1 = 3  ✓   仓库 2 发出 0 + 2 = 2  ✓
         客户 1 收到 2 + 0 = 2  ✓   客户 2 收到 1 + 2 = 3  ✓
```

第 10 步不是形式主义：手算里最容易错的地方正是「哪条约束决定了 $q$ 的上界」和「哪一条被当成复核用掉了」。把四个数代回四条等式，才是这一步的验收。

四个变量塌缩成一个 $q$ 的过程，正好是 Day 2 里「基本变量 / 非基变量」在最小实例上的形状：$q$ 是非基变量，另外三个是基变量（本实例的基变量个数是 $3=m+n-1$，见第 5 节）。

**这张图是同一个问题的另一种写法**：

![运输问题的二部图：一条变量就是一条边，灰色边流量为零](../../projects/02_optimization_models/artifacts/figures/transport_network.png)

图注：左列是仓库 W1（供应 3）与 W2（供应 2），右列是客户 C1（需求 2）与 C2（需求 3）；四条连线就是四个变量，方框里的两个数是「单位运费」与「当前流量」，边越粗流量越大。最优解 $q=x_{11}=2$ 时，W1→C1 与 W2→C2 各走 2 单位，W1→C2 走 1 单位，而 W2→C1 是一条灰色细线 —— 它的流量为零，但它仍然是一条真实的边（费用 3 摆在那里），只是当前方案没用到它。两条对角边的标注落在同一个中点上、在图中互相遮挡，图上显示的是 W2→C1 那一格（cost 3 / flow 0）。这张图由 `m2_figures.py` 的 `fig_transport_network()` 生成，最优流不是硬编码进去的，而是脚本对 $q\in[0,2]$ 做网格搜索复算出来的。

## 5. 四条守恒等式为什么不全独立

把四条等式分成两组相加：

```text
供给两式之和： (x11 + x12) + (x21 + x22) = 3 + 2 = 5
需求两式之和： (x11 + x21) + (x12 + x22) = 2 + 3 = 5
两个左边的展开都是 x11 + x12 + x21 + x22
```

所以「供给两式之和」与「需求两式之和」是同一个表达式。这意味着任意三条可以推出第四条：

```text
由供给行 1：x12 = 3 - x11
由供给行 2：x22 = 2 - x21
两式相加：  x12 + x22 = 5 - (x11 + x21)
由需求行 1：x11 + x21 = 2，代入得 x12 + x22 = 5 - 2 = 3
这正是需求行 2。
```

一般结论：$m$ 个源、$n$ 个汇的**平衡**运输模型有 $m+n$ 条等式，但秩只有 $m+n-1$，因此基本变量的个数是 $m+n-1$，非基变量（也就是自由度）有 $mn-(m+n-1)$ 个。

```text
本实例：m = n = 2   ->  秩 3、基本变量 3 个、非基变量 1 个（就是 q）
项目实例：m = 2, n = 3, 变量 6 个（S1/S2 到 D1/D2/D3）
         ->  秩 2+3-1 = 4、基本变量 4 个、非基变量 2 个
```

项目里的测试注释把这件事写得很直白：运输算例的最优基有 $m+n-1=2+3-1=4$ 个基本变量，而最优解里这 4 个全为正，所以那个基是**非退化**的。这个数字不是记出来的，是从「行数减去一个冗余」推出来的。

**建模时可以保留冗余。** 保留 `demand_D3` 这条等式不会让模型算错：求解器在预处理阶段通常会发现并处理这种线性相关的行。但你必须知道冗余存在，否则会犯两个错：一是以为方程组唯一确定了运输方案（实际还有一个自由度，本实例是 $q$）；二是看到某个客户的需求行在最优解里「自动成立」，就以为它在起作用 —— 它可能只是被别的行推出来的。

## 6. 指派：供给与需求都恰好为 1 的运输模型

指派问题问的是「每个人做哪个任务」。令 $x_{ij}$ 表示人员 $i$ 是否承担任务 $j$，每人恰好一个任务、每个任务恰好一个人：

$$\sum_{j}x_{ij}=1\quad(\forall i),\qquad \sum_{i}x_{ij}=1\quad(\forall j),\qquad x_{ij}\ge0.$$

把 $x_{ij}\ge0$ 换成 $x_{ij}\in\{0,1\}$，就是业务上真正想写的模型。但今天我们**先不写整数**，看会发生什么。

这组约束与运输模型长得完全一样，只是把 $a_i$ 与 $b_j$ 全换成了 1（人数等于任务数）。教材第 3 章 3.7 节的小例可以直接手算：两名工人甲、乙，两项任务的成本矩阵是

| | 任务 1 | 任务 2 |
|---|---:|---:|
| 甲 | 4 | 1 |
| 乙 | 2 | 3 |

令 $x_{11}=t$，四条等式给出 $x_{12}=1-t$、$x_{21}=1-t$、$x_{22}=t$，非负性要求 $0\le t\le1$。目标为

$$4t+(1-t)+2(1-t)+3t=4t+3 .$$

$t=0$ 得 3，$t=1$ 得 7，所以最优是「甲做任务 2、乙做任务 1」，成本 3。这里 $t$ 取值的两个端点 $0$ 与 $1$ **恰好**对应两个完整的指派，而 $t=1/2$ 这种中间点对应的是「甲做半个任务 1、乙做半个任务 1」—— 它不是任何真实的指派方案。

这不是巧合，而是一条可以陈述的结构事实：

> **平衡指派多面体 $\{x\ge0:\ \sum_j x_{ij}=1\ (\forall i),\ \sum_i x_{ij}=1\ (\forall j)\}$ 的极点，恰好是置换矩阵**，也就是每行每列恰好一个 1 的 0–1 矩阵，即一个完整的一对一指派。

这条事实有两个直接推论：

1. **线性成本总能在某个极点达到最优**（这是 LP 的基本性质，Day 1 已经用过：有界可行域上的线性目标至少有一个极点最优解）。既然每个极点都是一个整数指派，那就**存在**一个完整指派达到最优 —— 不必再额外声明整数。
2. 所以这个模型可以直接交给 LP 求解器，不需要 MILP。省下来的不只是写代码的力气：LP 的理论与实现都比 MILP 成熟得多，规模上来之后差距会非常大。

**今天必须把这个结论的措辞练准**（第 8 节还会回到它）：

| 不能说 | 应该说 |
|---|---|
| 指派的 LP 解一定是整数 | 指派多面体**存在**一个整数最优极点；LP 的最优解**集合**里可能还有非整数的非极点解 |
| 一次返回整数，说明一般 LP 都有整数性质 | 整数性来自这张系数矩阵的结构，与「是不是 LP」无关 |
| 既然结果整数，就不用再检查了 | 结果整数只是必要条件；约束残差、行和、列和仍要逐条核对 |

## 7. 整数性从哪里来：全幺模矩阵

### 7.1 准确定义

一个矩阵 $A$ 是**全幺模**的（totally unimodular），当且仅当它的**每一个方形子矩阵**的行列式都取自 $\{-1,0,1\}$。

「方形子矩阵」指从 $A$ 中任取若干行、若干列，且行数与列数相等的那些子矩阵 —— 包括 $1\times1$ 的子矩阵，也就是 $A$ 的每一个元素本身。所以系数里一旦出现 2，全幺模立刻不成立。

这条定义有一个很常见的错误讲述方式：**「全幺模就是每个基的行列式为 $\pm1$」**。这是把定义的一个后果当成了定义：

- 基矩阵只是全部方形子矩阵里很小的一部分，而且是**求解过程中才会出现**的那一部分。你在建模阶段既不知道求解器会选哪个基，也没法在大规模模型里逐个枚举子矩阵；「每个基行列式为 $\pm1$」只是「全幺模」的一个**推论**，用它去「证明」某个矩阵全幺模，等于用结论当理由。
- 反过来，判定一个矩阵是否全幺模，靠的是**结构性论证**，不是抽查。例如网络矩阵：运输模型里每一条列恰好有两个非零元，一个 $+1$ 在一个供给行、一个 $+1$ 在一个需求行（需求行方向取负号后就是典型的 $+1/-1$ 结构）。这类「每列恰好一个 $+1$、一个 $-1$」的矩阵（连通二部图的节点–边关联矩阵）是全幺模的经典充分条件。

### 7.2 为什么行列式只能是 $\pm1$ 才是关键

极点对应的基变量满足 $x_B=B^{-1}b$。若 $B$ 是整数矩阵且 $\det B=\pm1$，则 $B^{-1}=\operatorname{adj}(B)/\det(B)$ 也是整数矩阵（伴随矩阵的元素是整数子式），于是 $b$ 为整数时 $x_B$ 也是整数。

整条链条上只要有一个行列式是 $2$，$B^{-1}$ 就会出现分母 $2$，$x_B$ 就可能是 $1/2$。**「基行列式为 $\pm1$」这个结论之所以成立，正是因为全幺模保证了所有子矩阵（包括所有可能出现的基）的行列式都不超过 1。** 这也解释了为什么定义必须写成「所有方形子矩阵」，而不能写成「若干个基」。

### 7.3 适用条件一条也不能少

1. **右端项必须是整数。** 全幺模保证的是「行列式干净」，它不改变 $b$ 的小数位。需求写成 2.5，解出来的流量照样可以是 $1.5$。
2. **要取合适的标准形式。** 讨论极点整数性时，模型要写成 $Ax=b,\ x\ge0$ 这类形式；变量有上界、有自由变量、或者系数经过缩放时，要重新检查结论，不能直接搬。
3. **结论是「存在整数极点」，不是「整数解随手可得」。** 求解器实际返回哪个顶点、返回的是不是极点，取决于它的算法路径；整数性的正确用法是「知道最优值能被某个整数解达到」，而不是「相信打印出来的每个数都是整数」。这也是今天两条勘误里的第一条：**只检查几个基的行列式不等于证明**。

## 8. 边界：什么时候不能再依赖整数性

上一节讲的是「结构给了什么」。这一节讲「结构什么时候不在了」。三条边界都很容易在真实报告里说错。

### 8.1 额外约束可能直接破坏结构

「加一条预算约束」是建模里最常见的动作。它是真实的业务需求，但它会把原来干净的结构改掉。用第 6 节那个 $2\times2$ 指派实例演示一次，成本矩阵同上：

| | 任务 1 | 任务 2 |
|---|---:|---:|
| 甲 | 4 | 1 |
| 乙 | 2 | 3 |

加一条业务条款：「甲必须先投入任务 1 的一半工作量才能做别的事」，写成 $x_{11}\ge 1/2$。可行集还是那条线段（$x_{11}=t$，$x_{12}=1-t$，$x_{21}=1-t$，$x_{22}=t$），只是 $t$ 的范围从 $[0,1]$ 缩小成 $[1/2,1]$：

```text
LP：  min 4t + 3   s.t. 1/2 <= t <= 1
      t = 1/2 取最优，目标值 5
      对应解 (1/2, 1/2, 1/2, 1/2) —— 四个变量全是分数
整数可行解：只有 t = 1（「甲做任务 1、乙做任务 2」），成本 7
      t = 0 那个更便宜的整数方案被新约束砍掉了
```

于是出现了一个必须看懂的现象：**LP 给出 5，真实的整数最优是 7，中间差了 2**。这个 $5$ 不是任何可执行方案的成本，它只是「半个任务」这种不存在的安排算出来的数。如果谁拿 LP 的 5 去写报告，读者会读到一个永远实现不了的承诺。

这个例子是刻意构造的小例，不能反过来推广成「加任何约束都会产生分数解」；它要说明的只是一件事：**整数性是原结构的性质，加约束之后必须重新论证**，或者干脆把模型写对 —— 把 $x_{ij}$ 声明成 0–1 变量交给 MILP 解。

### 8.2 「所有最优解都整数」是错的

指派结构保证的是「**存在**整数最优极点」，不是「每个最优解都是整数」。看一个所有人成本都相同的例子：两人两任务、$c_{ij}\equiv1$。可行集还是那条线段，目标是常数：

```text
目标 = t + (1-t) + (1-t) + t = 2，与 t 无关
t = 0： (0,1,1,0) 是整数，目标 2
t = 1： (1,0,0,1) 是整数，目标 2
t = 1/2：(1/2,1/2,1/2,1/2) 全是分数，目标还是 2
```

$t=1/2$ 那个点确实是最优 LP 解，只是它不是极点，而是落在两个整数最优方案连线的**正中间**。所以「指派模型的 LP 结果会不会是分数」的正确答案是：**最优值为整数一定成立，返回的解是不是整数不保证**。看到分数不要立刻怀疑代码有 bug，先判断它是不是非极点的最优解，或者模型里是不是多了别的约束。

### 8.3 一次返回整数，说明不了「一般 LP」怎么样

这是第二条勘误。运输与指派能拿到整数解，靠的是**这两张特定矩阵的结构**加上**整数数据**，一般的 LP 没有这个性质。最容易被误判的是「改等号」这一类改写，所以要把分界看准 —— 分界不在等号与不等号，而在**矩阵**：

- **只把「每个任务恰好一个人」改成「每个任务至少一个人」，矩阵没变**：它仍然是二部图的节点–边关联矩阵，加上剩余变量之后依然全幺模，整数性照样成立。两人两任务时可以手验：两条需求不等式会被「总供给恰好是 2」逼成等式，可行集与原来完全一样。
- **换成不再来自二部图的矩阵，结构就消失了**：教材第 3 章 3.8 节的集合划分例子（三个需求点、三个候选站、每个站覆盖两个点）的系数矩阵是三角形结构，$3\times3$ 子矩阵的行列式等于 $2$，全幺模直接不成立。三条等式相加得 $2(x_A+x_B+x_C)=3$，左边是偶数、右边是奇数，**整数解根本不存在**；而 LP 允许 $x_A=x_B=x_C=1/2$，一切看起来都很正常。

所以「求解器这一次返回了整数」是一条**观察**，而「这个模型的 LP 松弛必有整数最优解」是一条**定理**，两者需要不同的证据。前者的证据是一次运行，后者的证据是结构（比如全幺模 + 整数右端项）。

### 8.4 顺带一条读数边界：对偶解不唯一

今天的脚本会把运输与指派的**对偶解**也打印出来，而且刻意不硬编码某一组具体数值 —— 因为这两个模型的最优对偶解都不唯一：

1. **运输**：产销平衡时，把所有源位势 $u_i$ 加上 $t$、所有汇位势 $v_j$ 减去 $t$，每一条对偶约束 $u_i+v_j\le c_{ij}$ 都不变，而对偶目标的变化量是 $t(\sum_i a_i-\sum_j b_j)=0$，所以目标值也不变。产销平衡给了对偶解**整体平移的自由度**。
2. **指派**：取等的对偶约束比未知数还少（脚本的 $3\times3$ 实例里，对偶变量只有 $6$ 个，而取等的对偶约束共 $5$ 条），最优对偶解同样不唯一。

因此读对偶结果时的正确姿势是**核验不变量**，而不是比对某个向量：位势可行（$u_i+v_j\le c_{ij}$ 全部成立）、流量为正的格子处取等、对偶目标等于最优目标。这三条在任何一组最优对偶解上都成立，换一组解也不会变。

## 9. 实验：`m2w1d3_transport_assignment.py`

脚本链接：[m2w1d3_transport_assignment.py](../../projects/02_optimization_models/examples/m2w1d3_transport_assignment.py)。

从仓库根目录运行：

```bash
python projects/02_optimization_models/examples/m2w1d3_transport_assignment.py
```

脚本分 10 段：运输数据 → 约束矩阵 → 运输解 → 运输手算核对 → 运输对偶 → 指派数据 → 指派全枚举 → 指派 LP 解 → 指派对偶 → 断言。**注意它与本页第 4 节的手算实例不是同一个实例**：脚本用的是 2 源 3 汇、总供给 45 的项目算例。教学小例负责把方法讲清楚，项目算例负责证明代码在另一个规模上也对得上。

```text
== 1. 运输算例：先集合、后参数 ==
源集合 S = ['S1', 'S2']，汇集合 D = ['D1', 'D2', 'D3']
供应 supply    = {'S1': 20.0, 'S2': 25.0}
需求 demand    = {'D1': 15.0, 'D2': 20.0, 'D3': 10.0}
产销平衡：45 = 45
单位运费            D1      D2      D3
S1               4       6       8
S2               6       4       3
```

第一段把「集合、参数、数据」分开打印。产销平衡是等式模型的前提，脚本把它显式打出来（45 = 45），而不是让人自己加一遍。

```text
== 2. 约束矩阵（运输：每行是一个节点的流量守恒）==
规模：6 个变量、5 条等式约束。
变量 = 源 x 汇 的组合，每条变量恰好出现在两条等式里（一源一汇）。
  supply_S1      x_S1_D1 + x_S1_D2 + x_S1_D3 = 20
  supply_S2      x_S2_D1 + x_S2_D2 + x_S2_D3 = 25
  demand_D1      x_S1_D1 + x_S2_D1 = 15
  demand_D2      x_S1_D2 + x_S2_D2 = 20
  demand_D3      x_S1_D3 + x_S2_D3 = 10
```

第二段是今天最该盯着看的一段：**6 个变量、5 条等式**，因为有 $m+n=5$ 个节点、而供需平衡让其中一条行冗余，秩是 $4=2+3-1$。任何一条变量都出现在且只出现在两条行里，这正是「一条变量就是一条边」的字面证据。

```text
== 3. 运输最优解 ==
状态 OPTIMAL，最小运费 180
             D1       D2       D3       行和      供应
S1      15.0000   5.0000   0.0000  20.0000      20
S2       0.0000  15.0000  10.0000  25.0000      25
列和      15.0000  20.0000  10.0000  45.0000
需求           15       20       10
```

读到解时要先看**行和与列和两栏**，它们分别复核对供给约束与需求约束。表格里出现的零（S1→D3、S2→D1）是「这条边当前不用」，不是「这条边不存在」。

```text
== 4. 手算核对：逐项成本相加 ==
Σ c_ij x_ij = 4*15 + 6*5 + 8*0 + 6*0 + 4*15 + 3*10 = 180
求解器报 180，手算 180，差值 0.000e+00

本算例的 LP 最优解是否全部取整：是
观察（不是定理）：运输约束矩阵是全幺模的，所以 LP 的极点天然整数；
本算例只是这条定理的一个样本，不是它的证明。
```

第四段是一次**独立重算**：把 6 项成本各自相乘再相加，走的是与求解器完全不同的路径。脚本自己的措辞也值得抄进笔记 —— 「本算例只是这条定理的一个样本，不是它的证明」，这正是第 7 节说的「一次返回整数 ≠ 结构定理」。

```text
== 5. 运输的对偶（位势）与 reduced cost ==
u（源的位势） = {S1: 0.0000, S2: -2.0000}
v（汇的位势） = {D1: 4.0000, D2: 6.0000, D3: 5.0000}
对偶目标 Σ a_i u_i + Σ b_j v_j = 180.000000
变量             c_ij   u_i+v_j       rc   位势是否可行
x_S1_D1           4    4.0000   0.0000   可行
x_S1_D2           6    6.0000   0.0000   可行
x_S1_D3           8    5.0000   3.0000   可行
x_S2_D1           6    2.0000   4.0000   可行
x_S2_D2           4    4.0000   0.0000   可行
x_S2_D3           3    3.0000   0.0000   可行
位势可行的最大违反量 = 0.000e+00（对偶可行的含义就是 u_i + v_j <= c_ij）
```

第五段这张表要横着读：**流量为正的格子 rc 全是 0**，**流量为零的格子 rc 全为正**。这正是 Day 2 学过的那条读数规则在网络问题上的样子 —— 让一个当前为零的格子开始运货，每单位要多付 rc 这么多（S1→D3 是 3，S2→D1 是 4）。对偶解的推导是教材第 2 章的内容，今天只需要会核验它的三条不变量。

```text
注意：产销平衡时给全部 u 加 t、全部 v 减 t，不改变任何一条对偶约束，
对偶目标的变化量是 t * (Σa - Σb) = 0，所以运输问题的对偶解天然不唯一。
  平移 t =    0：对偶目标 = 180.000000
  平移 t =    1：对偶目标 = 180.000000
  平移 t = -2.5：对偶目标 = 180.000000
```

这三行就是第 8.4 节讲的那条自由度的实验证据：三组不同的位势、同一个对偶目标。若把对偶解的数值写进结论里当「唯一答案」，这个实验会立刻指出它站不住。

```text
== 7. 手算核对：把 3! = 6 种指派全部枚举 ==
  J1->W2、J2->W1、J3->W3         总成本 9
  J1->W2、J2->W3、J3->W1         总成本 10
  J1->W1、J2->W2、J3->W3         总成本 14
  J1->W3、J2->W2、J3->W1         总成本 16
  J1->W1、J2->W3、J3->W2         总成本 20
  J1->W3、J2->W1、J3->W2         总成本 21
最小总成本 = 9（J1->W2、J2->W1、J3->W3）
```

指派算例是 $3$ 人 $3$ 任务（成本矩阵 J1 行 9/2/7、J2 行 6/4/3、J3 行 5/8/1）。$3!=6$ 种排法全部列出，最小是 9，第二名是 10 —— 两者只差 1，所以「最优」不是随手挑一个就行的。

```text
== 8. 指派 LP 的解 ==
状态 OPTIMAL，最小总成本 9
            W1      W2      W3      行和
J1      0.0000  1.0000  0.0000  1.0000
J2      1.0000  0.0000  0.0000  1.0000
J3      0.0000  0.0000  1.0000  1.0000
任务 W1 的列和 = 1.0000
任务 W2 的列和 = 1.0000
任务 W3 的列和 = 1.0000
```

第八段里，模型**没有**写任何整数变量或 0–1 声明，求解器返回的却正好是 0/1，而且行和、列和全是 1。它落在那 6 个枚举值中的最小值 9 上 —— 两套完全独立的计算给出同一个答案，这才叫可信。

```text
== 9. 指派的对偶：不唯一，所以只核验不变量 ==
u = {J1: 1.0000, J2: 3.0000, J3: 1.0000}
v = {W1: 3.0000, W2: 1.0000, W3: 0.0000}
Σu + Σv = 9.000000（应当等于最优成本 9）
  J1->W2：u + v = 2.0000，c = 2，取等（互补松弛）
  J2->W1：u + v = 6.0000，c = 6，取等（互补松弛）
  J3->W3：u + v = 1.0000，c = 1，取等（互补松弛）
全部 9 个格子的 u_i + v_j - c_ij 最大值 = 0.000e+00（要求 <= 0）
取等的对偶约束共有 5 条：其中 3 条来自正分量，2 条来自退化的零分量。
```

最后一段的一次运行里，9 个格子的对偶约束全部可行，其中 5 条取等 —— 3 条来自被选中的指派（正分量），2 条来自没被选中但恰好取等的格子。**取等的条数多于正分量个数，说明基是退化的**，这也是对偶解不唯一的直接来源。脚本因此只核验三个数：最大违反量、正分量处的取等、$\sum u+\sum v$ 是否等于最优成本。最后的三条断言（运输 180、指派 9、指派等于枚举最小值）在容差 $10^{-9}$ 内全部通过。

- Q7：全幺模加上什么条件才能推出极点整数性？只加全幺模够不够？
- Q8：指派模型返回了分数解，是程序错误吗？给出两种可能的原因。
- Q9：把指派的「恰好一次」改成「至少一次」，整数性还能保证吗？换成「三个候选站覆盖三个需求点」那样的结构呢？
- Q10：运输与指派的最优对偶解都不唯一，那么读对偶结果时应该核验哪些量？

### 参考答案

- A1：每一条变量（一列）恰好出现在两行里 —— 一条是它所属仓库的供给行，一条是它所属客户的需求行；系数都是 1。这正是二部图节点–边关联矩阵的形状。
- A2：四条守恒等式不全独立（总供给等于总需求）。$m+n=4$ 条行的秩只有 $4-1=3$，变量有 4 个，所以非基变量正好 1 个，取它为 $q$，其余三个被等式唯一确定。
- A3：基本变量 $m+n-1$ 个，秩也是 $m+n-1$。产销平衡时 $m+n$ 条行线性相关，去掉任意一条不改变可行集。
- A4：都是「多一个节点、多一条（或一组）边」，但虚拟边的费用必须表达真实后果：缺货要写缺货惩罚，库存要写仓储成本。设零等于宣称这些都不要钱，模型会把缺口全塞给它，最优值会系统性地偏低。
- A5：因为平衡指派多面体的极点恰好是置换矩阵（每行每列恰好一个 1 的 0–1 矩阵），而线性目标至少有一个极点最优解，所以**存在**一个整数指派达到最优。这是结构定理，不是求解器的善意。
- A6：全幺模指矩阵的**每一个**方形子矩阵行列式都取自 $\{-1,0,1\}$。「每个基的行列式为 $\pm1$」只是它在一个特定标准形式下的推论：基只是全部方形子矩阵里极小的一部分，而且要看求解过程才会出现；用它当判据等于用结论当理由，也无法解释系数里出现 2 时会发生什么。
- A7：还需要整数右端项与合适的标准形式（如 $Ax=b,\ x\ge0$）。只加全幺模不够：若 $b$ 含小数，极点照样可以是小数；变量有上界或自由变量时也要重新检查。
- A8：不一定。两种常见原因：模型存在非极点的最优解（例如所有费用相同时，$1/2$ 的解也在最优面上），或者模型里被加了额外约束、结构已经改变（此时 LP 的最优值甚至可能对应不了任何真实指派）。
- A9：前者仍然保证 —— 约束方向变了，矩阵没变，仍是二部图的节点–边关联矩阵，加上剩余变量后依旧全幺模（两人两任务时两条需求不等式被总供给 2 逼成等式，可行集与原来一样）。后者不保证 —— 教材第 3 章 3.8 节的矩阵是三角形结构，$3\times3$ 子矩阵行列式为 $2$，全幺模不成立；集合划分甚至没有整数解，而 LP 有 $x_A=x_B=x_C=1/2$ 的解。
- A10：三样：位势可行性（$u_i+v_j\le c_{ij}$ 全部成立）、正分量处取等、对偶目标等于最优成本。具体数值不能比对，因为它们不唯一（运输有平移自由度，指派有退化带来的多解）。

---

## 13. 今日一句话总结

> **运输把变量画成边、指派把「恰好一次」交给极点结构；整数性是结构给的红利，不是 LP 的普适性质 —— 加一条额外约束，红利就可能当场消失。**
