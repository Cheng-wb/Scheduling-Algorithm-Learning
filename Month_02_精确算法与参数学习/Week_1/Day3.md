## 2. 为什么 Day 3 要专门看这两类 LP

Day 1–2 的生产计划 LP 是「一般形态」：约束系数是想写几就写几的 `usage[r][p]`。今天换两个模型，它们的约束系数**只有 0 和 1**，而且每列只出现在两个约束里：

```text
生产计划：   2 x_P1 + x_P2 + x_P3 <= 100      系数任意，行是「资源」
运输：       x_S1_D1 + x_S1_D2 + x_S1_D3 = 20  系数全 1，行是「节点」
             x_S1_D1 + x_S2_D1         = 15
```

这个差别不是写法上的小区别，它决定了一件大事：

```text
Day 1-2：一般 LP          -> 连续解，可能出现分数
Day 3：  网络结构的 LP     -> 全幺模 -> 极点自动整数
```

所以今天要建立的认知是：**「这个问题的 LP 解是整数」不是运气，而是结构给的**。识别结构，就能省掉整整一层整数规划——这正是 Month 2 后面（Week 2 的 MILP）要反过来讲的：结构一旦被破坏，整数性就没了。

知识链的位置：

```text
Day 1  写模型、看极点的几何
Day 2  交给求解器、读四个读数量
Day 3  换两个模型，观察「矩阵结构 → 解的性质」      ← 今天
Day 4  对偶：两个模型的对偶都有「位势」这个名字
```

## 3. 概念：两个模型的定义

### 3.1 运输模型

**定义（运输模型）**：给定源集合 `S`、汇集合 `D`，供应量 `a_i`、需求量 `b_j`、单位运费 `c_ij`，决策变量 `x_ij` 表示从源 `i` 运到汇 `j` 的数量：

```text
min  Σ_i Σ_j c_ij x_ij
s.t. Σ_j x_ij = a_i        对每个源 i（出清）
     Σ_i x_ij = b_j        对每个汇 j（满足）
     x_ij >= 0
```

两点必须说清楚：

- **所有约束都是等式**。这不是「不能有多余」的假设，而是「运出去的要正好等于供应的」这条账的写法。多运一点没有意义（运费非负时不会更优），少运一点就是没出清。
- **平衡条件**：`Σ_i a_i = Σ_j b_j` 是问题可行的必要条件。不满足时可加虚拟源 / 虚拟汇（单位运费 0）补齐，但那是**建模决策**，必须由使用者显式做出。本仓库的 builder 直接抛错：

```python
if abs(total_supply - total_demand) > DEFAULT_TOLERANCE:
    raise ValueError(f"transportation model must be balanced: supply=..., demand=...")
```

**为什么不让 builder 自动加虚拟节点**：自动补一个源会悄悄改变模型规模与约束名，而「虚拟节点的运费取多少」是一个业务判断（取 0 表示「运不出去也不亏」，取罚值表示「缺货有代价」）。**默认替使用者做业务决策，是建模库最危险的一种"方便"。**

### 3.2 指派模型

**定义（指派模型）**：给定 `n` 个人、`n` 个任务、成本 `c_ij`：

```text
min  Σ_i Σ_j c_ij x_ij
s.t. Σ_j x_ij = 1          每个人恰好一个任务
     Σ_i x_ij = 1          每个任务恰好一个人
     x_ij >= 0
```

**为什么这里不加 `x_ij <= 1`**：它是一条**冗余约束**——由 `Σ_j x_ij = 1` 与 `x_ij >= 0`，任何一列的和不超过 1，所以每个分量必然 `<= 1`。数学上冗余，代码里却有害：有限上界会在对偶里多出一组项，把「对偶目标 = `b'y`」这个干净结论弄脏（Day 4 会看到）。本仓库的 builder 因此在文档里写死了这条理由，`build_dual` 也在遇到有限上界时直接抛 `ValueError`。

**方阵要求**：`len(agents) != len(tasks)` 时 builder 抛错。非方阵的指派问题同样可以处理（加虚拟人 / 虚拟任务），但那还是那句：**建模决策要让使用者显式做出**。

### 3.3 两个模型的矩阵形状

```text
运输 2x3：   6 个变量，5 条等式，系数全为 1
             每列恰好两个 1（一个在源行、一个在汇行）
指派 3x3：   9 个变量，6 条等式，系数全为 1
             每列恰好两个 1（一个在人行、一个在任务行）
```

这类矩阵叫**节点—弧关联矩阵**（node-arc incidence matrix）。它的每条列只有两个非零元，这两个性质合起来，就是下一节那条定理的全部来源。

## 4. 手算：两份小例子

### 4.1 运输算例：贪心构造 + 位势法检验

数据（`TRANSPORT_BASE`）：

```text
         D1   D2   D3      供应
S1        4    6    8        20
S2        6    4    3        25
需求     15   20   10        45 = 45（平衡）
```

第一步：**按运费从低到高贪心**填出一个基本可行解。

```text
运费 3：S2 -> D3   填 min(25, 10) = 10      S2 剩 15，D3 满
运费 4：S1 -> D1   填 min(20, 15) = 15      S1 剩  5，D1 满
运费 4：S2 -> D2   填 min(15, 20) = 15      S2 剩  0，D2 剩 5
运费 6：S1 -> D2   填 min( 5,  5) =  5      全部出清
```

得到一个可行解：`x_S1_D1 = 15`、`x_S1_D2 = 5`、`x_S2_D2 = 15`、`x_S2_D3 = 10`，其余为 0，共 4 个正分量。运费：

```text
4*15 + 6*5 + 4*15 + 3*10 = 60 + 30 + 60 + 30 = 180
```

第二步：**位势法检验最优性**。给每个源、每个汇设一个位势 `u_i`、`v_j`，要求「正分量处取等」（`u_i + v_j = c_ij`）：

```text
令 u_S1 = 0（位势可以整体平移，先固定一个）
x_S1_D1 > 0： 0 + v_D1 = 4   ->  v_D1 = 4
x_S1_D2 > 0： 0 + v_D2 = 6   ->  v_D2 = 6
x_S2_D2 > 0： u_S2 + 6 = 4   ->  u_S2 = -2
x_S2_D3 > 0： -2 + v_D3 = 3  ->  v_D3 = 5
```

再用「零分量处必须 `u_i + v_j <= c_ij`」检验：

```text
x_S1_D3 = 0： u_S1 + v_D3 = 5 <= 8  ✓   rc = 8 - 5 = 3
x_S2_D1 = 0： u_S2 + v_D1 = 2 <= 6  ✓   rc = 6 - 2 = 4
```

全部通过，所以这个解是**最优**的，最小运费 180。对偶目标：

```text
Σ a_i u_i + Σ b_j v_j = 20*0 + 25*(-2) + 15*4 + 20*6 + 10*5
                      = 0 - 50 + 60 + 120 + 50 = 180  ✓（与原始目标相等）
```

**位势就是运输问题的影子价格**：`u_S2 = -2` 表示「S2 的供应增加 1 单位，总运费减少 2」——因为多出来的货运到 `D2`/`D3` 都在谷底价附近，而下游需求是固定的，多供应反而顶掉了别的流向。负号在这里是正常的：这是 `min` 问题，约束是等式，位势**自由**（可正可负）。

### 4.2 指派算例：把 `3! = 6` 种指派全部枚举

```text
         W1   W2   W3
J1        9    2    7
J2        6    4    3
J3        5    8    1
```

三种人的三种派法一共 `3! = 6` 种，全部算一遍：

```text
J1->W2、J2->W1、J3->W3     2 + 6 + 1 =  9    ← 最优
J1->W2、J2->W3、J3->W1     2 + 3 + 5 = 10
J1->W1、J2->W2、J3->W3     9 + 4 + 1 = 14
J1->W3、J2->W2、J3->W1     7 + 4 + 5 = 16
J1->W1、J2->W3、J3->W2     9 + 3 + 8 = 20
J1->W3、J2->W1、J3->W2     7 + 6 + 8 = 21
```

最优是 `J1 -> W2`、`J2 -> W1`、`J3 -> W3`，总成本 9。

**为什么必须全枚举**：`n!` 增长极快（`n = 10` 就是 3628800 种），到了 Week 2 会看到它的整数规划写法。今天的小算例只是「判据」——用来核对求解器，不是方法。

对偶一侧的手算规律：给每个人一个 `u_i`、每个任务一个 `v_j`，要求「配上的格子取等」`u_i + v_j = c_ij`；本算例的解是 `u = (1, 3, 1)`、`v = (3, 1, 0)`，三个配上的格子：

```text
J1 -> W2：u_J1 + v_W2 = 1 + 1 = 2 = c_12      ✓
J2 -> W1：u_J2 + v_W1 = 3 + 3 = 6 = c_21      ✓
J3 -> W3：u_J3 + v_W3 = 1 + 0 = 1 = c_33      ✓
Σu + Σv = (1 + 3 + 1) + (3 + 1 + 0) = 9 = 最优成本   ✓（强对偶）
```

## 5. 结构给了什么：四条要分清的结论

### 5.1 定理（不是观察）

1. **全幺模性**：运输 / 指派的约束矩阵是节点—弧关联矩阵，它是**全幺模**的（每个子方阵的行列式取值为 `-1 / 0 / +1`）。当右端项 `b` 是整数时，LP 的**每个基本可行解都是整数**。
2. **指派的多面体**：`2n` 条等式加非负约束定义的可行域（双随机矩阵的推广），其顶点恰好是**排列矩阵**（Birkhoff–von Neumann 定理）。所以指派 LP 的最优解一定可以取成 0/1 指派。
3. **秩缺一**：`Σ_i (源行) = Σ_j (汇行) = 总流量`，所以这两类模型都有一条**冗余行**，约束矩阵的秩是「行数 − 1」。运输 2 × 3 的秩是 `2 + 3 − 1 = 4`；指派 3 × 3 的秩是 `3 + 3 − 1 = 5`。
4. **对偶不唯一是必然的**：秩缺一意味着对偶变量里存在整体的平移自由度（下一节有数值验证）；加上退化，对偶解可能是一整个多面体。

### 5.2 观察（不是定理）

第 7 节的实测里，运输解是 `(15, 5, 0, 0, 15, 10)`、指派解是 0/1 矩阵——都取到了整数。**这只是在两个样本上成立的观察**。把「我这次跑出来是整数」当成「这类问题一定是整数」是实验报告里最常见的越界结论；上面第 1、2 条才是能支撑这个结论的依据。

### 5.3 一个必须记住的边界

全幺模性是**这两张特定矩阵**的性质，不是「所有带网络味道的 LP」的性质。一旦加上与网络结构无关的额外约束（例如「S1 到 D2 与 S2 到 D3 不能同时开通」这种成对约束），矩阵就不再是节点—弧关联矩阵，整数性**失去保证**——那时 LP relaxation 可能给出分数解，就需要整数规划。这正是 Week 2 的入口。

### 5.4 冗余行与对偶平移的数值验证

运输的第 7 节输出里有一组「平移 `t`」的打印：

```text
给全部 u 加 t、全部 v 减 t：
  对偶约束 u_i + v_j 不变（一加一减抵消），所以可行性不变；
  对偶目标的变化 = t * (Σ a_i - Σ b_j) = t * 0 = 0（产销平衡！）。
```

所以运输问题的对偶最优解**天然是一族**，而不是一个点。这解释了为什么 `u_S1 = 0` 是「人为固定」的，也解释了一个实践问题：**不要拿位势的绝对值做业务解释**，只有差值（`u_i + v_j` 与 `c_ij` 的比较、或两个位势之差）才有意义。

## 6. 实现：三个 builder 的差别

对应文件 [lp_models.py](../../projects/02_optimization_models/opt_models/lp_models.py)。

| 维度 | `build_production_lp` | `build_transportation_lp` | `build_assignment_lp` |
|---|---|---|---|
| 目标 | `max` 利润 | `min` 运费 | `min` 成本 |
| 行方向 | 全 `<=`（加 `>=` 交付行） | 全 `=` | 全 `=` |
| 行数 | 资源数 + 产品数 | 源数 + 汇数 | 人数 + 任务数 |
| 变量数 | 产品数 | 源数 × 汇数 | 人数 × 任务数 |
| 前置校验 | 无 | 产销平衡 | 方阵 |
| 变量上界 | 无（上界写成行） | 无 | 无（由行隐含） |

三处实现细节：

1. **约束名沿用同一套命名约定**：`supply_<源>`、`demand_<汇>`、`agent_<人>`、`task_<任务>`。对偶变量名由它派生（`y_supply_S1` …），Day 4 的对照表因此对三个模型通用。
2. **平衡 / 方阵的校验放在 builder 里**，用的是 `DEFAULT_TOLERANCE = 1e-9`；浮点数据（例如 `0.1 + 0.2`）不会被误判为不平衡，而真正的不平衡会被挡住。
3. **`meta` 字段记录 `kind`**：`"production" / "transportation" / "assignment" / "dual"`。Day 7 的复盘表就是按这个字段分组的，它也是「这个模型该用什么读法」的索引。

```text
u_i + v_j <= c_ij 全部成立、正分量处取等、Σu + Σv = 最优成本。

== 10. 断言 ==
运输手算 180、指派枚举最小 9，两者与求解器结果一致（容差 1e-9）。
```

五处值得停留的细节：

1. **运输的对偶解与第 4.1 节手算完全一致**：`u = (0, -2)`、`v = (4, 6, 5)`。手算里「令 `u_S1 = 0`」这个人为选择，求解器也做了同样的选择——这是平移自由度的一个具体表现，**不代表 `u_S1 = 0` 有什么特殊含义**。
2. **平移 `t` 的三个数值都是 `180.000000`**：这不是近似，而是精确的代数恒等式（`t * (45 - 45) = 0`）。
3. **`x_S2_D1` 的 `rc = 4`**：这一格现在没运，是因为它比 `S1 -> D1`（运费 6 对 4 的位势差）贵 4。这句读法和 Day 2 的「`P2` 亏 5 元」是同一个读法。
4. **指派的 5 条取等对偶约束**：其中 2 条来自 `x = 0` 的退化格子（`J2 -> W2` 与 `J2 -> W3` 的 `u + v` 恰好等于成本）。这 2 条「白送」的等式正是对偶解不唯一的原因——6 个对偶变量只剩 1 个自由度。
5. **指派的解是 0/1**：与第 5.1 节的 Birkhoff 定理一致；输出里的 6 条列和 / 行和都是 `1.0000`，说明「每个人恰好一个任务、每个任务恰好一个人」被严格满足。

## 10. 自测题

不看上文回答：

- Q1：运输模型的三部分分别是什么？为什么三条都是等式约束？
- Q2：产销不平衡时本仓库的 builder 会怎么做？为什么不做「自动补虚拟节点」？
- Q3：指派模型里 `x_ij <= 1` 为什么是冗余的？
- Q4：全幺模性说的是什么？它在运输问题里换来了什么结论？
- Q5：Birkhoff–von Neumann 定理与指派问题的关系是什么？
- Q6：为什么运输 / 指派的约束矩阵「秩缺一」？秩是多少？
- Q7：运输的对偶为什么天然不唯一？不变量是什么？
- Q8：`u_S1 = 0` 说明 `S1` 有什么特殊性吗？
- Q9：把 `x_S2_D1` 的 `reduced cost = 4` 翻译成业务语言。
- Q10：给运输模型加一条与网络结构无关的成对约束，会发生什么？

### 参考答案

- A1：`min Σ c_ij x_ij`（目标）、`Σ_j x_ij = a_i`（源行，出清）、`Σ_i x_ij = b_j`（汇行，满足）。用等式是因为「运出的量必须正好等于供应的量、到达的量必须正好等于需求的量」。
- A2：直接抛 `ValueError`。虚拟节点的运费取多少是业务判断（取 0 还是取罚值含义完全不同），库不能替使用者做这个决定。
- A3：由 `Σ_j x_ij = 1` 与 `x_ij >= 0`，任一行的分量之和为 1，所以每个分量必然 `<= 1`；写上去没有数学效果，只会在对偶里多出一组上界项。
- A4：约束矩阵的每个子方阵行列式为 `-1 / 0 / +1`；右端项为整数时，LP 的每个基本可行解都是整数，所以不需要整数规划。
- A5：它说 `2n` 条等式定义的可行域（安排矩阵的凸包）的顶点恰好是排列矩阵，因此指派 LP 的最优值可以由一个 0/1 指派取到。
- A6：因为 `Σ_i (源行) = Σ_j (汇行)`，有一行是其余行的线性组合，所以秩 = 行数 − 1；运输 2 × 3 的秩是 4，指派 3 × 3 的秩是 5。
- A7：产销平衡使「全部 `u` 加 `t`、全部 `v` 减 `t`」不改变任何对偶约束，也不改变对偶目标。不变量是差值（`u_i + v_j` 与 `c_ij` 的关系）以及 `Σ a_i u_i + Σ b_j v_j` 的值。
- A8：没有。位势可以整体平移，`u_S1 = 0` 只是「任选一个基准」的结果，是求解器与手算都采用的一个便利约定。
- A9：`S2 -> D1` 这条线路现在空着。它的实际运费是 6，而按当前位势算出的「合理运费」是 `u_S2 + v_D1 = -2 + 4 = 2`，两者差 4；要让这条线值得开通，它的运费得降到 2 以下。
- A10：矩阵不再是节点—弧关联矩阵，全幺模性失去保证；LP relaxation 可能出现分数解，需要整数规划方法来解。

## 11. 今日一句话总结

> **运输与指派是两张「系数只有 0 和 1、每列只出现在两条约束里」的 LP：全幺模性与 Birkhoff 定理让它们的 LP 解自动是整数，位势法（对偶）给出最优性证书，而「秩缺一」与退化让对偶解天然不唯一——能核验的只有不变量。**
