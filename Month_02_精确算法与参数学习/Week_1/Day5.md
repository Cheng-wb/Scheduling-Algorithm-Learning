## 2. 为什么 Day 5 要专门做一次敏感性实验

Day 2 读到了影子价格 `y_M = 15`、`y_L = 10`，Day 4 验证了它与对偶最优解是同一个东西。但那两天都留了一个没回答的问题：

```text
「M 的产能每多一单位，目标多 15」——这句话在产能翻倍时还对吗？
```

答案是：**不对**。影子价格是**局部**信息，它是目标值函数在某一点处的斜率，而目标值函数是一个分段线性的**凹**函数（`max` 问题、右端项扰动方向）：

```text
目标值
  ^                                ___________  <- 斜率 0：产能多到用不完
  |                              /
  |                            /   <- 斜率变小：换了另一个顶点
  |                          /
  |                        /     <- 基准点斜率 15
  |                      /
  |____________________/__________> 右端项（产能）
                    折点      折点
```

今天要做的就是**把这个图形量出来**：在每一根轴上扫网格，看线性预测从哪里开始不成立。这是把「解释」变成「可验证的解释」的那一步——M1 里 `bound` 必须诚实的纪律，在 LP 世界里的对应物就是**引用影子价格时必须带上它的区间**。

知识链的位置：

```text
Day 2  读影子价格             「y_M = 15」
Day 3  两个网络模型的对偶      「位势 = 影子价格」
Day 4  对偶的推导与条件        「它是对偶最优解的一阶信息」
Day 5  量出它的有效范围         ← 今天
Day 6  把这个范围写进对拍容差
```

## 3. 概念：局部导数与折点

### 3.1 定义

**定义（右端项敏感性的成立区间）**：设基准模型的最优基为 `B`，第 `i` 条约束的影子价格为 `y_i`。使最优基仍然为 `B` 的右端项取值范围称为该基的**有效区间**；在这个区间内 `b_i` 增加 `Δ` 时最优值增加 `y_i · Δ`（一阶线性）。

三点必须一起说：

```text
1. 「成立区间」是对**某一条**约束的右端项而言的，其他右端项保持不动；
2. 区间由「基不变」定义，不是由「误差小」定义；
3. 到了区间端点，基可能要换，斜率随之改变。
```

### 3.2 折点上的对偶解

**理论结论**：目标值函数 `V(b)` 是分段线性凸（`min` 问题）/ 凹（`max` 问题）函数；在可微点处 `∂V/∂b_i = y_i`，在折点处 `V` 不可微，此时**对偶最优解不唯一**，它们的集合正是 `V` 在折点处的**次梯度**集合。

于是折点上的读数必须带一句限定：

```text
求解器报的 y_i 是众多次梯度之一：
  - 它等于左侧斜率（左导数），或右侧斜率（右导数），或两者之间的某个值；
  - 用它做预测前先问：往哪个方向扰动？
```

**这不是数值噪声，而是对偶解的非唯一性**——和 Day 3 里运输对偶的整体平移自由度是同一类现象。（一个是「对偶可行面里有一条直线」，一个是「折点处有多个斜率」，表现形式不同，本质都是「对偶最优解不是唯一的一点」。）

### 3.3 实验观察与理论结论的分界

今天的所有数字都是**实验观察**，必须加限定语：

```text
观察：在 cap_M ∈ [80, 120] 这张网格上，线性预测成立。
不能说：cap_M 永远可以用 15 来预测。（那需要先证明「最优基在这个区间不变」）
```

网格本身也有粒度限制：**在网格点之间，我们只做了线性插值，没有检查**。说「区间是 [80, 120]」时，准确的意思是「在这 9 个网格点上预测都成立，最近的两个失效点在 70 和 130」。

## 4. 手算：预测值与折点的推算

### 4.1 基准解回顾

`PRODUCTION_BASE` 的基准最优解（Day 2 手算过的）：

```text
x = (x_P1, x_P2, x_P3) = (20, 0, 60)，目标值 2300
cap_M 的 slack = 0，影子价格 y_M = 15
cap_L 的 slack = 0，影子价格 y_L = 10
三条需求行的 slack 都大于 0，影子价格都是 0
```

### 4.2 用影子价格做预测

预测规则只有一句：**右端项变化 `Δ` 时，目标值变化 `y_i · Δ`**。于是：

```text
cap_M: 100 -> 90   Δ = -10   预测 2300 + 15*(-10) = 2150
cap_M: 100 -> 110  Δ = +10   预测 2300 + 15*(+10) = 2450
cap_L:  80 -> 70   Δ = -10   预测 2300 + 10*(-10) = 2200
cap_L:  80 -> 90   Δ = +10   预测 2300 + 10*(+10) = 2400
```

这四个预测都在第 7 节的实测表里得到了验证。要特别注意一点：**`y_L = 10` 与 `y_M = 15` 的比值 2:3，不是「L 不如 M 重要」，而是这两个影子价格量纲相同但作用在不同的顶点族上**——比较影子价格只在这个比值本身有意义时才有意义（例如「同样的钱该投哪条产线」）。

### 4.3 折点在哪里

在顶点族 `x_P1 = cap_M - cap_L`、`x_P3 = 2·cap_L - cap_M` 上（此时两条产能都顶死、三条需求都不顶死），目标值可以写成产能的线性函数：

```text
V = 40·x_P1 + 25·x_P3
  = 40·(cap_M - cap_L) + 25·(2·cap_L - cap_M)
  = 15·cap_M + 10·cap_L
```

所以在这条「顶点族」上，`y_M = 15`、`y_L = 10` 是**恒等式**。剩下的问题是这个顶点族本身在什么范围内是最优的：

```text
需求侧的可行条件：x_P1 = cap_M - cap_L  <= 40   （demand_P1）
                  x_P3 = 2 cap_L - cap_M <= 80   （demand_P3）
非负条件：        x_P1 >= 0  ->  cap_M >= cap_L
                  x_P3 >= 0  ->  cap_M <= 2 cap_L
```

代入基准值 `cap_M = 100, cap_L = 80`，第二条需求条件是 `160 - 100 = 60 <= 80`，还留了 20 的余量：

```text
cap_M 增大到 120 时：x_P3 = 160 - 120 = 40，仍 <= 80  ✓
cap_M 增大到 130 时：x_P3 = 160 - 130 = 30，仍 <= 80，但 x_P1 = 130 - 80 = 50 > 40  ✗
                     -> demand_P1 顶死，换顶点，斜率改变
cap_M 减小到 70 时： x_P1 = 70 - 80 = -10 < 0  ✗（该顶点族不可行）
cap_M 减小到 80 时： x_P1 = 0，恰在边界上  ✓
```

于是 `cap_M` 的区间是 `[80, 120]`，两个端点分别由「`x_P1 >= 0` 的边界」和「`demand_P1` 顶死」决定。同理对 `cap_L`：由 `x_P3 >= 0`（`cap_M <= 2 cap_L`，即 `cap_L >= 50`）与 `demand_P3` 顶死（`2 cap_L - cap_M <= 80`，即 `cap_L <= 90`）给出区间 `[60, 90]`——`cap_L = 60` 比纯几何下界 50 更紧，因为 `demand_P1` 在 `cap_L = 60` 处先顶死了。

**这就是「手算解释实测」的意义**：网格告诉我区间在哪，手算告诉我区间的端点各自由哪条约束决定。

### 4.4 四个区间端点的手算复核

把第 4.3 节的不等式在基准点上逐条代入，四个端点都能单独算出来：

```text
cap_M 的左端点（cap_L 固定在 80）：
  x_P1 = cap_M - 80 >= 0        ->  cap_M >= 80
  （这条与「cap_M >= cap_L」是同一件事，代入 80 即得）

cap_M 的右端点（cap_L 固定在 80）：
  x_P1 = cap_M - 80 <= 40       ->  cap_M <= 120   （demand_P1 先顶死）

cap_L 的左端点（cap_M 固定在 100）：
  x_P1 = 100 - cap_L <= 40      ->  cap_L >= 60    （demand_P1 先顶死，比几何下界 50 更紧）

cap_L 的右端点（cap_M 固定在 100）：
  x_P3 = 2*cap_L - 100 <= 80    ->  cap_L <= 90    （demand_P3 顶死）
```

四个端点全部由手算的不等式给出，与网格实测的 `[80, 120]` / `[60, 90]` 逐一吻合。这个分工要写清楚：

```text
网格的作用：发现「预测在哪个取值上不成立」，给出现象与量级（cap_M = 130 差 150）；
手算的作用：说明「端点由哪条约束决定」，给出解释与可推广的形式。
两者不能互相代替 —— 网格会漏掉「这条约束其实不活跃」，手算会漏掉「写错一条不等式」。
```

## 5. 建模与实现：扫描函数的三件套

对应文件 [lp_experiments.py](../../projects/02_optimization_models/opt_experiments/lp_experiments.py) 与示例脚本 [m2w1d5_sensitivity.py](../../projects/02_optimization_models/examples/m2w1d5_sensitivity.py)。

### 5.1 扫描函数要输出什么

一条轴的扫描表至少要有五列，缺一列都会让结论含糊：

```text
取值 | 状态 | 实测目标 | 预测目标 | 误差 | 该行影子价格 | 预测是否成立
```

- **状态列**：扫描时必须检查每个点的求解状态。某一点变成 INFEASIBLE（Day 6 会讲：也包括 UNBOUNDED），那一行就没有目标值，不能拿它算误差。
- **误差列**：允许把浮点尘埃（`-4.55e-13`）与真正的失效（`-150`）区分开。只看「成不成立」会丢掉量级信息。
- **影子价格列**：这是本实验的核心证据——它显示**同一行**的影子价格在区间外换了值（`cap_M = 70` 时是 20、`= 130` 时是 0），这就解释了预测为什么失效。

### 5.2 区间检测的写法

区间的检测是纯后处理，不依赖任何求解器内部信息：

```python
ok_values = [value for value, _, _, ok in rows if ok]
if ok_values:
    print(f"在这张网格上，线性预测成立的区间是 {lo} ∈ [{min(ok_values):g}, {max(ok_values):g}]。")
```

**为什么要加「在这张网格上」**：`min`/`max` 取的是网格点，不是解析出的端点。诚实的说法是「这 9 个点上成立」，而不是「区间是 [80, 120]」。这两句话在数学上不等价，教材里常常混着写。

### 5.3 端点上的单侧斜率

区间的两个端点是最有信息量的位置。脚本对每个端点额外打印一行：

```text
左侧网格斜率、右侧网格斜率、求解器报的影子价格
```

这样「求解器报的数落在两侧斜率之间」这件事是**看得见**的，而不是靠读者相信。

## 6. 三个成本 / 需求侧的读法

### 6.1 `reduced cost` 是盈亏平衡价，不是斜率

`rc(P2) = -5` 的正确读法：

```text
要让 x_P2 进基，它的单位利润至少要提高 5（从 30 提到 35）。
```

错误读法：「`rc = -5`，所以单位利润每提高 1，目标提高 5」——这句话把 `rc` 当成了「利润对目标的影响系数」，方向正好相反。实测表里的证据：

```text
单位利润 25、30：x_P2 = 0，目标恒为 2300（提高利润并不改变目标！）
单位利润 35：    x_P2 = 0，rc = 0（出现另一个同样好的顶点）
单位利润 40、45：x_P2 = 20，目标 2400 / 2500
```

**注意 35 那一行**：`rc = 0` 而 `x_P2` 仍然是 0，说明「恰好等于盈亏平衡价」时最优解**不唯一**（0 与 20 都是最优），求解器给的是其中一个顶点。这又是一次「对偶 / 原始解在临界点不唯一」的例子。

### 6.2 需求侧的方向不对称

`demand_P1` 这一行在基准点上有 `slack = 20`、影子价格 `0`。它为什么是 0，以及它什么时候不为 0：

```text
基准点（上限 40）：需求上限 40，实际生产 20，slack = 20 > 0
                    -> 这条约束「松」，放松它（提高上限）不改变任何东西，影子价格 0
压缩到 20 时：      实际生产 20 = 上限，约束顶死
                    -> 此时它的影子价格是 15（= 利润 P1 40 - 利润 P3 25）
```

那为什么是 `40 - 25 = 15`：需求上限压着 `P1` 时，少做一单位 `P1` 就得用 `P3` 顶上，而 `P3` 的单位利润是 25，所以损失一单位 `P1` 的代价是 `40 - 25 = 15`。**影子价格是「替代品的利润差」，不是「被限住的那件东西的利润」**——这是一个很容易当场算错、但对拍一定能抓住的地方。

另外要留意方向：

```text
基准点上的 0 是**右导数**（把上限往上调不涨），不是左导数（往下压会掉）。
同一个行、同一个函数，两侧斜率不同 —— 只在右导数意义上「0 是对的」。
```

### 6.3 产能被谁决定

`cap_L` 的实测区间 `[60, 90]` 与「几何下界 50」之间的差额（60 vs 50）说明：**区间的端点往往是另一条约束先顶死造成的，不是这条约束自己算出来的**。这条观察是 Week 2 讲「瓶颈约束会换人」的伏笔。

### 6.4 敏感性读数不该这么用（四个反例）

```text
反例一：把折点上的读数当全局斜率。
  cap_M = 120 处求解器报 0；以 120 为基准拿它往左预测 cap_M = 70，
  会得出 2600 + 0*(-50) = 2600（实测 1800，多算 800）。

反例二：把 rc 的绝对值当「不投产的损失」。
  rc(P2) = -5 不代表「不做 P2 就损失 5」。实测：单位利润 25、30 时目标都是 2300。

反例三：忽略方向。
  demand_P1 在基准点的影子价格 0 是**右导数**；把上限往下压时要用 15。

反例四：跨轴外推。
  cap_M ∈ [80, 120] 是在 cap_L = 80 固定的前提下测出来的；
  本实验只扫了单条轴，其余参数一律固定在基准值上——
  「两轴同时动」的区间没有被测量过（那需要二维网格，本周没做）。
```

四条反例的共同点：**影子价格与 `reduced cost` 都是「在当前这个基、当前这个方向、当前这组参数」下的量。** 引用时把这三项补全，才是完整的引用。

在这张网格上，线性预测成立的区间是 cap_L ∈ [60, 90]。
区间外预测立刻失效：目标值函数在折点处换了斜率，基准影子价格不再适用。
  取值为 60（区间左端点）时：左侧网格斜率 25、右侧网格斜率 10，求解器报 25。
  取值为 90（区间右端点）时：左侧网格斜率 10、右侧网格斜率 6.66667，求解器报 6.66667。
折点上的对偶解不唯一：求解器报的那个数是众多次梯度之一，
用它做预测前先问清楚「往哪个方向扰动」。

基准单位利润 30，基准 reduced cost -5，盈亏平衡价 = 30 - (-5) = 35

== 5. 需求轴：沿 demand_P1 扫描 ==
基准需求上限 40，该行影子价格 0
     需求上限        实测目标    该行 slack        该行影子价格      x_P1   线性预测

基准点上该行 slack = 20、影子价格 = 0，那是**右导数**；

== 6. 断言 ==
区间内预测成立（cap_M = 80）、区间外预测失效（cap_M = 130）两条断言均通过。

六处要留意的细节：

1. **`cap_M = 120` 那一行的影子价格是 `0.0000` 而预测仍然成立**：因为 `cap_M` 一路加到 120 时目标停在 2600（`demand_P1` 已经顶死），此时影子价格确实变成 0，而「预测」是用**基准**影子价格 15 算的，它在 `Δ = +20` 处恰好也对上（`y_M · Δ` 在区间端点处正好等于目标差）。这提醒一件事：**一个点「预测成立」不等于「基没变」**。所以在区间端点上要格外小心，不能把「端点仍成立」当成「端点内也都是这个基」。
2. **`cap_L = 90` 那一行的误差是 `-4.55e-13`**：这不是失效，是浮点噪声。同样的判定必须用容差（本仓库默认 `1e-9`），Day 6 会给这条容差定依据。
3. **`cap_L = 60` 处求解器报 25（左侧斜率）、`cap_L = 90` 处报 6.6667（右侧斜率）**：两个端点报的是**不同的那一侧**。这不是求解器的规矩，而是「它返回的那个次梯度恰好落在哪边」——事先无法假定，只能读出来再用。
4. **`cap_M = 70` 那一行的影子价格是 20**，与基准的 15 完全不同。这个 20 是左侧顶点族的斜率（`cap_L` 先顶死）。**同一行在不同顶点族上的影子价格不同**，这正是「必须带区间」的实证。
5. **第 4 节表格里 35 与 45 的目标值差是 100，而 40 与 45 的目标值也差 100**：因为 `x_P2` 在 40 和 45 时都是 20（`P2` 的需求上限 50 没有顶死）。这个数不是巧合，它等于 `Δunits × Δprofit`，但**它只在 `demand_P2` 顶死之前成立**——`P2` 的需求上限是 50，而 `x_P2` 只到 20，余量还很大。
6. **第 5 节第 10、15 两行的 `线性预测` 列写的是「失效（差 -150）」**：这个「预测」用的是**基准点**影子价格 0，所以预测值恒为 2300，而实测是 2150 / 2225。这一列存在的意义就是显示「基准点的 0 不能向左用」。

不看上文回答：

- Q1：影子价格 `y_i` 的准确定义是什么？在什么范围内可以用它做线性预测？

- Q6：`demand_P1` 基准点的影子价格为什么是 0？它在哪个方向上是对的？
- Q7：需求顶死时 `demand_P1` 的影子价格为什么是 `40 - 25 = 15`？
- Q8：`cap_M = 120` 处预测仍然成立，这能说明基没变吗？

- Q10：`cap_M = 140` 时目标值是多少？是哪条约束在起作用？

### 参考答案

- A1：第 `i` 条约束右端项单独增加 1 单位时最优值的变化率；只在最优基不变（该基的有效区间）内成立。
- A2：因为它描述的是目标值函数在某一点处的斜率，而该函数是分段线性的；失效的两种方式是「换了顶点族（斜率改变）」与「约束转为松弛（斜率变 0）」。
- A3：它是众多次梯度之一，可能等于左导数、右导数或两者之间的值；必须说明扰动方向才能用它预测。
- A4：不是。它是「让变量进基所需的系数提高量」，即盈亏平衡价；当斜率用会得出方向相反的结论。
- A5：因为需求约束 `demand_P1` 在 `cap_L` 降到 60 时先顶死了（`x_P1 = cap_M - cap_L = 100 - 60 = 40` 正好等于上限），比纯几何下界 50 更早换顶点。
- A6：因为它的 slack = 20 > 0，约束没有顶死；它在「提高上限」这一侧（右导数）是对的。
- A7：上限压着 `P1` 时，少做一单位 `P1` 要用 `P3` 顶上，`P3` 的单位利润是 25，所以损失 `40 - 25 = 15`。
- A8：不能。`y_M` 在 120 处已经变成 0，只是「基准影子价格 × Δ」恰好在端点处重合；端点上必须两面都看。
- A9：限定语是「在这张网格上」；网格点之间只做了线性插值、没有检查，所以只能说这些点上成立。
- A10：2600，由 `demand_P1` 决定（从 120 起 `x_P1` 就卡在 40 上限，产能再多也不能多做 `P1`）。

## 11. 今日一句话总结

> **影子价格与 reduced cost 都是局部量：前者是目标值函数在某条约束右端项方向上的斜率，只在最优基不变（本算例 `cap_M ∈ [80, 120]`、`cap_L ∈ [60, 90]`）的范围内有效，折点上它只是众多次梯度之一；后者的正确身份是「变量进基所需的系数提高量」，即盈亏平衡价（`P2` 是 35），把它当斜率用会得出方向相反的结论——引用任何一个这样的数，都必须带上它的区间。**
