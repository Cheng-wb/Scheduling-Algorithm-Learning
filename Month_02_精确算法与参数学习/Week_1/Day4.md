## 2. 为什么 Day 4 要「认真推导一遍」对偶

Day 2 已经在用影子价格了，Day 3 的位势法本质上也是对偶——但前两天都是「拿来就用」。今天要把这件事**从天上拽到地上**：

```text
Day 2：读求解器给的 dual 值                    「它说 15 就是 15」
Day 3：看两张网络 LP 的位势                     「u + v <= c 看起来像个对偶条件」
Day 4：把对偶 LP 显式构造出来、独立求解、逐项核对  ← 今天
```

为什么值得花一天：**对偶是可解释性的来源**。原始解说「做什么」，对偶解说「为什么这样做、瓶颈值多少钱、什么条件下结论会变」。没有对偶，LP 只是「一堆约束的解」；有了对偶，它才有经济学读法。

今天要建立的三件事：

```text
1. 一张表：任意原始 LP 都能机械地写出它的对偶，不需要灵感；

3. 一个检查：对偶的对偶回到原始 —— 用它验证自己造的对偶没有写错。
```

第三条是本周最实用的工程习惯：**不要「看」着对偶觉得对，要让它自己证明自己。**

## 3. 概念与对偶表

### 3.1 定义

**定义（对偶 LP）**：设原始问题（primal）为标准型

```text
max  c'x
s.t. A x <= b
     x >= 0
```

则它的对偶（dual）是

```text
min  b'y
s.t. A' y >= c
     y >= 0
```

对应关系：`A` 转置、`b` 与 `c` 互换、`max` 与 `min` 互换、`<=` 与 `>=` 互换。**对偶的约束数等于原始变量数，对偶的变量数等于原始约束数。**

### 3.2 对偶表（完整版）

标准型只是最常见的特例。一般形式下要按符号分别处理：

| 原始（`max`） | 对偶（`min`） |
|---|---|
| 第 `i` 条约束是 `<=` | `y_i >= 0` |
| 第 `i` 条约束是 `>=` | `y_i <= 0` |
| 第 `i` 条约束是 `=` | `y_i` 自由 |
| `x_j >= 0` | 第 `j` 条对偶约束是 `>=` |
| `x_j <= 0` | 第 `j` 条对偶约束是 `<=` |
| `x_j` 自由 | 第 `j` 条对偶约束是 `=` |

原始是 `min` 时，把表格左右两列的方向同时反过来（`<=` 与 `>=` 互换，`max` 与 `min` 互换）。

这张表在代码里就是 `build_dual` 的全部逻辑，**没有任何需要「想」的地方**。它的名字派生规则是：

```text
原始约束 cap_M  ->  对偶变量 y_cap_M
原始变量 x_P1   ->  对偶约束 d_x_P1
```

### 3.3 一个必须说清的限制

对偶表只覆盖**变量本身的下界/上界为零或无穷**的情形。如果变量带**有限上界**（例如 `0 <= x <= 40`），那么 `x <= 40` 本身就是一条额外约束，套用上面的表会漏掉它对应的那组对偶项，算出来的「对偶目标」会比强对偶要求的**少一截**。

本仓库的处理是**拒绝**而不是**猜**：

```python
raise ValueError(
    f"build_dual cannot handle bounded variables: {var_name} has bounds "
    f"[{lower}, {upper}]; write the bound as an explicit row instead"
)
```

对应到建模层就是 Day 1 定下的那条约定：**上界一律写成行**。于是三个 builder 生成的模型都能直接套表，不需要任何补丁。

### 3.4 对照表的一次实战：运输模型的对偶为什么是「位势」

把对偶表用到运输模型上，能一次性解释 Day 3 里三个「看起来奇怪」的现象。运输模型是 `min`，所以先把表的左右两列反过来用（`=` 行对应**自由**变量）：

```text
原始（min）                对偶（max）
每个源一条 = 行        ->  u_i 自由
每个汇一条 = 行        ->  v_j 自由
x_ij >= 0              ->  第 (i, j) 条对偶约束是 <=
目标 min Σ c_ij x_ij   ->  目标 max Σ a_i u_i + Σ b_j v_j
```

于是对偶约束恰好是 `u_i + v_j <= c_ij`（位势可行的条件），对偶目标恰好是 `Σ a_i u_i + Σ b_j v_j`（Day 3 实测 = 180.000000）。三个现象因此有了出处：

```text
1. 位势可以为负（实测 u_S2 = -2.0000）：等式行给的对偶变量是自由的，没有符号条件。
2. 全部 u 加 t、全部 v 减 t 不改变任何一条对偶约束：约束里只出现 u_i + v_j 这个和。
3. 对偶目标在平移下不变：Σ a_i (u_i + t) + Σ b_j (v_j - t) = 原值 + t(Σa - Σb)，
   而产销平衡给出 Σa = Σb，于是变化量为 0。
```

**这三条不是运输问题的「特殊巧合」，而是「等式行 → 自由对偶变量」这条规则的三个推论。** 同理，指派模型的对偶也是位势——区别只在指派的行是「每个人恰好一次」，右端项全是 1。

## 4. 推导：弱对偶与强对偶

### 4.1 弱对偶（可以手写证明）

**定理（弱对偶）**：设 `x` 是原始可行解、`y` 是对偶可行解，则 `c'x <= b'y`。

证明只有三行，思路是「给原始目标加上一个恒为非正的量」：

```text
对任意 y >= 0，由 Ax <= b 得 y'(b - Ax) >= 0，于是
c'x <= c'x + y'(b - Ax) = b'y + (c - A'y)'x
若还有 A'y >= c 且 x >= 0，则 (c - A'y)'x <= 0
故 c'x <= b'y                      证毕
```

注意证明里用到的两个条件：**`y >= 0`**（否则第一步不等号反向）与 **`A'y >= c, x >= 0`**（否则第三行不成立）。所以：

```text
弱对偶的适用范围：任意原始可行解 x 与任意对偶可行解 y。
```

它给出的界是**单侧**的：对 `max` 问题，对偶可行解的目标值一定是原始最优值的**上界**。求解器里的 `best_bound` 就是靠这个道理运作的——这也是 M1 里「`bound` 必须诚实」那条纪律在 LP 世界的对应物。

### 4.2 强对偶（有前提条件）

**定理（强对偶）**：若原始与对偶**都存在最优解**，则两者的最优值相等。

三个必须记住的条件：

```text
1. 两边都要可行（原始不可行时，对偶要么不可行、要么无界）；
2. 两边都要有最优解（「可行」不等于「有最优解」，无界就是反例）；
3. 「最优值相等」是结论，不是前提 —— 不能用它去证明可行性。
```

### 4.3 互补松弛

**定理（互补松弛）**：设 `x*`、`y*` 分别是原始与对偶的最优解，则

```text
x*_j * rc_j = 0        rc_j = c_j - Σ_i a_ij y*_i    对所有 j
slack_i * y*_i = 0     slack_i = b_i - a_i'x*        对所有 i
```

去符号化的读法：

```text
一个变量为正，它的 reduced cost 必须为 0；
一条不等式约束没顶死（slack > 0），它的影子价格必须为 0。
```

**等式行的 `slack` 恒为 0**，所以等式行上的 `slack · y = 0` 自动成立、不携带信息。真正有信息量的是不等式行上的那一半——核对时只统计不等式行，原因就在这里。

互补松弛不只是「最优解的性质」，它还是**证明最优性的工具**：今天第 5 节就会用它从原始解反推出对偶解，从而完成一次手算的最优性证明。

## 5. 手算：对偶解与互补松弛

### 5.1 手写 2D 算例的对偶

原始（`PRODUCTION_2D`）：

```text
max  40 x_P1 + 30 x_P2
s.t. 2 x_P1 +   x_P2 <= 100      (cap_M)
       x_P1 + 2 x_P2 <=  80      (cap_L)
      x_P1, x_P2 >= 0
```

按对偶表逐项翻译：

```text
约束是两行 <=      -> 两个对偶变量 y_M >= 0、y_L >= 0
变量是两个 x >= 0  -> 两条对偶约束，方向 >=
max                -> min（目标 min 100 y_M + 80 y_L）
系数矩阵转置        -> x_P1 的列 (2, 1) 变成第一条对偶约束的系数
```

得到：

```text
min  100 y_M + 80 y_L
s.t. 2 y_M +   y_L >= 40      (d_x_P1)
       y_M + 2 y_L >= 30      (d_x_P2)
     y_M, y_L >= 0
```

`y_M`、`y_L` 就是 Day 2 里读到的影子价格。

### 5.2 手算对偶最优解

两条对偶约束都是 `>=`，最优时应当都顶死（否则可以继续压低 `y`），解方程组：

```text
2 y_M +   y_L = 40
  y_M + 2 y_L = 30
两式相加：3 y_M + 3 y_L = 70   ->  y_M + y_L = 70/3
相减得：  y_M = 40 - 70/3 = 50/3
         y_L = 30 - 50/3 = 40/3？不 —— 由 y_M + y_L = 70/3 得 y_L = 20/3
检验：2*(50/3) + 20/3 = 120/3 = 40  ✓       50/3 + 2*(20/3) = 90/3 = 30  ✓
```

对偶目标：

```text
100 * 50/3 + 80 * 20/3 = (5000 + 1600) / 3 = 6600/3 = 2200
```

与 Day 1 手算的原始最优值 2200 相等——这正是强对偶。

两个数字的业务读法：`y_M = 50/3 ≈ 16.67` 元 / 单位 M、`y_L = 20/3 ≈ 6.67` 元 / 单位 L。它们的**比值**（5:2）解释了为什么最优解要「多做 `P1`」：`P1` 更吃 `M`，而 `M` 更值钱。

### 5.3 弱对偶的一个具体例子

取一个**不是最优**但对偶可行的点 `y = (20, 10)`：

```text
可行性：2*20 + 10 = 50 >= 40  ✓        20 + 2*10 = 40 >= 30  ✓
目标值：100*20 + 80*10 = 2800
弱对偶：2800 >= 2200  ✓（它是一个上界，尽管并不紧）
```

这个例子说明弱对偶为什么「弱」：**任何**对偶可行解都给上界，但只有最优的那一个给出紧上界。同时它也提醒一件事——**对偶不可行的 `y` 不提供任何界**，因为证明的第一步就断了。

## 6. 实现：`build_dual` 与对照表

对应文件 [lp_models.py](../../projects/02_optimization_models/opt_models/lp_models.py)。

### 6.1 三条实现规则

1. **对偶变量名 = `y_<原约束名>`、对偶约束名 = `d_<原变量名>`**：名字对应，不靠位置索引。`build_dual` 的返回模型里带 `meta = {"kind": "dual", "derived_from": ...}`，可以追溯它是谁的对偶。
2. **对偶变量挂符号条件**：`<=` 行给 `[0, +inf)`、`>=` 行给 `(-inf, 0]`、`=` 行给自由。这些是**变量界**，不是行——因为符号条件不是「资源约束」，它不该出现在对偶目标里。
3. **遇到有限上界抛 `ValueError`**（第 3.3 节）：宁可在构造阶段失败，也不要悄悄给出缺项的对偶。

### 6.2 用「对偶的对偶」做结构检查

对偶的对偶**在结构上必须回到原始**：系数矩阵转置两次回到原处、`max` 转两次回到 `max`、变量数转两次回到原数。于是有一条零成本的检查：

```text
构造 dual(dual(P))  ->  变量数、约束数、方向、最优值都应当回到 P
```

第 7 节的实测里，`dual(dual(prod_2d))` 的变量数与目标值都和原始一致（`2200`），差值 `0.000e+00`。**注意它是结构检查，不是正确性证明**：它只能发现「转置写反了、方向忘翻了」这类错误，不能证明对偶的每一项都翻译对了。要证明翻译正确，仍然要靠强对偶的数值对拍。

### 6.3 对偶读数在什么时候可以被解释

三个解释条件必须一起说：

```text
y_i 的含义：第 i 条约束的右端项增加 1 单位时最优值的变化率，
           仅在「最优基保持不变」的范围内有效（实测区间 `cap_M ∈ [80, 120]`）；
rc_j 的含义：让变量 x_j 被动增加 1 单位时目标的减少量（max 问题里 rc <= 0），
           等价地，是它进基所需的系数临界值（盈亏平衡价）；
两者都要求：该问题有最优解，且读的是 OPTIMAL 状态下的对偶解。
```

**没有这些条件，「影子价格 = 边际价值」就是一句会误导人的口号。**

### 6.4 三个常见误用

```text
误用一：把对偶最优解当成「唯一解」。
  Day 3 的两个网络模型都不唯一（运输有平移自由度、指派有退化带来的自由度）；
  能核验的是不变量（u_i + v_j <= c_ij、正分量处取等、Σu + Σv = 最优值）。

误用二：把 y_i 当成「第 i 种资源的利润率」。
  y_i 是右端项的单位变化率，量纲是「目标单位 / 右端项单位」；
  它随最优基变化，不带区间地引用会误导（实测区间 `cap_M ∈ [80, 120]`）。

误用三：把 rc_j < 0 当成「这个变量在亏钱」。
  rc_j 是相对量，衡量「在当前这个基下让 x_j 进基的代价」。
  P2 的单位利润是 30（正数），它的 rc 却是 -5；单位利润降到 25 时目标仍是 2300，
  不做 P2 一点也没亏。
```

三条误用的共同点：**它们都是把一个「相对 / 局部」的量当成「绝对 / 全局」的量来读。** 对偶表负责把 LP 翻译出来，它不负责提醒你这些量该怎么解释——那一步必须由人带上条件地说出来。

## 7. 实验：`m2w1d4_duality`

对应脚本 [m2w1d4_duality.py](../../projects/02_optimization_models/examples/m2w1d4_duality.py)，在项目目录下运行：

```bash
python examples/m2w1d4_duality.py
```

脚本把「对偶」当成可复核的对象：先打印原始模型，再由 `build_dual` 生成对照表，然后**独立求解对偶**、手算核对、演示弱对偶、逐项核对互补松弛，最后做对偶的对偶检查。实际输出：

```text
== 1. 原始 LP（标准型：max c'x, Ax <= b, x >= 0）==
max 40*x_P1 + 30*x_P2
  cap_M    2*x_P1 + 1*x_P2 <= 100
  cap_L    1*x_P1 + 2*x_P2 <= 80
  非负       x_P1 >= 0, x_P2 >= 0

== 2. 原始—对偶对照表（由 build_dual 的命名约定生成，不靠位置索引）==
约束行 -> 对偶变量（含符号条件）：
  原始约束           方向      右端项   对偶变量          符号条件
  cap_M          <=    100.0   y_cap_M       y >= 0
  cap_L          <=     80.0   y_cap_L       y >= 0
原始变量 -> 对偶约束（含方向与右端项）：
  原始变量         对偶约束           方向      右端项
  x_P1         d_x_P1         >=     40.0
  x_P2         d_x_P2         >=     30.0
对偶目标：min 100*y_cap_M + 80*y_cap_L

原始状态 OPTIMAL，原始最优 2200；影子价格 {'cap_M': 16.6666666667, 'cap_L': 6.6666666667}

== 3. 手算对偶最优解（两条对偶约束同时顶死）==
解方程组 2 y_M + y_L = 40、y_M + 2 y_L = 30，得 y_M = 50/3、y_L = 20/3
对偶目标 b'y = 100*(50/3) + 80*(20/3) = 2200
求解器独立求解对偶得 2200，差值 4.547e-13
对偶状态 OPTIMAL，对偶变量 {'y_cap_M': 16.6666666667, 'y_cap_L': 6.6666666667}

== 强对偶：|原始目标 - 对偶目标| = 4.547e-13（容差 1e-09）==
强对偶的前提是两边都有可行解且都有最优解；本算例满足。

== 4. 弱对偶：任意对偶可行解都给出原始目标的上界 ==
取一个**非最优**的对偶点 y_M = 20、y_L = 10：
  对偶约束 2 y_M + y_L = 50 >= 40，可行
  对偶约束 y_M + 2 y_L = 40 >= 30，可行
  它的目标值 b'y = 2800
弱对偶断言：2800 >= 原始最优 2200，成立。
注意：弱对偶只对**对偶可行**的点成立，不可行的 y 不提供任何界。

== 5. 互补松弛逐项核对（2D 算例）==
类型                名字                 原始侧         对偶侧          乘积
variable          x_P1         40.000000    0.000000   0.000e+00
variable          x_P2         20.000000    0.000000   1.421e-13
inequality_row    cap_M         0.000000   16.666667   2.368e-13
inequality_row    cap_L         0.000000    6.666667   0.000e+00
两条产能行 slack = 0，它们的影子价格可以不为 0；
两个变量都为正，它们的 reduced cost 必须是 0。这就是互补松弛的两半。

== 6. 对偶的对偶：结构上应当回到原始 ==
原始 2 个变量、2 条约束
对偶 2 个变量、2 条约束
对偶的对偶 2 个变量、2 条约束
变量名逐一对应：('y_d_x_P1', 'y_d_x_P2')
方向：原始 max -> 对偶 min -> 对偶的对偶 max
目标值：原始 2200、对偶 2200、对偶的对偶 2200
对偶的对偶与原始的差 |gap| = 0.000e+00

== 7. 断言 ==
强对偶、手算对偶解、对偶的对偶三项断言全部通过。
```

五处要留意的细节：

1. **对偶是独立求解出来的**：脚本调用 `build_dual(model)` 造出一个真的 LP，再用 `solve_model` 解一次。所以第 3 节那个 `4.547e-13` 是**两次独立求解**的差，不是把原始目标抄了一遍。这是「强对偶」在本周最实在的一次验证。
2. **`x_P2` 那一行的乘积是 `1.421e-13` 而不是 0**：`x_P2 = 20`、`rc = 0`，浮点乘法给出的是噪声量级的非零值。**互补松弛是理论上的严格等式，实测里只能到噪声水平**——所以判定必须带容差。
3. **`inequality_row` 只列了两条产能行**：等式行不列（`slack` 恒为 0，乘积恒为 0）。这份「不列」是刻意的，属于第 4.3 节那条说明的实现。
4. **对偶的对偶的变量名是 `y_d_x_P1`**：名字按约定层层叠加，看起来有点笨，但它证明了一件事——**每一层都是机器生成的，没有一次是手抄的**。
5. **弱对偶那一段用的是 `y = (20, 10)`**，一个既可行又明显不最优的点。它给出的上界 2800 与真值 2200 差了 600，正好说明「对上界」与「等于」的区别。

## 10. 自测题

不看上文回答：

- Q1：标准型的对偶是什么？`max` 变成什么？约束方向变成什么？
- Q2：对偶表里 `>=` 行对应的对偶变量符号是什么？为什么？
- Q3：弱对偶的结论是什么？它对哪些点成立？
- Q4：强对偶的结论与前提条件分别是什么？
- Q5：互补松弛的两半分别是什么？为什么等式行不列？
- Q6：`y_i` 的业务含义是什么？在什么范围内有效？
- Q7：`rc_j` 的业务含义是什么？它与「盈亏平衡价」的关系是什么？
- Q8：`build_dual` 遇到带有限上界的变量会怎么做？为什么？
- Q9：「对偶的对偶回到原始」能证明什么、不能证明什么？
- Q10：如果一个解 `y` 不满足对偶可行性，它的目标值还能给上界吗？

### 参考答案

- A1：`min b'y s.t. A'y >= c, y >= 0`；`max` 变成 `min`，`<=` 变成 `>=`，`A` 转置，`b` 与 `c` 互换。
- A2：`y_i <= 0`。因为原始 `>=` 行在 `max` 问题里是「至少要做这么多」的下限，放松它（把右端项调小）不会让目标变好，对偶方向因此相反。
- A3：任意原始可行解与任意对偶可行解满足 `c'x <= b'y`（`max` 问题）；只对**双可行**的点成立。
- A4：两边都有最优解时最优值相等；前提是两边都可行且都有最优解（无界或不可行的情形不适用）。
- A5：`x_j · rc_j = 0` 与 `slack_i · y_i = 0`；等式行的 `slack` 恒为 0，乘积恒为 0，不携带信息。
- A6：第 `i` 条约束右端项增加 1 单位时最优值的变化率；只在最优基不变的区间内有效（实测区间是 `cap_M ∈ [80, 120]`）。
- A7：变量的对偶松弛：让 `x_j` 被动增加一单位时目标的减少量；等价于它进基所需的系数临界值，即盈亏平衡价（`P2` 是 35）。
- A8：抛 `ValueError`。有限上界是一条额外约束，套用对偶表会漏掉它对应的项，给出的「对偶目标」会比强对偶要求的小。
- A9：能发现「转置写反、方向忘翻」这类结构错误；不能证明每一项都翻译正确——那要靠强对偶的数值对拍。
- A10：不能。弱对偶证明的第一步要求 `y >= 0`，对偶可行性（`A'y >= c`）是第三行的前提；不满足时推导直接断裂。

## 11. 今日一句话总结

> **对偶不是灵感而是翻译：按对偶表把 `max / <=` 换成 `min / >=`，就有了一个能独立求解的 LP；弱对偶总是成立、强对偶要求两边都有最优解、互补松弛把「变量为正」与「约束顶死」配对起来——影子价格与 reduced cost 就是这张表在业务上的读法，而且只在基不变的范围内有效。**
