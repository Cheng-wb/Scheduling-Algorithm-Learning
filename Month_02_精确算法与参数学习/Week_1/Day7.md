## 2. 为什么 Day 7 要复盘

七天的内容如果只是七份笔记，那学到的是一堆技巧；复盘要做的是**把它们连成一条流水线**，并且**标出流水线在哪里会崩**：

```text
Day 1  写模型（集合 / 参数 / 变量 / 目标 / 约束）
Day 2  求解并读四个量
Day 3  换两个有网络结构的模型
Day 4  推导对偶，把「读量」变成「有定理支撑的读量」
Day 5  量出读量的有效区间
Day 6  用五条独立核对把整条链验一遍
Day 7  收拢成流水线 + 写下局限          ← 今天
```

复盘的价值全在第二件事上。一套工具如果只说「怎么用」，使用者会在它失效的地方继续用它——本周已经出现过三次这种失效：

```text
局限一：状态码 → 把 INFEASIBLE 当成「真的不可行」（Day 6 第 5 节）
局限二：影子价格 → 拿 15 去预测产能 130 的目标值，多算 150（Day 5 第 2 节）
局限三：对偶解 → 把求解器打印的那一组当成唯一真理（Day 3 第 9 节）
```

**这三条局限不是「注意事项」，而是本周最硬的知识**。

## 3. 概念：建模九步

### 3.1 定义（一条 LP 从业务问题到可执行结论的流水线）

**定义（建模九步）**：前五步写模型，后四步读模型。

| 步骤 | 做什么 | 做到什么算做完 |
|---|---|---|
| 1. 写集合 | 产品、资源、源、汇、人、任务 | 索引集合写死，型号顺序后面全靠它 |
| 2. 写参数 | 利润、消耗、产能、需求、运费、成本 | 每个参数带单位，且与集合对齐 |
| 3. 写变量 | 决策变量的含义 | 先声明取值范围（`>= 0` / 自由 / 整数），再谈含义 |
| 4. 写目标 | `max` 或 `min` 的线性式 | 写明它是「单位量 × 数量」的求和，不许有常数项 |
| 5. 写约束 | 每条约束一句话：谁被谁限制 | 上界写成行，不写成变量界 |
| 6. 求解 | 调用求解器 | 读状态；状态不是 `OPTIMAL` 时先别解释目标值 |
| 7. 读解 | 四个量一起读 | `primal`、`slack`、`reduced cost`、`shadow price` |
| 8. 对拍 | 五条独立核对 | `c'x` 与 `b'y` 互相印证；互补松弛与 `rc` 恒等式做结构核对 |
| 9. 解释 | 翻译回业务语言 | 标出它成立的**区间** |

### 3.2 四条不可让步的规矩

```text
1. 上界写成行，不写成变量界。
   理由：Day 4 的 `build_dual` 遇到有限上界会抛 ValueError——
   因为套对偶表会漏掉那一项，给出的对偶目标是错的。

2. 状态不是 OPTIMAL 时，先别解释目标值。
   理由：Day 6 实测 GLOP 对无界 LP 也返回 INFEASIBLE；
   状态码只说明「有没有最优解」，不说明问题本身的性质。

3. 没有检查过就是 None，不是 0。
   理由：Day 6 的不可行算例里 objective/primal/dual/slack 全写 None；
   写 0 会造出一行「看起来很成功」的假数据。

4. 任何数字都要带区间与容差。
   理由：Day 5 的 `cap_M ∈ [80, 120]`；Day 6 的 `1e-9`（比实测噪声 2e-13
   宽约 4 个数量级）。不带区间的数字与不带容差的相等判断都是半成品。
```

### 3.3 后四步的输入输出

```text
第 6 步 -> 状态（OPTIMAL / INFEASIBLE / …）
第 7 步 -> primal（做什么）+ slack（哪条约束顶死了）
          + reduced cost（哪个变量差一点就能进基）
          + shadow price（哪条约束值得投钱）
第 8 步 -> 五条核对量（残差 / 互补松弛 / rc 恒等 / 对偶可行 / gap）
第 9 步 -> 业务语言 + 成立区间 + 容差
```

### 3.4 如果只能留三条

一周的内容可以压成三条，共同点是「每条都指向一个具体的失败模式」：

```text
规矩一：看到 OPTIMAL 才解读目标值，看到别的先停下来。  防止把「没有最优解」读成「最优值是 0」
规矩二：引用任何对偶读数都带上区间。                    防止用 cap_M 的 15 去预测 130
规矩三：无法判断的字段写 None。                         防止把「没检查」伪装成「检查通过」
```

三条规矩分别对应本周的三个反例：GLOP 的状态码陷阱（Day 6 第 5 节）、`cap_M` 的区间外预测（Day 5 第 2 节）、不可行算例的字段（Day 6 第 6 节）。**能背下规矩不算掌握，能立刻说出它防的是哪一次具体事故才算。**

## 4. 手算：本周五个算例的总账

### 4.1 总账

| 场景 | 类型 | 规模 | 状态 | `primal` | `dual` | `\|gap\|` | 互补松弛 |
|---|---|---:|---|---:|---:|---:|---:|
| `prod_2d` | `production` | 2×2 | OPTIMAL | 2200 | 2200 | 4.55e-13 | 2.37e-13 |
| `prod_base` | `production` | 3×5 | OPTIMAL | 2300 | 2300 | 0.00e+00 | 2.13e-13 |
| `prod_infeasible` | `production` | 3×6 | INFEASIBLE | None | None | None | None |
| `transport_base` | `transportation` | 6×5 | OPTIMAL | 180 | 180 | 0.00e+00 | 0.00e+00 |
| `assign_base` | `assignment` | 9×6 | OPTIMAL | 9 | 9 | 0.00e+00 | 0.00e+00 |

三个手算依据（全部在本周出现过）：

```text
prod_2d     ：极点枚举，最优顶点 (40, 20)，目标 40*40 + 30*20 = 2200（Day 1）
transport   ：逐项相加 4*15 + 6*5 + 4*15 + 3*10 = 180（Day 3）
assignment  ：3! = 6 种指派全枚举，最小 9（Day 3）
```

### 4.2 三条读数规则

1. **`gap` 不为 0 的那两行，原因相同**：`prod_2d` 与 `prod_base` 的对偶解含分数（`50/3`、`20/3`），浮点表示带来 `1e-13` 级的噪声；`transport` 与 `assignment` 的整数数据在 `double` 里是精确的，所以 `gap` 恰好是 0。**噪声的来源是问题本身含分数，不是求解器不稳。**
2. **互补松弛列的量级与 `gap` 一致**：都是 `1e-13` 级。这两列互相印证——它们都由「分数 × 浮点」产生。
3. **不可行行的四个量都是 `None`**：这一行**不是失败**，它是本周最重要的记录之一。把它写成 0 会让「没有解」伪装成「目标值为 0 的最优解」。

### 4.3 对偶的四个读数量

| 约束行 | `slack` | `shadow price` | 业务读法 |
|---|---:|---:|---|
| `cap_M` | 0.0000 | 15.0000 | M 产能多 1 单位，利润 +15；少于 15 元/单位就别扩 |
| `cap_L` | 0.0000 | 10.0000 | L 产能多 1 单位，利润 +10；同理 |
| `demand_P1` | 20.0000 | 0.0000 | 需求上限放松 1 单位不改变利润——它现在没顶住 |
| `demand_P2` | 50.0000 | 0.0000 | 同上；P2 的需求上限根本用不上 |
| `demand_P3` | 20.0000 | 0.0000 | 同上；P3 还有 20 单位余量 |

| 变量 | `x` | `reduced cost` | 业务读法 |
|---|---:|---:|---|
| `x_P1` | 20.0000 | 0.0000 | 已投产，`rc = 0`；它是基变量，没有额外信息 |
| `x_P2` | 0.0000 | -5.0000 | 不投产；P2 的单位利润要涨到 35 才值得开工 |
| `x_P3` | 60.0000 | 0.0000 | 已投产，`rc = 0`；它是基变量，没有额外信息 |

四句必须一起说清的话：

```text
shadow price：只有在最优基不变的区间内才是「边际价值」（cap_M 是 [80, 120]）；
reduced cost：是盈亏平衡价（35），不是「涨 5 元就多赚 5 元」；
slack = 0    才可能 shadow price > 0；slack > 0 时它必然是 0；
gap = 0      是强对偶的数值形态，它要求两边都有最优解。
```

### 5.3 「不覆盖非空目录」是纪律不是洁癖

驱动在写之前先检查输出目录：

```python
if output.exists() and any(output.iterdir()):
    raise ValueError(f"output must be empty (preserve previous experiments): {output}")
```

实测拒绝行为（在项目目录下运行 `python -m opt_experiments.lp_experiments`，目录已非空时）：

```text
refused: output must be empty (preserve previous experiments): ...\artifacts\month2_w1
```

**为什么要拒绝**：覆盖式重跑会把「上一次的结果」和「这一次的结果」混在一份文件里，而两次运行的容差、求解器版本、代码版本可能不同。**一份来源不明、内容混合的产物，比没有产物更危险**——它会让人以为自己在看证据，其实在看两份不同世界的平均值。

## 6. 三条局限（每条都有本周的反例）

### 6.1 局限一：状态码不等于可行性结论

```text
现象：GLOP 对「可行但目标无下界」与「真的可行域为空」返回同一个状态码 INFEASIBLE。
反例：Day 6 第 5 节的两个探针（min -x, x >= 0 与 min y, y >= 1, y <= 0）。
结论：状态码只能读作「没有最优解」；要判断「可行域是否为空」必须另找证据
      （手算、加人工界、换后端）。
```

### 6.2 局限二：`shadow price` 只在基不变的区间内有效

```text
现象：cap_M 的影子价格在 [80, 120] 上是 15；到 130 时目标停在 2600。
反例：用 15 预测 cap_M = 130 的目标值 -> 2300 + 15*30 = 2750，实测 2600，多算了 150。
结论：引用影子价格必须带区间；折点上它只是众多次梯度之一。
```

### 6.3 局限三：对偶解可能不唯一

```text
现象：assign_base 的对偶有 6 个变量，取等的对偶约束却只有 5 条
      （其中 2 条来自退化的零分量），于是最优对偶解有一维自由度。
反例：Day 3 第 9 节；运输问题还有「全部 u 加 t、全部 v 减 t」的平移自由度
      （实测 t = 0 / 1 / -2.5 的对偶目标都是 180）。
结论：能核验的是不变量（u_i + v_j <= c_ij、正分量处取等、Σu + Σv = 最优值），
      不是某一组具体数值。
```

### 6.4 本周边界之外还剩什么

三条局限指向同一件事：**LP 能给的是一组「条件化的最优」，不是无条件的最优**。而下面这些问题 LP 根本表达不了，不在本周范围：

```text
整数决策（要么开工要么不开工、机器不许拆分）  -> 不在本周范围（本周只观察到网络 LP 恰好整数）
顺序与资源不重叠（同一台机器上两件活不能同时干）-> 不在本周范围
求解时间与最优性的权衡（算不完怎么办）          -> 不在本周范围
对称性、热启动、诊断                            -> 不在本周范围
```

### 6.5 三条局限在工程上怎么落地

```text
局限一 -> 把限制写成常量，让下游看得见：GLOP_STATUS_CAVEAT 随状态一起被打印与写入 metadata.json；
局限二 -> 报影子价格时必须同时报区间；区间由网格实测给出，端点由手算不等式解释；
局限三 -> 断言只写不变量（u_i + v_j <= c_ij、正分量处取等、Σu + Σv = 最优值），
          不写「那一组具体数值」。
```

三条落地方式的共同思路：**把「不能说的事」写进代码与产物，而不是写在注释里。** 注释会被忽略，而 `metadata.json` 里的字段、`results.csv` 里的 `None`、断言里的不等式不会——它们会在下一次运行、下一次对拍里继续说话。

```text
局限一：状态码不等于可行性结论。
  prod_infeasible 返回 INFEASIBLE，但本环境 GLOP 对无界 LP 也返回同一个码；
  「真的不可行」是手算 x_P2 <= 50 与 x_P2 >= 60 冲突得到的。
局限二：shadow price 只在基不变的区间内有效。
  cap_M 的影子价格在 [80, 120] 上是 15；到 130 时目标停在 2600，
  线性预测会给出 2750，多算了 150。
局限三：对偶解可能不唯一，别把打印出来的那一组当成唯一真理。
  assign_base 的对偶有 6 个变量，取等的对偶约束却只有 5 条
  （其中 2 条来自退化的零分量），于是最优对偶解有一维自由度；
  能核验的是不变量（u_i + v_j <= c_ij、u + v 在配对上取等、Σu + Σv = 9）。

== 5. 断言 ==
复盘用到的六个数字全部来自本周脚本与手算，断言通过。
```

五处要留意的细节：

1. **第 2 节里 `prod_infeasible` 那一行是唯一有 `None` 的**：它不是「跑失败了」，而是**故意的**。这一行存在的意义是让「没解」这件事出现在总账里，而不是被悄悄跳过。
2. **`prod_2d` 与 `prod_base` 的 `互补松弛` 列非零，另两行为 0**：这正是第 4.2 节那条读数规则——分数的浮点噪声。**不要把它当成「生产计划的模型更差」**。
3. **第 3 节最后那句「注意 x_P2 那一行」是刻意加的**：四个读数量里最容易读错的就是 `reduced cost`（把它当斜率），所以复盘表专门指出来。
4. **局限三的措辞是「有一维自由度」而不是「这一组是错的」**：求解器给的那一组**确实是对偶最优解**，只是**不是唯一**的。**说「求解器错了」和说「解不唯一」是两件完全不同的事。**
5. **第 5 节的六条断言**：`2300`、`15`、`-5`、`x_P2 = 0`、`cap_M = 130` 时 `2600`，以及「线性预测的偏差大于 100」这一条。最后一条断言是**故意用不等式**写的——它验的不是某个具体数字，而是「预测失效」这个现象确实存在。

不看上文回答：

- Q1：建模九步里哪五步是「写模型」？哪四步是「读模型」？
- Q2：「上界写成行，不写成变量界」的理由是什么？
- Q3：`prod_2d` 的 `gap` 是 `4.55e-13` 而 `transport_base` 是 0，为什么？
- Q4：不可行算例的 `objective` 为什么写 `None`？

- Q6：三条局限分别是什么？各举一个本周的反例。
- Q7：`reduce cost` 的正确读法是什么？错误读法会得出什么结论？
- Q8：实验驱动为什么要拒绝非空输出目录？
- Q9：举一个 LP 表达不了的问题，并说明要用什么补救。
- Q10：「结论 + 区间 + 容差」三件套为什么缺一不可？

### 参考答案

- A1：前五步（写集合、写参数、写变量、写目标、写约束）写模型；后四步（求解、读解、对拍、解释）读模型。
- A2：有限上界是一条额外约束，套对偶表会漏掉它对应的项，算出的对偶目标是错的；`build_dual` 遇到这种变量直接抛 `ValueError`。
- A3：`prod_2d` 的对偶解含分数（`50/3`、`20/3`），浮点表示带来 `1e-13` 级噪声；`transport_base` 的整数数据在 `double` 里精确，所以 `gap` 恰好为 0。
- A4：`None` 表示「没有最优解，这个量不存在」。写 0 会让「没有解」伪装成「目标值为 0 的最优解」。
- A5：`slack`（哪条约束顶死了）、`shadow price`（哪条约束值得投钱）、`reduced cost`（哪个变量差一点就能进基）、`gap`（强对偶的数值形态）。
- A6：状态码不等于可行性结论（GLOP 对无界也返回 `INFEASIBLE`）；`shadow price` 只在基不变的区间内有效（`cap_M` 用 15 预测 130 多算 150）；对偶解可能不唯一（`assign_base` 6 个对偶变量只有 5 条取等约束；运输的平移自由度）。
- A7：正确读法是「让这个变量进基所需的系数提高量」（盈亏平衡价，`P2` 是 35）；错误读法是把它当斜率，会得出「单位利润越低越赚」的方向相反结论。
- A8：覆盖式重跑会把两次不同容差 / 版本的结果混在一起；来源不明的混合产物比没有产物更危险。
- A9：例：「要么不开工、要么至少做 25」（半连续变量）——LP 会给出 `0 < x_P2 < 25` 的分数解，必须用整数变量或 `big-M` 约束表达。
- A10：只有结论会让人用错区间（`cap_M = 130` 的预测）；只有区间会让人忘记数值不是精确的（`4.55e-13` 的 `gap` 到底是错还是噪声）；只有容差会让人在含义不明的数字上继续算。

## 11. 今日一句话总结

> **Week 1 的成果是一条能自证的流水线：九步把业务问题写成 LP 再读回业务结论，四个读数量（`slack`、`shadow price`、`reduced cost`、`gap`）各回答一个业务问题，五条独立核对（残差、互补松弛、`rc` 恒等式、对偶可行、独立求解的对偶目标）把它验一遍；而它真正的边界写在三条局限里——状态码不等于可行性结论、影子价格只在基不变的区间（`cap_M ∈ [80, 120]`）内有效、对偶解可能不唯一——所以本周所有结论都以「数字 + 区间 + 容差（`1e-9`）」的形式给出，并且任何无法判断的字段都写 `None` 而不写 0。**
