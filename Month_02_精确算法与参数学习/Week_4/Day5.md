## 1. 共同接口不是把所有方法伪装成同一种求解器

统一接口是为了让可比较的信息放在同一位置，同时保留无法比较或无法获得的信息。启发式有解但通常没有求解器下界；精确方法可能有界但尚无解；异常运行可能两者都没有。

| 字段 | 含义 | 缺失时 |
|---|---|---|
| status | 本次运行的结论与终止状态 | 保留明确工程状态 |
| schedule | 可供独立验证的排程 | None |
| objective | 该排程按共同目标重算的数值 | None |
| best_bound | 同一目标、单位及问题范围下的有效界 | None |
| gap | 已知可行值与有效界之间的差距 | 任一端缺失则 None |
| build_time / solve_time | 两个阶段的耗时 | 不把未执行误写成真实测量 |

## 2. 本项目的 gap 约定

最小化下项目采用 $g=(U-L)/\max(1,|U|)$。这是项目报告约定，不是所有求解器原生相对 gap 的统一定义。U=0 或目标为负时，尤其要记录分母约定并同时提供绝对差距。

如果目标乘以系数 a>0 或加常数 b，U 与 L 都要变成 aU+b、aL+b。绝对差距按 a 缩放，但相对 gap 可能受常数项影响，因此“等价优化目标”不保证相同 gap 百分比。

## 3. 证书范围必须明确

同一个 best_bound 字段必须注明它属于原问题、加了安全截断的等价优化问题，还是固定变量后的受限子问题。后者不能直接用来证明原问题最优。

项目的 `milp_fixing` 和自定义状态词表需要按实际含义阅读。代码接受某个状态字符串，不意味着这个字符串是 CP-SAT 原生枚举；代码生成了 gap，也不自动保证两端属于同一个问题范围。

## 4. 界的取整需要看目标格点

如果原目标严格取整数值，数学上有效的最小化下界 L 可加强为 $\lceil L\rceil$。若目标是分数权重的和，或经过近似缩放，就未必适用。浮点误差也需要保守处理。

向下取整整数目标的下界仍然安全，但通常更弱；“下界绝不能向上取整”不是一般数学结论。最重要的是证明有效性与保持单位，而非机械选某个取整函数。

## 5. 实验与自测

运行统一结果脚本，检查无解、无界信息和正常解三类行。启发式可以配外部解析下界，但应明确写出来源，不能冒称来自启发式搜索本身。

1. 没有下界时填 objective 会怎样？制造假零 gap。
2. 没有下界时填 0 总安全么？不是，目标可为负，且“未知”与“证明非负”不同。
3. U=10、L=8，加目标常数 100 后相对 gap 相同吗？不相同：项目公式从 0.2 变为 2/110。
