## 2. 为什么要理解机制

Day 6 得到了两组方向相反的观察：

```text
parallel_8 / parallel_12 ：CP-SAT 证明最优比 time-indexed MILP 快两个数量级
single_12                ：time-indexed MILP 证明 532 用了 0.6216 s
                            CP-SAT 找到 532 但 5 秒仍没证明
```

如果只停在这一层，能得到的结论只有「各有强项」。但这句话对下周、下个月的建模决策**没有指导价值**——遇到一个新实例，你还是不知道该把预算投给哪一边。

要把「各有强项」升级成可迁移的判据，必须回答：

```text
CP-SAT 快的时候，它在做什么推理？
MILP 快的时候，它的下界是从哪来的？
这两种推理各自在什么结构上失效？
```

今天的四组观察分别回答这四个问题：

| 观察 | 针对的机制 |
|---|---|
| 链 vs `NoOverlap` 的域 | CP 的传播能推多远、在什么地方停 |
| root LP 的实测 gap | MILP 的下界从哪来、有多紧 |
| CP-SAT 的界随预算抬升 | CP 的界为什么不是「一次算出来」的 |
| 分支数与冲突数 | 两种搜索在「切什么」上的本质区别 |

```text
Day 1-4  建模型
Day 5    读状态
Day 6    比较（观察「谁快谁慢」）
Day 7    解释（回答「为什么」）        ← 今天
```

**能不能解释现象，是「会用工具」与「懂工具」的分界。**

## 3. 概念：两条推理路线

### 3.1 定义（传播）

**定义（域传播）**：给定变量 $x$ 的域 $D(x)$ 与作用于一组变量的约束 $c$，传播指：从每个变量的域中**删去不可能出现在任何满足 $c$ 的赋值里的取值**。

对一个不等式约束 $x + p \le y$，传播做的就是：

```text
上界方向：max D(y) 变小 -> max D(x) <= max D(y) - p
下界方向：min D(x) 变大 -> min D(y) >= min D(x) + p
```

注意它**只动端点，不动中间**。域 $[0, 25]$ 在 $x$ 的下界抬到 5 之后变成 $[5, 25]$；它不会去论证「$x$ 不可能取 17」。

**定义（松弛）**：把原问题的约束集 $\mathcal{C}$ 换成更松的 $\mathcal{C}' \supseteq \mathcal{C}$（满足原约束的解一定满足新约束），再求 $\mathcal{C}'$ 上的极值。

线性松弛（LP relaxation）的典型做法是把 $x \in \{0,1\}$ 换成 $x \in [0,1]$：**整数性被放掉**。

### 3.2 两条路线的对照

| 维度 | CP 的传播 | MILP 的线性松弛 |
|---|---|---|
| 动的是什么 | 变量的**域**（端点） | 变量的**取值范围**（整数性、可行域的凸包） |
| 一次操作给出 | 一批被排除的取值 | 一个下界值 |
| 下界从哪来 | 逐步推理，**随搜索推进收紧** | 一次 LP 求解，**与搜索无关** |
| 全局性 | 局部推理，差在「不会算全局量」 | 全局（LP 本身是全局优化），差在「凸化太松」 |
| 何时失效 | 约束是纯局部的互斥（如 `NoOverlap`）时推不动全局量 | 结构高度非凸时（如不可抢占性）松弛太松 |
| 典型强项 | 区间互斥、选机、容量 | 线性成本结构、交期惩罚 |

**关键的一句话**：传播在**排除不可能**，松弛在**给出不可能更低的界**。前者天然适合回答「这样排不可能」，后者天然适合回答「不可能比这个值更好」。

### 3.3 理论结论

**结论 1**：对同一实例，LP 松弛给出的下界**与给求解器多少时间无关**（只要 LP 解得出来）。它是问题结构与模型形式的函数，不是搜索进度的函数。

**结论 2**：CP-SAT 在搜索中给出的 `best_bound` 是**搜索进度的函数**。预算越大界越紧，但可能一直停在平凡界附近。

**结论 3**：两个下界都合法（都是「最优值不低于它」的证明），所以在同一实例上比较 `objective` 与 `bound` 是合法的；**但「谁的界更紧」不能归因于范式**——它由建模方式与结构决定。

结论 3 在 Day 6 已经用「同一 MILP 范式内部 gap 差 0.9」证过一次；今天第 7 节会用 LP gap 的实测数据从另一个角度再证一次。

## 4. 推导：两种推理各能推多远

### 4.1 链上一次传播的逐变量计算

构造：三道工序各长 5，单向优先级链 $O_0 \to O_1 \to O_2$，时间上界 $H = 30$，即 $end_i \le 30$ 且 $end_i \le start_{i+1}$。

```text
初始：
    D(start0) = D(start1) = D(start2) = [0, 30]
    D(end_i)  = [0, 30]   （end_i = start_i + 5 会把下界提到 5）

第 1 轮：从终点往回推
    O2 的 end <= 30          -> D(end2) = [5, 30]
    O2 的 end <= 30 且 p=5   -> D(start2) 上界 30 - 5 = 25 -> [0, 25]
    O1 的 end <= start2     -> D(end1) 上界 <= max D(start2) = 25 -> [5, 25]
    O1 的 start <= end1 - 5  -> D(start1) 上界 <= 25 - 5 = 20 -> [0, 20]
    O0 的 end <= start1     -> D(end0) 上界 <= max D(start1) = 20 -> [5, 20]
    O0 的 start <= end0 - 5  -> D(start0) 上界 <= 20 - 5 = 15 -> [0, 15]
```

一轮推完，端点域就是脚本第 1 节打印的那组：

```text
chain_start0  -> [0, 15]
chain_end0    -> [5, 25]
chain_start1  -> [5, 20]
chain_end1    -> [10, 25]
chain_start2  -> [10, 25]
chain_end2    -> [15, 30]
```

注意两件事：

```text
（a）链的传播等价于「把后面所有工序的长度和减掉」：
     start2 的上界 = 30 - 5 = 25
     start1 的上界 = 30 - 5 - 5 = 20
     start0 的上界 = 30 - 5 - 5 - 5 = 15
     公式：start_i 的上界 <= H - sum(后序所有工序的长度) - p_i
       start0: 30 - (5+5) - 5 = 15
       start1: 30 - 5 - 5     = 20
       start2: 30 - 0 - 5     = 25
     这与输出完全一致，说明这条链上的传播达到了「路径下界」的强度。

（b）end0 的下界从 0 被抬到 5、start1 的下界抬到 5、end1 抬到 10：
     这是从「end_i = start_i + 5」与「start_i >= 0」一路推下去的结果。
     域在变紧，但一遍推完就是不动点，不会再多。
```

### 4.2 `NoOverlap` 上同样三个区间

把链换成「三个长 5 的区间互不重叠」（`AddNoOverlap`），$H = 30$：

```text
输出：noov_start{i} -> [0, 25]，noov_end{i} -> [5, 30]，三者相同。
```

推导这个 25 是怎么来的：

```text
NoOverlap 对每个区间只能做两件事：
（a）若某个区间可能排在最后，则它的 start <= H - p
（b）若某个区间可能排在最前，则它的 end >= 0 + p
本题三个区间完全对称，每个都可能排最后，所以
    start_i <= 30 - 5 = 25
而 end_i >= 0 + 5 = 5 本来就成立，没有新增信息。
```

**为什么它给不出 15？**

```text
「三个长 5 的任务放在同一条时间轴上至少占 15」是一个全局量（sum of processing
times 的推论）。它需要把「这三个区间不重叠」与「每个长度都是 5」两条信息合起来用。
两两互斥的局部推理做不到这点：对任意一对 (i, j)，能推出的只是
    start_j >= end_i 或 start_i >= end_j
而单看每一对，都存在「i 先、j 后」与「j 先、i 后」两种可能，
于是「谁排最后」在推理阶段是不确定的，上界只能停在 H - p = 25。
```

对照链的情况：链上「谁先谁后」是确定的（$O_0 \to O_1 \to O_2$），所以传播能把 3 段长度全扣掉。**信息够不够，决定传播能推多远。**

```text
结论：NoOverlap 给的是「这台机器上单个任务最晚什么时候开始」；
      链给的是「这条路径整段的累积约束」。
      两者都是对的，强度不同，来源是确定性的多少。
```

### 4.3 LP 松弛算的是什么

`milp_alt` 是 time-indexed 模型：$x_{jt} \in \{0,1\}$ 表示工序 $j$ 在 $t$ 时刻开始。把 $x_{jt} \in [0,1]$ 之后就得到 LP。

放宽的后果可以直观地说清：

```text
整数整数解：每道工序在每一时刻要么在加工、要么不在 —— 一个机器每个时刻最多一道
LP 解     ：允许一道工序「一半在加工」 —— 于是同一时刻可以塞进多道工序的小数份额
```

对 makespan 目标，这一放宽的后果比「丢掉不可抢占性」还严重一层：模型里「每道工序恰好选一个（机器，开工时刻）」是等式 $\sum_{m,t} y = 1$，$y$ 一取小数，同一道工序的归属就可以摊到多台机器与多个时刻上，于是 LP 不只允许抢占，还允许**一道工序同时出现在多台机器上**。实测后果见第 7 节：`parallel_8` 的 LP 值 25.0000 甚至低于「总加工时间 / 机器数」这个平凡下界 $\lceil 76/3 \rceil = 26$。机器不可抢占性正是并行机调度的核心约束，放掉它当然会松。

对 total_tardiness 目标，LP 的处境相反：交期惩罚是**分段线性凸函数**，time-indexed 建模里通常用「完工时刻的线性表达式 + 辅助变量」表示，这种结构与 LP 的对偶非常契合，紧得多。

第 7 节的实测把这层定性说法变成了数字：

```text
single_8     LP 83.9347 / 整数 85    LP gap 0.0125
single_12    LP 529.0987 / 整数 532  LP gap 0.0055
parallel_8   LP 25.0000 / 整数 29    LP gap 0.1379
parallel_12  LP 28.9645 / 整数 39    LP gap 0.2573
```

**同一个 MILP 范式、同一个实例生成器、同一个目标函数族，只换机器数与目标类型，LP gap 从 0.55% 变到 25.7%。** 这就是「界强度由结构决定，不由范式决定」的第二个证据。

## 6. 读法：什么时候该期待哪一边强

把机制映射成建模决策，得到一张可用的判据表：

| 实例特征 | 更该期待 | 机制原因 |
|---|---|---|
| 目标含交期惩罚（分段线性凸） | MILP 的界 | LP 对偶对这类成本结构一上来就很紧 |
| 机器互斥 / 选机是主导约束 | CP-SAT 的传播 | 区间互斥是域传播最擅长的形状 |
| 有限容量资源（`Cumulative`） | CP-SAT | `AddCumulative` 直接建成区间约束，无需 time-indexed 展开 |
| 需要「矛盾在搜索前被发现」 | CP-SAT | 传播阶段就能推爆域，不必进搜索树 |
| 变量数极大、结构规整 | MILP | LP 求解在大规模线性结构上是多项式时间 |
| 时间窗很紧（每个任务可选起点少） | 两边都好 | 紧时间窗同时收紧 CP 的域与 LP 的可行域 |

下面这三种判断是错的：

```text
错的：CP-SAT 是新一代，所以全面更强。
错的：MILP 有理论保证，所以更可靠。   ← 两者都只在有界/状态地说才有意义
错的：用 LP gap 就能预测 CP-SAT 的表现。 ← 实测里 CP 在 LP gap 大的实例上反而赢
```

最后一条尤其重要，第 7 节的实测直接给出了反例：`parallel_12` 的 LP gap 是 0.2573（四例中最大），而 CP-SAT 在这个实例上 0.0324 s 就证明了最优；`single_12` 的 LP gap 只有 0.0055（四例中最小），CP-SAT 却在 5 秒内没能证明。**LP gap 衡量的是 LP 松弛的紧度，与 CP 的推理能力无关。**

## 7. 实验：`m2w3d7_mechanisms`

对应脚本 [m2w3d7_mechanisms.py](../../projects/02_optimization_models/examples/m2w3d7_mechanisms.py)，在项目目录下运行：

```bash
python examples/m2w3d7_mechanisms.py
```

实例一律来自 `generate_instance`，CP-SAT 一律 `num_search_workers = 1`、`seed = 0`。实际输出：

```text
=== 1. CP 的传播：沿约束收紧 domain ===
  优先级链 end_k <= start_k+1，三道各 5，H = 30
    chain_start0     -> [0, 15]
    chain_end0       -> [5, 25]
    chain_start1     -> [5, 20]
    chain_end1       -> [10, 25]
    chain_start2     -> [10, 25]
    chain_end2       -> [15, 30]
  三个长 5 的区间 + 一条 NoOverlap，H = 30
    noov_start0      -> [0, 25]
    noov_end0        -> [5, 30]
    noov_start1      -> [0, 25]
    noov_end1        -> [5, 30]
    noov_start2      -> [0, 25]
    noov_end2        -> [5, 30]
  链把上界一路推下来：最后一道必须在 H - 3*5 = 15 前开始，前一道 20，第一道 25。
  NoOverlap 只能给出 H - 5 = 25：三者谁排最后没定，这就是它能给的最紧的界。
  机制差别：NoOverlap 的推理是「区间两两互斥」的局部推理，
  它不会去算「3 个长 5 的任务放在一台机器上至少要 15」这种全局量。
  注意：这里读到的是求解过程中的域，可能含搜索定值，适合定性观察传播。

=== 2. MILP 的松弛：一次 LP 就得到结构性下界（root_lp=True 实测）===
  实例           模型                 root LP      整数最优   LP gap       求解
  ------------------------------------------------------------------
  single_8     time_indexed       83.9347        85   0.0125   0.0174
  single_12    time_indexed      529.0987       532   0.0055   0.1003
  parallel_8   time_indexed       25.0000        29   0.1379   0.0134
  parallel_12  time_indexed       28.9645        39   0.2573   0.0546
  同一范式内部就能差很多：单机上 time-indexed 的 LP gap 不到 1%，
  并行机 makespan 上接近 26% —— 因为松弛把「机器不可抢占」这件事放掉了，
  整数解必须重新付这笔账。LP 值是可证明的下界，与预算无关。

=== 3. CP-SAT 的界来自搜索，不是来自一次松弛 ===
  同一实例 single_12（整数最优 532，上面实测的 root LP = 529.0987）：
    CP-SAT time_limit=0.05  状态 FEASIBLE  objective=643.0    bound=0        分支 1564
    CP-SAT time_limit=0.5   状态 FEASIBLE  objective=587.0    bound=0        分支 15397
    CP-SAT time_limit=5.0   状态 FEASIBLE  objective=532.0    bound=1        分支 82749
  观察：CP-SAT 的界随着搜索推进才慢慢抬起来，5 秒时仍接近平凡界 1；
  而 time-indexed MILP 的 LP 松弛在建模阶段就给出 529 这个下界。
  但这不是「MILP 更强」—— 换到 parallel_8 上方向就反了，实测：
    同一个 time-indexed MILP：LP 界 25.0000，证到最优 29 用了 0.8621 s
    cpsat_parallel        ：OPTIMAL，界 29，证到最优 29 只用了 0.0121 s
  LP 界弱的地方（并行机 makespan 丢掉了不可抢占性），CP 的区间推理正好强；
  反过来，交期惩罚那种线性成本结构，LP 的对偶界一上来就很紧，
  CP 侧反而要一点点搜。强弱是**建模结构**的函数。

=== 4. 分支机制与计数 ===
  2x2 JSP：OPTIMAL Cmax = 7，分支 5，冲突 0
  并行机 [3,3,2,2,2]/2：OPTIMAL Cmax = 6，分支 96，冲突 5
  容量不可行的实例：INFEASIBLE，分支 0，冲突 0
  差别在「决策变量是什么」：
    MILP 分支：把某个本来取小数的最优 LP 变量按 lb/ub 割成两支；
    CP-SAT 分支：在某个变量的 domain（集合）中间切一刀，
      并且把搜索中撞到的冲突记成 nogood，用冲突数衡量学到的信息量。
  上面的 INFEASIBLE 分支数与冲突数都是 0：矛盾在传播阶段就被发现，
  求解器根本没进搜索树 —— 这是 CP 侧最漂亮的一类推理，LP 松弛做不到。
```

### 7.1 观察

上面是**一次运行**的原始输出。重跑同一脚本时，会变的只有三类数：各处耗时（墙钟量）、分支数、以及 `time_limit=0.05` 那一档的目标值（另一次跑到过 `665.0`）；**四组端点域、四个 LP 值（83.9347 / 529.0987 / 25.0000 / 28.9645）、两个整数最优（29 与 532）与 `INFEASIBLE` 的 0 分支在两次运行里完全相同。**

八处观察：

1. **链的传播强度恰好等于「路径长度扣减法」**：`start0 <= 30 - 5 - 5 - 5 = 15`、`start1 <= 30 - 5 - 5 = 20`、`start2 <= 30 - 5 = 25`，与输出逐行一致。这说明在这条链上传播已经达到了该结构的理论最紧界。
2. **`NoOverlap` 停在 H - p = 25**：三个区间完全对称，「谁排最后」不确定，所以只能给每个区间一个共同的宽松上界。它给不出 15——那需要「三个长度都是 5」这个全局信息，而局部互斥推理用不上它。
3. **LP 松弛的 gap 在四个实例上差出 47 倍**：`single_12` 是 0.0055（0.55%），`parallel_12` 是 0.2573（25.73%）。**同一范式、同一建模方式、同一实例生成器**，只换了机器数与目标类型。
4. **`parallel_8` 的 LP 值甚至低于「总加工时间 / 机器数」这个平凡下界**：该实例是 8 道单工序的作业，加工时间 `[9, 16, 2, 14, 15, 2, 15, 3]`，总加工时间 76，3 台机器，于是「总量下界」为 $\lceil 76/3 \rceil = 26$、整数最优是 29 —— 而 LP 松弛给的是 **25.0000**，比 26 还低。原因是模型里「每道工序恰好选一个（机器，开工时刻）」是等式（$\sum_{m,t} y = 1$），在 LP 下 $y$ 可取小数，于是同一道工序的归属可以按小数摊到多台机器与多个时刻上，而每台机器每个时刻的容量约束（$\sum \le 1$）拦不住这种摊派。**这是 formulation 层面的松弛强度问题，不是求解器的问题**——同一个 `milp_alt` 在整数意义下能证明 29 是最优，说明模型本身是对的，只是它的 LP 松弛很松。
5. **CP-SAT 的界在 5 秒内几乎没动**：三档预算下界分别是 0 / 0 / 1，而目标值从 600 以上一路降到 532（已经是最优；`0.05` 秒那一档在多次运行间会波动，实测见过 643 与 665）。**「解的质量」与「界的质量」在这里完全脱钩**——搜索找解很有效，证明很无力。
6. **同一个实例上两边的下界来源完全不同**：LP 松弛给出 529.0987（一次算出，与预算无关），CP-SAT 5 秒后给出 1（逐次搜索，几乎平凡）。这两个数都是合法下界，但**只有 LP 那个是紧的**。
7. **`parallel_8` 上方向立刻反转**：LP 界 25.0000（离最优 29 有 4 的缺口），而 CP-SAT 0.0121 s 就证明了 29；同一个 MILP 证完花了 0.8621 s，是 CP-SAT 的 71 倍。**LP 界弱的地方正是 CP 传播强的地方。**
8. **不可行实例用 0 分支、0 冲突判死**：容量不可行的实例在传播阶段就把域推爆了，求解器根本没进搜索树。这是 LP 松弛做不到的一类推理——**LP 松弛是一次数值求解，它不会「发现矛盾」，只会给出一个数值**；矛盾要靠分支定界逐步逼近才能暴露。

### 7.2 把这些观察翻译成判据

```text
判据 1：先看目标结构。目标含交期惩罚这类分段线性凸成本 -> 优先 MILP。
判据 2：再看主导约束。机器互斥 / 选机 / 容量是主导 -> 优先 CP-SAT。
判据 3：可先用 LP gap 估「MILP 有多好走」，但**不要**用它预测 CP-SAT。
        实测里 LP gap 最大（0.2573）的实例上 CP-SAT 是赢的。
判据 4：如果实例有可能不可行，CP-SAT 的传播可能一步判死，值得先跑一次。
判据 5：真正的做法是两边都跑、都过同一个验证器、都在同一预算下报
        「状态 + 目标值 + 界」，而不是先验地选一边。       ← 这就是 Month 2 的收束
```

判据 3 与判据 4 都是今天的实测直接支持的，不是从教科书上抄的。

## 10. 自测题

不看上文回答：

- Q1：对约束 $x + p \le y$，传播会动哪些量？
- Q2：链与 `NoOverlap` 在同样三个长 5 的区间上给出的上界分别是多少？差在哪里？
- Q3：`NoOverlap` 为什么给不出「三个任务至少要 15」这个量？
- Q4：LP 松弛的下界与求解预算是什么关系？为什么？
- Q5：CP-SAT 的 `best_bound` 与求解预算是什么关系？为什么？
- Q6：`single_12` 上 LP 松弛给多少？CP-SAT 在 5 秒时给多少？
- Q7：四个实例的 LP gap 分别是多少？这说明了什么？
- Q8：MILP 分支与 CP-SAT 分支各在「切什么」？
- Q9：为什么不可行实例可以用 0 分支 0 冲突判死，而 LP 松弛做不到？
- Q10：LP gap 大是不是意味着 CP-SAT 会输？给一个实测反例。

### 参考答案

- A1：动 $x$ 的上界与 $y$ 的下界：$x$ 的上界被压到 $y$ 的上界减去 $p$，$y$ 的下界被抬到 $x$ 的下界加上 $p$。只动端点，不动域内部的取值。
- A2：链给出 15 / 20 / 25（按后序长度和扣减），`NoOverlap` 三个区间都只能给 25。差的 10 来自链的先后关系是确定的，而 `NoOverlap` 里「谁排最后」不确定。
- A3：因为它做的是「区间两两互斥」的局部推理。要得到「至少 15」，必须把三个区间的不重叠性与三个长度合起来做一次全局计算，局部推理拿不到这个信息。
- A4：与预算无关。LP 松弛是一次独立的线性规划求解，一次算完就是那个值；它只取决于模型形式与问题结构。
- A5：正相关但可能停在平凡附近。CP 的界是搜索过程中累加的推理结果，预算越大界可能越紧；但如果实例的 LP 结构对 CP 不友好（如交期惩罚），界可能一直在平凡界附近。
- A6：LP 松弛 529.0987，CP-SAT 5 秒时 `best_bound = 1`（而它已经找到了最优解 532）。
- A7：`single_8` 0.0125、`single_12` 0.0055、`parallel_8` 0.1379、`parallel_12` 0.2573。说明界强度由建模结构与问题结构决定，不由范式决定——同一范式内部就差了 47 倍。
- A8：MILP 在最优 LP 解里挑一个取小数的变量，按上下界割成两支；CP-SAT 在某个变量的域（一个集合）中间切一刀，并把搜索中撞到的冲突记成 nogood。
- A9：因为矛盾可以在传播阶段就被发现——某个变量的域被推空了，求解器在进搜索树之前就返回 INFEASIBLE。LP 松弛只是给一个数值，它不会主动去发现矛盾。
- A10：不是。实测反例是 `parallel_12`：LP gap 0.2573（四例中最大），而 CP-SAT 用 0.0324 s 证明了最优；反方向的例子是 `single_12`，LP gap 只有 0.0055（四例中最小），CP-SAT 却在 5 秒内没能证明。

## 11. 今日一句话总结

> **CP 的推理是「沿约束删掉变量域里不可能的取值」，所以链上能把上界一路推到 15/20/25、能在并行机上 0.0121 s 证明最优、能用 0 分支 0 冲突判死不可行；MILP 的推理是「放掉整数性求一次 LP 极值」，所以它能一次给出与预算无关的下界、在交期惩罚上把 gap 压到 0.55%，却在并行机 makespan 上掉到 25.73% —— 强弱是建模结构的函数，判据是「目标是线性成本结构还是机器互斥主导」，而不是范式的新旧。**
