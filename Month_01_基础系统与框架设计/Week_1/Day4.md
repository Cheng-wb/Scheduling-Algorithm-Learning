## 2. 为什么第 4 天要先做「规则」

前三天搭好了数据流水线：

```text
JSON → Parser → Instance → Validator → 可信输入
                                     ↓（今天开始）
                              Rules → Schedule → Objective → 数字
```

今天第一次在「可信输入」之后接上一个**真正产出排程**的模块。选择从经典规则开始，而不是一上来写 MILP 或元启发式，原因：

1. **规则是任何调度系统的最低基线**。以后所有更复杂算法（局部搜索、SA、CP-SAT、RL）都要和规则比；规则打不过，说明算法没意义。
2. **规则最容易被手算对拍**。规则逻辑简单、可推导，是建立「代码对不对」信心的最好起点。
3. **规则揭示「目标决定顺序」**这个 Day 1 埋下的核心观点：同一批 job，换成不同目标，最优顺序就不同。

一句话：**先把最容易验证、最不可能写错的基线做扎实。**

## 3. 四条经典规则总表

| 规则 | 全称 | 排序键（从小到大） | 最优于 | 直觉 |
|---|---|---|---|---|
| SPT | Shortest Processing Time | `p_j` | `1\|\|ΣCj` | 短任务先做，减少排队 |
| EDD | Earliest Due Date | `d_j` | `1\|\|Lmax` | 最紧急的交期先做 |
| WSPT | Weighted SPT（Smith 规则） | `p_j / w_j` | `1\|\|ΣwjCj` | 单位权重耗时越短越优先 |
| LPT | Longest Processing Time | `-p_j`（降序） | `P\|\|Cmax`（并行机） | 长任务先放，平衡并行机负载 |

注意三点：

- **WSPT 的排序键是比值** `p_j / w_j`，不是「w 大的先做」。权重的作用是「摊薄加工时间」：一个 `p=2,w=5` 的任务（比值 0.4）比 `p=1,w=1`（比值 1）更优先，尽管它加工时间更长。
- **LPT 在单机上几乎没有对应目标**。它真正的用武之地是**并行机** `P||Cmax` 列表调度（把长任务先分给负载最小的机器）。今天在单机上实现 LPT 只是把它当作「最长优先」基线，用来对照。
- 以上「最优」都只在**无释放时间、无额外约束**的标准单机模型下成立；一旦加 `rj`，见第 6、8 节。

---

## 4. 为什么「目标决定顺序」

沿用 Day 1 的一个结论：同样是三个 job，只改变目标，最优顺序就变。

```text
p = [1, 3, 8]

1||ΣCj 的最优顺序（SPT）：     1 → 3 → 8，C = [1, 4, 12]，ΣCj = 17
1||ΣwjCj（设 w = [1, 5, 1]）：
  比值 p/w = [1, 0.6, 8]，WSPT 顺序：3 → 1 → 8，C = [3, 4, 12]，ΣwjCj = 5*3 + 1*4 + 1*12 = 31
  （SPT 顺序下 ΣwjCj = 1*1 + 5*4 + 1*12 = 33 > 31，确实更差）
```

所以「排序规则」本质上是在回答：**面对当前可选的任务，哪一个先做对目标最有利？**

---

## 5. 释放时间 rj：从「静态排序」到「非延迟列表调度」

前四条规则在没有 rj 时，答案就是「把 job 排序一遍，从前往后加工」。因为有 rj 时，会出现一个新的问题：

> 机器已经空闲，但「最应该先做」的那个 job 还没到达。怎么办？

两个选择：

1. **空等**（deliberate idle）：等那个高优先级 job 到达再开工。
2. **先做已到达里最好的**（non-delay）：机器不空闲，从当前已释放的任务里挑最好的。

第 2 种就是 **non-delay（非延迟）列表调度**，也是大多数规则基线的默认策略：

> **只要有任务可用，机器绝不空闲。**

它的伪代码：

```text
t = 0
while 还有未排程的 job:
    在「rj <= t」的未排程 job 中，挑优先级最高的一个
    if 没有已释放的 job:
        t = 剩余 job 的最小 rj      # 空转等待
        continue
    start = max(t, rj)             # 不能早于释放时间开始
    排入该 job，t = start + p
```

关键点：**释放时间不是「修改优先级」，而是「限制可选集合」。** 规则只决定「在已释放的 job 里挑谁」，rj 决定「哪些 job 现在有资格被挑」。

## 6. 有 rj 后，规则为什么不再保证最优

这是今天最重要的理论认识。

`1|rj|ΣCj` 和 `1|rj|Lmax` 都是 **NP-hard**（无释放时间时 SPT/EDD 还最优，加了 rj 立刻变难）。因此有 rj 时，SPT/EDD/WSPT 都只是**启发式基线**，不保证最优。

更微妙的是：**non-delay 策略本身也可能不是最优的**。看这个反例：

```text
Job A：p = 100, r = 0
Job B：p = 1,   r = 1
目标 1|rj|ΣCj
```

- **non-delay SPT**：t=0 时只有 A 已释放 → 先做 A（0→100），再做 B（100→101）。`ΣCj = 100 + 101 = 201`。
- **故意空等**：t=0→1 空转，先做 B（1→2），再做 A（2→102）。`ΣCj = 2 + 102 = 104`，**好了近一倍**。

结论：

1. 有 rj 时，最优排程可能需要在机器空闲时**故意等待**一个即将到达的短任务。
2. 我们实现的 non-delay 列表调度是「不求最优、但求简单确定」的基线；它把「该不该空等」这个难题留给精确求解与元启发式方法去处理。
3. 记清楚这一点，能避免一个常见错误：**把规则基线在带 rj 实例上的结果当成最优解**。

（补充：若允许抢占 `pmtn`，`1|rj,pmtn|ΣCj` 又可以用 SRPT 精确求解，`1|rj,pmtn|Lmax` 用抢占 EDD；但本模型不支持抢占，只作延伸了解。）

## 7. 实现：`rules.py` 的设计

对应文件 [rules.py](../../projects/01_scheduling_core/scheduling_algorithms/rules.py)。

### 7.1 核心是「一个通用函数 + 四个薄包装」

```python
def list_schedule(instance, priority, *, machine_id=None) -> Schedule:
    # priority(job, op) -> 排序键，键越小优先级越高
```

四条规则只是给出不同的 `priority`：

```python
def spt(instance):   return list_schedule(instance, lambda j, o: o.processing_time)
def lpt(instance):   return list_schedule(instance, lambda j, o: -o.processing_time)
def edd(instance):   return list_schedule(instance, key_edd)      # 无交期排最后
def wspt(instance):  return list_schedule(instance, lambda j, o: Fraction(o.processing_time) / Fraction(j.weight))
```

这样「释放时间处理」「平局决胜」「Schedule 构造」只写一遍，规则差异被压缩成「排序键」这一个正交维度。这也符合 Day 2 约定的统一入口 `solve(instance) -> Schedule`。

### 7.2 排序键升序 = 优先级从高到低

约定「键越小越优先」，SPT/EDD/WSPT 天然如此；LPT 通过取负 `-p` 复用同一套升序逻辑，避免单独维护「降序」分支。

### 7.3 EDD 的「无交期」处理

`due_date=None` 的 job 没有交期，EDD 无法排序。约定：**放到最后**（对应 Day 2 第 18 节的要求）：

```python
def key_edd(job, op):
    if job.due_date is None:
        return (1, 0)        # 无交期 → 排在所有有交期之后
    return (0, job.due_date)  # 有交期 → 按交期升序
```

用元组 `(has_due, due_date)` 把「有/无交期」作为第一关键字，天然保证无交期的排最后，且无需引入 `inf`。

### 7.4 WSPT 用 `Fraction` 避免浮点误差

`p/w` 是比值，直接用 `float` 相除存在精度隐患（例如理论上相等的两个比值可能舍入后不等）。用标准库 `fractions.Fraction` 做**精确有理数比较**。注意 `Fraction(a, b)` 的两个参数都必须是有理数（int/Fraction），`weight` 是 float，所以要 `Fraction(op.processing_time) / Fraction(job.weight)`。

### 7.5 确定性的平局决胜

两条 job 优先级相同时，用 `job.id` 升序做次级决胜：

```python
ordered = sorted(tasks, key=lambda t: (priority(t[0], t[1]), t[0].id))
```

这让结果**与输入顺序无关、与运行次数无关**，是「可复现实验」的基本保障。

### 7.6 单机限定

单机规则要求「恰好一台机器、每个 Job 恰好一道工序」。不满足时 `list_schedule` 会抛出带说明的 `ValueError`，而不是静默地产生错误结果。多工序与并行机不在今天实现的范围。

## 8. 手算：实例 A（带释放时间）

用 Day 1 第 14 节的 5 个 job，作为本日连续性的对拍实例：

| Job | `pj` | `rj` | `dj` | `wj` |
|---|---:|---:|---:|---:|
| J1 | 6 | 0 | 12 | 1 |
| J2 | 2 | 0 | 8 | 3 |
| J3 | 4 | 3 | 15 | 1 |
| J4 | 3 | 5 | 10 | 2 |
| J5 | 7 | 0 | 20 | 1 |

总加工量 `Σpj = 6+2+4+3+7 = 22`，所以无论什么顺序 `Cmax = 22`。

### 8.1 SPT（p 升序）

静态排序：J2(2), J4(3), J3(4), J1(6), J5(7)。用 non-delay 贪心逐步推：

```text
t=0   已释放 {J1,J2,J5}，其中最短是 J2 → J2: 0-2
t=2   已释放 {J1,J5}（J3 r3、J4 r5 未到）→ J1: 2-8
t=8   已释放 {J5,J3,J4}，最短是 J4 → J4: 8-11
t=11  已释放 {J5,J3}，最短是 J3 → J3: 11-15
t=15  J5: 15-22
```

顺序 **J2 → J1 → J4 → J3 → J5**，完工时间 `C = [8, 2, 15, 11, 22]`。

```text
ΣCj   = 8 + 2 + 15 + 11 + 22 = 58
ΣTj   = max(0,8-12)+max(0,2-8)+max(0,15-15)+max(0,11-10)+max(0,22-20) = 0+0+0+1+2 = 3
ΣwjCj = 1*8 + 3*2 + 1*15 + 2*11 + 1*22 = 8+6+15+22+22 = 73
```

注意：**J2 先于 J4** 是因为 J4 在 t=5 才释放，机器在 t=2 已经空了，non-delay 不会为它空等，而是做已释放里最短的 J1。

### 8.2 LPT（p 降序）

静态排序：J5(7), J1(6), J3(4), J4(3), J2(2)。

```text
t=0  已释放 {J1,J2,J5}，最长 J5 → J5: 0-7
t=7  已释放 {J1,J2,J3,J4}，最长 J1 → J1: 7-13
t=13 剩余 {J2,J3,J4}，最长 J3 → J3: 13-17
t=17 剩余 {J2,J4}，最长 J4 → J4: 17-20
t=20 J2: 20-22
```

顺序 **J5 → J1 → J3 → J4 → J2**，`C = [13, 22, 17, 20, 7]`。

```text
ΣCj   = 13+22+17+20+7 = 79
ΣTj   = 1+14+2+10+0 = 27
ΣwjCj = 1*13+3*22+1*17+2*20+1*7 = 13+66+17+40+7 = 143
```

### 8.3 对比

| 规则 | 顺序 | Cmax | ΣCj | ΣTj | ΣwjCj |
|---|---|---|---|---|---|
| SPT | J2,J1,J4,J3,J5 | 22 | **58** | **3** | **73** |
| LPT | J5,J1,J3,J4,J2 | 22 | 79 | 27 | 143 |

单机上 LPT 在 ΣCj / ΣTj / ΣwjCj 上全面输给 SPT——符合预期，因为 LPT 本就不是为单机这些目标设计的。

## 9. 手算：实例 B（无释放时间，展示规则差异）

为了看清四条规则的**本质差异**，用一组 `rj = 0` 的数据，让顺序差异「纯净地」来自目标：

| Job | `pj` | `dj` | `wj` |
|---|---:|---:|---:|
| J1 | 4 | 6 | 1 |
| J2 | 1 | 12 | 5 |
| J3 | 3 | 8 | 2 |
| J4 | 2 | 3 | 1 |

无 rj 时，排序就是最终顺序。逐一推导四条规则：

**SPT**（p 升序）：J2(1), J4(2), J3(3), J1(4) → `C = [10, 1, 6, 3]`

```text
ΣCj = 10+1+6+3 = 20；ΣwjCj = 1*10+5*1+2*6+1*3 = 30
Lmax：L1=4, L2=-11, L3=-2, L4=0 → 4；ΣTj = 4+0+0+0 = 4
```

**EDD**（d 升序）：J4(3), J1(6), J3(8), J2(12) → `C = [6, 10, 9, 2]`

```text
ΣCj = 27；ΣwjCj = 76
Lmax：L1=0, L2=-2, L3=1, L4=-1 → 1；ΣTj = 1
```

**WSPT**（p/w 升序）：比值 J1=4, J2=0.2, J3=1.5, J4=2 → J2, J3, J4, J1 → `C = [10, 1, 4, 6]`

```text
ΣCj = 21；ΣwjCj = 1*10+5*1+2*4+1*6 = 29
Lmax：L1=4, L2=-11, L3=-4, L4=3 → 4；ΣTj = 4+0+0+3 = 7
```

**LPT**（p 降序）：J1, J3, J4, J2 → `C = [4, 10, 7, 9]`

```text
ΣCj = 30；ΣwjCj = 77
Lmax：L1=-2, L2=-2, L3=-1, L4=6 → 6；ΣTj = 6
```

### 对比表

| 规则 | 顺序 | ΣCj | ΣwjCj | Lmax | ΣTj |
|---|---|---|---|---|---|
| SPT | J2,J4,J3,J1 | **20** | 30 | 4 | 4 |
| EDD | J4,J1,J3,J2 | 27 | 76 | **1** | **1** |
| WSPT | J2,J3,J4,J1 | 21 | **29** | 4 | 7 |
| LPT | J1,J3,J4,J2 | 30 | 77 | 6 | 6 |

每个规则**恰好在自己对应的目标上最优**：

- SPT → ΣCj 最小（20）✓
- WSPT → ΣwjCj 最小（29）✓
- EDD → Lmax 最小（1）✓

这正是「目标决定顺序」的最直观证据，也是「为什么不能只靠一个规则打天下」的原因。

## 10. 规则适用条件与失效反例（务必记清）

| 规则 | 保证最优的前提 | 失效场景 |
|---|---|---|
| SPT | `1\|\|ΣCj`（无 rj、无权重） | 有 rj 时（NP-hard）；目标换成 ΣwjCj 时也不保证 |
| EDD | `1\|\|Lmax`（无 rj） | 有 rj 时；对 ΣTj 只是启发式（ΣTj 单机即 NP-hard） |
| WSPT | `1\|\|ΣwjCj`（无 rj） | 有 rj 时；权重为 0 或负时无意义（输入已校验 weight>0） |
| LPT | `P\|\|Cmax` 的列表调度（并行机） | 单机上对 ΣCj/ΣTj/ΣwjCj 都很差 |

记忆要点：**任何「无 rj 时最优」的结论，加了 rj 大概率就不再最优**；而「规则」的价值在于它简单、确定、可解释，作为基线永远有用。

- A1：SPT → `1||ΣCj`；EDD → `1||Lmax`；WSPT → `1||ΣwjCj`。
- A2：`p/w` 升序（等价于 `w/p` 降序）。
- A3：NP-hard，SPT 不再保证最优。
- A4：只要机器空闲且存在已释放任务就立即加工（绝不空等）。它是启发式基线，不是最优。
- A5：A(p=100, r=0)、B(p=1, r=1)：non-delay 得 ΣCj=201，故意空等到 1 得 104。
- A6：排到最后（用 `(has_due, due_date)` 元组实现）。
- A7：保证结果确定、与输入顺序和运行次数无关；用 job.id 升序。
- A8：因为单机上先做长任务会拖长所有后续任务的完工时间；LPT 的正途是**并行机** `P||Cmax` 列表调度。
- A9：Lmax 取最大（可为负），ΣTj 是非负求和；前者衡量「最糟的一次延迟」，后者衡量「总迟交量」。
- A10：先按优先级排好全序，每步只在 `rj <= t` 的 job 中挑优先级最高的那个。

## 15. 今日一句话总结

> **优先级规则把「目标」翻译成「排序键」，释放时间把「静态排序」变成「动态选择」；SPT/EDD/WSPT/LPT 是四条永远要打、也永远要先打对的基线。**
