## 2. 为什么今天要做一条独立的第三条路径

到这里已经有两条能给出排程的路径了：

```text
Day 2  解码器（decode / dispatch）    从 (指派, 顺序) 或派工规则构造排程
Day 4  CP-SAT                        在它自己的模型上求解并证明
```

问题在于：**这两条路径都可能有 bug**。如果拿它们互相检查，「两个都错」也会「对得上」——
它们共享同一套对问题的理解（同一个数据模型、同一个目标函数），错法很可能是一致的。

所以今天要做的是第三条路径：**自己枚举、自己构造、自己跟踪机器占用**，
只共用 `fjsp_core` 里那两类「不是被检验对象」的东西：

```text
共用：数据模型、目标函数 evaluate、独立验证器 validate_schedule
不共用：解码器（fjsp_shop.fjsp）、CP-SAT（fjsp_shop.cpsat_fjsp）
```

它在工程上的作用是给**小实例**发一张最优值证书。有了它，
`fjsp_cpsat` 报出的 `OPTIMAL` 就有了第二个证人 —— 但代价是空间，
这个证人只覆盖「个位数工序」那一档，而且它自己也要说清「在什么条件下它的话才算数」。

## 3. 概念：空间、拓扑序与证书的边界

### 3.1 搜索空间公式

`FJSP` 的完整决策由两部分组成，空间是两者的乘积：

```text
空间 = Π_o |合格机器_o|   x   (拓扑序个数)
       └── 指派组合数 ──┘       └── 顺序组合数 ──┘
```

四个实例的读数：

| 实例 | 工序数 | 每道工序的合格机器数 | 指派组合 | 拓扑序 | 空间 |
|---|---|---|---|---|---|
| `tiny_2x2` | `4` | `2` | `16` | `6` | `96` |
| `gap_2x2` | `4` | `2` | `16` | `6` | `96` |
| `assign_2x3` | `4` | `3` | `81` | `6` | `486` |
| `jsp_fixed_2x2` | `4` | `1` | `1` | `6` | `6` |

两个因子都值得单独看：

- **指派组合 = `Π_o |合格机器_o|`**：每道工序独立地在自己的合格机器里挑一台，
  所以是乘积。`assign_2x3` 上是 `3^4 = 81`，`jsp_fixed_2x2` 上是 `1^4 = 1`
  （每道工序只有一台机器，「选机」这一维退化了）。
- **拓扑序个数 = `n! / Π_j k_j!`**：`4` 道工序、两个订单各 `2` 道时是 `24 / (2 x 2) = 6`。
  分母的 `k_j!` 是每个订单内部的工序重排数 —— 那些排列违反工艺路线，不在枚举范围里。

### 3.2 为什么顺序只能枚举拓扑序

解码时每道工序的开工下界是「同订单前道工序的完工时刻」。**如果顺序不是拓扑序**，
后道工序会被放到前道之前，工艺路线给的先后约束就被绕过了。产出的是非法排程，
而它常常给出一个比真最优更小的假值。本日第 7 节会用可复现的实例把这件事量出来。

这类数字如果被当成「最优值」，得到的结论会连带把方法排名、算法选择全部带偏：
它比真最优**小**，所以任何与它比较的方法都显得「更差」，而真正的最优反而被当成次优。

### 3.3 oracle 的三段流程

```text
1. 先查（_reject_unsupported）：目标可证明吗？实例里有本模块没有建模的约束吗？空间超限吗？
2. 再枚举：对每个指派组合 x 每个拓扑序，用**自己的**插入式构造一个排程
3. 最后复核：只在「出现改进」时调用独立验证器，保证最终返回的那个排程一定合法
```

第 1 步必须在最前面：它的代价是常数级，而第 2 步的代价是空间大小级的。
更要紧的是**语义**：如果算完了才说「算的其实是另一个更松问题」，调用方可能已经把结果写进报告了。

第 3 步只对改进点复核，是一个刻意的取舍：复核每一次构造会让代价成倍上升，
而复核每一个改进点已经足以保证**最终返回的排程**是合法的。
如果构造逻辑有错，第一次改进就会在验证器那里炸掉，而不是悄悄返回一个错值。

### 3.4 它能证明什么、不能证明什么

这一段是今天最重要的纪律。oracle 的证书有明确的边界：

| 输入 | 行为 | 原因 |
|---|---|---|
| `objective = "makespan"`，纯 `FJSP` + 释放时间 | 给出**最优值证书** | 主动排程族含最优 `makespan` 排程（第 4.4 节的定理） |
| 目标不是 `makespan` | **拒绝** | 本模块只为 `makespan` 搭建并核对了证书 |
| 实例含本模块没有建模的约束 | **拒绝** | 枚举出来的是「另一个更松问题的最优值」 |
| 空间 `> limit` | **拒绝** | 不能算一部分，再把一部分叫「最优」 |

```text
拒绝一律抛 ValueError，并且绝不返回「受限枚举的最好值」冒充最优。
```

表里第二行的理由是一件必须说准的事：它说的是**本模块的覆盖范围**，
不是「别的目标在数学上做不到」。判断哪些目标可以证，靠的是第 4.4 节那条定理
对目标函数的要求；而**敢不敢发证书**，还要加上「这一族构造与复核有没有为它写过、测过」。
两件事叠在一起，本模块才把范围收在 `makespan` 这一格上：收得保守，但每一条发出去的证书都站得住。

`limit` 判的是空间，不是实例的规模。`486` 与 `485` 之间没有别的东西 ——
空间是 `486` 就拒绝，是 `486` 以下就放行。它不抽样、不近似、
也不「先给一个数再补一句说明」。

## 4. 推导：空间公式与主动排程族定理

### 4.1 拓扑序个数为什么是 `n! / Π_j k_j!`

把 `n` 个工序位置排成一行，然后往里面**分配**：先决定订单 `J0` 的 `k_0` 道工序占哪些位置，
有 `C(n, k_0)` 种选法；它们在那几个位置上只有**一种**合法相对次序（必须按工艺路线）。
再给 `J1` 从剩下的位置里选 `C(n - k_0, k_1)` 种，依此类推：

```text
C(n, k_0) x C(n - k_0, k_1) x ... = n! / (k_0! x k_1! x ...)
```

`4` 道工序、两个订单各 `2` 道：`C(4,2) x C(2,2) = 6 x 1 = 6`。
`6` 道工序、两个订单各 `3` 道：`C(6,3) x C(3,3) = 20 x 1 = 20`。

这条公式是**算出来**的，不是枚举出来的 —— 所以「先查空间」这一步不需要先构造任何东西，
代价可以忽略。这是第 1 步能放在最前面的前提。

### 4.2 空间为什么是乘积

指派的每一组取值都配得上顺序的每一个取值：先给每道工序定机器，再给全部工序定一个拓扑序，
两者互不干涉（机器资格只看工序自己，先后顺序只看订单内的链）。没有哪一组指派会排除哪一个顺序，
所以组合数是乘积 `Π_o |合格机器_o| x (拓扑序个数)`。

### 4.3 插入式构造出来的排程是主动的

先把「主动」说清：**一个排程是主动的，指的是不存在「可以在不推迟任何其他工序的前提下提前」的工序**。

插入式构造的排程满足这个条件，理由是每道工序的开工时刻都被三个来源之一**顶住**：

```text
start(op) = max( 释放时间, 同订单前道工序的完工时刻, 该机器上排在它前面的占用区间的结束时刻 )
```

第三个来源在构造时是「该机器上紧挨着这道工序的那个区间」。工序一旦放下就不会再被动，
后面插入的工序只会填别的空隙，不会把它顶住的那一段挪走。于是任何提前的尝试都会与
那个顶住它的区间（或前道工序、或释放时间）冲突 —— 也就是要以推迟别人为代价。

### 4.4 主动排程族定理

```text
给定任何一张可行排程，反复做「把某道工序提前，前提是不推迟任何其他工序」这件事，
直到再也提前不动：过程一定终止（每次提前都让某个开工时刻严格变小，而时刻是整数且有下界），
结束时得到的排程是主动的，而且**每道工序的完工时刻都不大于原排程**。
```

> **理论结论（主动排程族定理）**：若目标函数是**正则**的 —— 也就是「任何一道工序的完工时刻
> 变大，目标值都不会变小」—— 那么主动排程族里一定含有一个最优排程。
> 论证就是上面那段：把任意一个最优排程左移到主动，正则性保证目标值没有变差，于是左移后的
> 主动排程也是最优的。`makespan` 显然是正则的：任何一道工序推迟，`max` 只会更大或不变。

这条定理说明的是**族**的性质：只要枚举的那一族包含主动排程族，就不会丢掉 `makespan` 的最优解。
而第 4.3 节说清了本模块的插入式构造产出的正是主动排程 —— 两者合起来，
才是「oracle 给出的 `makespan` 是最优值」这句话的完整依据。

> **纪律**：定理只保证「族里有最优解」，不保证「本模块一定发得出证书」。
> 发证书还要加上「这一族的构造与复核为那个目标写过、测过」。
> 本模块两件事都只对 `makespan` 做过，所以第 3.4 节的第二行把别的目标名一律挡在枚举之前。

## 5. 手算：四个实例的空间与 `limit` 分界

**`tiny_2x2`**（`4` 道工序、每道 `2` 台合格机器、两个订单各 `2` 道工序）：

```text
指派组合 = 2 x 2 x 2 x 2 = 16
拓扑序   = 4! / (2! x 2!) = 24 / 4 = 6
空间     = 16 x 6 = 96
```

**`assign_2x3`**（`4` 道工序、每道 `3` 台合格机器）：

```text
指派组合 = 3 x 3 x 3 x 3 = 81
拓扑序   = 6（工艺路线的形状没变）
空间     = 81 x 6 = 486
```

**`jsp_fixed_2x2`**（每道工序只有一台机器）：

```text
指派组合 = 1 x 1 x 1 x 1 = 1     <- 「选机」这一维整个退化了
空间     = 1 x 6 = 6
```

**`fjsp_6x4_f2`**（`18` 道工序 = `6` 个订单各 `3` 道、每道 `2` 台合格机器）：

```text
指派组合 = 2^18 = 262144
拓扑序   = 18! / (3!^6) = 137225088000
空间     = 262144 x 137225088000 = 35972733468672000
```

`limit` 的默认值是 `200000`：上面最后一个数字是它的 `1.8 x 10^11` 倍。
所以这个 oracle 的射程不是「工序数少」，而是「空间小」——`18` 道工序的生成实例就已经算不动了。

**`limit` 分界**（判据是 `space > limit`，即「严格大于」才拒绝）：

```text
assign_2x3 的空间 = 486
limit = 485 -> 486 > 485 成立 -> 拒绝
limit = 486 -> 486 > 486 不成立 -> 放行
```

**四个最优值里有三个可以不完全靠穷举就定下来**：

```text
tiny_2x2       下界 = max(max_o min_m p_om, ceil(Σ_o min_m p_om / |M|))
               = max(1, ceil(4 / 2)) = max(1, 2) = 2，与穷举值 2 相等     -> 下界碰上界
jsp_fixed_2x2  O00 与 O11 都只能在 M0 上做，工时 3 + 4 = 7
               -> M0 的负载 7 是下界；而 [0,3) 与 [3,7) 就能排开        -> 最优值就是 7
gap_2x2        订单 J1 的两道工序串行：O10 最快 8 分钟（在 M1）、O11 最快 2 分钟（在 M0）
               -> 完工时刻至少 8 + 2 = 10；而 10 又排得出来              -> 最优值就是 10
```

这三条手算与第 7 节的枚举读数互相印证：一条是「下界碰上界」，两条是「串行链给出下界、构造给出上界」。
`assign_2x3` 的 `10` 没有这么短的手算证明（脚本里那条朴素下界只有 `5`），
它只能靠枚举拿到 —— 这正是 oracle 存在的意义。

## 6. 实现：三段流程与两处独立实现

代码在 [oracle.py](../../projects/03_industrial_fjsp/fjsp_shop/oracle.py)。三个公开函数：

```python
topological_order_count(instance) -> int          # n! / Π_j (k_j!)
enumeration_space(instance) -> int                # Π_o |合格机器_o| x 拓扑序个数
exhaustive_optimum(instance, objective="makespan", limit=200_000) -> tuple[float, Schedule]
```

`topological_order_count` 用阶乘与整数除法算，**不枚举**：
这也是为什么「先查空间」这一步的代价可以忽略 —— 它不需要先构造出任何东西。

拓扑序的生成用的是**递归走法**，不是「先取全部 `n!` 个排列再过滤」：

```text
每一步：候选 = 每个订单剩下的第一道未排工序（这些工序的前道一定都排过了）
        对每个候选递归，走完就是恰好一个拓扑序
```

走法生成的是「合法顺序」的集合本身，所以既不会产生非法排列，也不会有过滤的浪费。
`4` 道工序两个订单各 `2` 道时它生成 `6` 个。

`_build` 是 oracle 自己的构造器：它维护 `job_ready[job]` 与每台机器的占用区间表，
用 `_earliest_fit(intervals, earliest, minutes)` 找最早放得下的空隙。
这个函数与 `fjsp.py` 里的同名思路**各写一份**，不共享代码：

| 共享的东西 | 不共享的东西 |
|---|---|
| `fjsp_core` 的数据模型、`evaluate`、`validate_schedule` | 空档查找 `_earliest_fit`、插入式构造 |
| 「什么叫一个合法排程」的定义 | 「拒绝哪些输入」的判断（`_reject_unsupported` 与同一道闸门在 `fjsp.py` 里各写一份） |

连拒绝判断都各写一份是刻意的：如果 oracle 调用 `fjsp.py` 的闸门，
那么 `fjsp.py` 对「哪些约束需要拒绝」的理解错了，oracle 会用同一种错法跟着错，
两者照样「对得上」。**独立性是一条链：只要有一个环节共用，那个环节的错就检不出来。**

在项目目录 `projects/03_industrial_fjsp` 下运行：

实际输出（原样粘贴）：

```text
=== 穷举 oracle：与解码器、CP-SAT 都独立的第三条计算路径 ===

== 1. 搜索空间 ==
  空间 = Π_o |合格机器_o|  x  (拓扑序个数)
  拓扑序个数 = n! / Π_j (k_j!)，不是 n! —— n! 里有一大半违反了工艺路线。

  实例          工序  指派组合  拓扑序  空间
  tiny_2x2         4        16       6     96
  gap_2x2          4        16       6     96
  assign_2x3       4        81       6    486

  tiny_2x2      optimum = 2.0    LB = 2
    O00@M0[0,1)  O10@M1[0,1)  O01@M0[1,2)  O11@M1[1,2)

  gap_2x2       optimum = 10.0   LB = 8
    O00@M0[0,2)  O10@M1[0,8)  O01@M0[2,5)  O11@M0[8,10)
  assign_2x3    optimum = 10.0   LB = 5
    O00@M0[0,3)  O10@M2[0,6)  O01@M0[3,8)  O11@M1[6,10)
  tiny_2x2 的 optimum 2.0 就等于它的下界，
  这个实例的最优性**不靠穷举**也能证明（下界碰上界）；穷举在这里的作用是验证「下界==上界」这条推理没错。

== 3. 三方对拍（oracle / CP-SAT / 三个启发式）==
  实例           oracle  cpsat(状态)    random  shortest  loadbalance
  tiny_2x2           2      2(OPTIMAL )       7       2       2
  jsp_fixed_2x2      7      7(OPTIMAL )       7       7       7
  gap_2x2           10     10(OPTIMAL )      15      10      10
  assign_2x3        10     10(OPTIMAL )      14      11      13
  oracle 与 CP-SAT 在最优点上一致，启发式各自落后或追平 —— 两条独立路径互证。

== 4. 可复现的反例：顺序为什么只能枚举拓扑序 ==
  实例工时（2 订单 x 2 工序，2 机器）：
    工序  M0  M1
    O00   1   9
    O01   4   1
    O10   2   7
    O11   7   2
  枚举全部 4! = 24 个排列（不检查工艺路线）：最好值 = 4
    顺序 = ('O00', 'O11', 'O01', 'O10')
    排程 = O00@M0[0,1)  O11@M1[0,2)  O10@M0[2,4)  O01@M1[2,3)
    独立验证器报错 = ['precedence: O10 -> O11']
  只枚举拓扑序（oracle 的做法）：最优值 = 5
    排程 = O00@M0[0,1)  O10@M0[1,3)  O01@M1[1,2)  O11@M1[3,5)
  后道工序 O11 被排到了前道工序 O10 之前 —— 工艺路线给的先后约束被绕过，
  于是枚举拿到一个比真最优（5）更小的假值（4）。
  受限枚举绝不能冒充最优：所以 oracle 只走拓扑序，
  并且在每个改进点上都调用独立验证器复核。
```

### 7.1 怎么读这段输出

**第 1 节的四行可以逐个手算核对。** 拿 `assign_2x3` 做例子：`3^4 = 81`、
拓扑序 `6`、空间 `486`，三个数都在第 5 节里手算过。
把 `limit` 定成 `200000` 时，**`18` 道工序的生成实例**就已经算不动了（`3.59727e+16`）——
也就是说这个 oracle 的射程只到「个位数工序」这一档。

**第 2 节给出了四个最优值，其中三个值得停一下。**

- `tiny_2x2` 的 `optimum = 2` 与 `LB = 2` 相等：这个实例的最优性**不需要穷举**也能证明
  （下界碰上界）。穷举在这里的价值是反过来的：它验证了「下界 == 上界」这条推理本身没错。
- `jsp_fixed_2x2` 的 `optimum = 7` 而 `LB = 6`：朴素下界差 `1`，所以这个 `7` 不靠下界证明；
  但它有第 5 节那条手算的独立依据（`O00` 与 `O11` 都只能在 M0 上做，`3 + 4 = 7`）。
- `gap_2x2` 的 `optimum = 10` 而 `LB = 8`：同样不靠下界，靠的是「两级串行链 `8 + 2 = 10`」那条手算。
- `assign_2x3` 的 `optimum = 10` 而 `LB = 5`：下界松了一半，最优值只能靠枚举拿到。
  这个 `10` 也回答了 Day 1 留下的问题 —— 当时只知道「`81` 个指派配上 ECT 派工」最好到 `10`，
  现在知道整个实例的最优值就是 `10`，所以那一步没有漏掉任何东西。

**第 3 节是三方对拍，重点在表头那一列的状态。** `oracle` 与 `cpsat` 四行全部相等，
而这一致是**两条独立路径**给出的一致：一条穷举、一条建模求解。
三个启发式则在不同实例上落后或追平（`tiny_2x2` 上 `shortest`、`loadbalance` 都追平了 `2`；
`jsp_fixed_2x2` 上三个启发式全部追平 `7` —— 退化实例上大家都能做对）。

**第 4 节是今天唯一一段「把错误留着」的内容。** 它故意实现了一个**不做拓扑检查**的
构造函数，然后枚举全部 `24` 个排列，拿到 `4`；独立验证器对这个排程报
`precedence: O10 -> O11`，而只枚举拓扑序得到的是 `5`。
`4 < 5` 这一处的方向很关键：非法枚举给出的不是「保守的上界」，
而是一个**更小、更诱人、更错**的数字。一个只看数字不看合法性的流程会直接采纳它。

**第 5 节把拒绝拆成三处，每一处都在算之前发生。**

- `fjsp_6x4_f2` 的空间是 `3.59727e+16`：这一行说明「射程」不是由工序数决定的，
  而是由空间决定的。
- `limit = 485` 拒绝、`486` 放行：闸门判的是空间与 `limit` 的大小关系，没有别的花样。
  输出里「`485` 与 `486` 之间没有别的东西」这句话就是为这一点写的。
- 「实例里有本模块没有建模的约束」这一类拒绝只写了一句说明，没有给例子 ——
  原因是**举一个这种实例，就要把那些约束的名字写出来，而它们不在今天的讨论范围内**。
  想知道这条闸门挡下的是什么，只要看 `_reject_unsupported` 里读的是实例的哪些字段。
  `tests/test_week2.py` 里有一条用例专门构造这种实例，验证拒绝确实发生。
- 「目标不是 `makespan`」的拒绝消息说的是**本模块的证书边界**：构造与复核都为 `makespan` 写过、
  测过，别的目标名一律在枚举之前拒绝。这不是关于别的目标能不能证的数学结论（第 4.4 节）。
- 最后一段是**反例的边界**：释放时间**不在**拒绝清单里。
  把 `J1` 的释放时间改成 `3` 之后，oracle 仍然给证书：`optimum = 5`，
  时间线里 `O10@M1[3,4)`。释放时间进了 `earliest` 的下界，结论依然成立。

**第 6 节是独立性的机械证据。** `from fjsp_shop ... import` 的行数为 `0`：
被对拍的两条路径，它一条都没碰。这一节不是装饰 —— 如果 oracle 复用了 `decode`，
那么「oracle 与解码器一致」就退化成「解码器与自己一致」。

## 10. 自测题

- Q1：搜索空间的两个因子分别是什么？为什么它们相乘而不是相加？
- Q2：`assign_2x3` 的空间是 `486`。如果把它的一道工序的合格机器从 `3` 台改成 `2` 台，空间变成多少？
- Q3：`jsp_fixed_2x2` 每道工序只有一台合格机器，空间是 `6`。这说明「选机」这一维退化之后，`FJSP` 退化成了什么？
- Q4：全排列枚举在反例实例上给出 `4`，而真最优是 `5`。为什么这个 `4` 不能当成「更好的解」报出去？
- Q5：主动排程族定理要求目标是**正则**的（任何一道工序的完工时刻变大，目标值不会变小）。`makespan` 为什么是正则的？
- Q6：oracle 为什么不复用 `fjsp.py` 的空档查找函数？复用它能省下一份代码，代价是什么？
- Q7：`limit` 判的是空间而不是工序数。这两者为什么会不一致？请各举一个例子。
- Q8：`exhaustive_optimum` 在「出现改进」时才调用 `validate_schedule`。如果某次改进后的排程不合法，会发生什么？
- Q9：第 7 节第 2 段里 `jsp_fixed_2x2` 的 `optimum = 7` 而 `LB = 6`。这个 `7` 是怎么被证明的？还有哪条不依赖穷举的证据？
- Q10：oracle 拒绝「目标不是 `makespan`」而不是「算完再报另一个目标值」。如果它选择后者，会给出什么样的错误结论？

### 参考答案

- A1：两个因子是「指派组合数 `Π_o |合格机器_o|`」与「拓扑序个数 `n! / Π_j k_j!`」。
  相乘是因为这两维是**独立选择**的：任何一组指派都可以配上任何一个拓扑序，
  组合起来就是一个完整的决策（`(assignment, order)`），没有哪一组被另一组排除。
  相加会漏掉「一半指派配另一半顺序」这种组合。
- A2：`2 x 3 x 3 x 3 = 54` 个指派组合，乘上拓扑序 `6`，空间是 `324`。
  注意这个改动同时也会改实例的最优值，所以空间变化与最优值变化是两件事。
- A3：退化成 `JSP`（车间作业调度）：只剩「每台机器上的先后顺序」这一维，
  空间就只剩拓扑序个数 `6`。这也是 `jsp_fixed_2x2` 这个实例存在的意义 ——
  它是 `FJSP` 代码在退化输入上的回归测试。
- A4：因为它**不合法**：验证器对这个排程报 `precedence: O10 -> O11`，
  后道工序被排到了前道之前。在车间里这意味着「零件还没加工就先装配」。
  把它当成「更好的解」报出去，等于用一个不存在的排程去回答一个真实的问题；
  而且它比真最优还小，会让人得出「问题比实际更容易」的错误结论。
- A5：正则目标指「任何一道工序的完工时刻变大，目标值都不会变小」。`makespan` 是全部工序
  完工时刻的最大值，把其中任何一个变大，`max` 只会更大或不变 —— 所以它是正则的。
  这条性质正是左移论证的最后一步所需要的：左移不会让任何完工时刻变大，
  正则性于是保证左移后的目标值不会变大。
- A6：省下一份代码的代价是**丢掉独立性**：如果 `fjsp.py` 的空档查找有一个「只在某些
  空隙形状上出错」的 bug，复用它的 oracle 会用同一种错法构造排程，于是「oracle 与解码器
  一致」这条证据就完全失效了 —— 它变成了「解码器与自己一致」。各写一份，
  两种实现同时错在同一个地方的概率远低于其中一种出错。
- A7：空间是「工序数」与「每道工序的灵活度」的乘积，两者可以独立变化。
  例一：`jsp_fixed_2x2` 有 `4` 道工序但空间只有 `6`（每道工序 `1` 台机器）。
  例二：`fjsp_6x4_f2` 有 `18` 道工序、每道 `2` 台机器，空间是 `3.59727e+16`；
  如果把它的机器数加一倍、工序数不变，工序数没变而空间会显著变大。
  判闸门只能判空间。
- A8：`validate_schedule` 会抛异常，整个 `exhaustive_optimum` 调用失败。
  这正是所要的：宁可当场炸掉，也不返回一个「看起来有值、其实不合法」的证书。
  反过来说，这个设计也保证了**只要它正常返回，返回的那个排程一定是合法的**
  （因为它是最后一个改进点，而每个改进点都验过）。
- A9：靠枚举，而不是靠下界。`LB = 6` 与 `optimum = 7` 不相等，下界什么也证明不了；
  是穷举了全部 `6` 个组合、每个组合都过了独立验证器，才敢说 `7` 是最优值。
  不依赖穷举的证据是第 5 节那条手算：`O00` 与 `O11` 都只能在 `M0` 上做，
  `M0` 的负载 `3 + 4 = 7` 就是下界，而 `[0, 3)` 与 `[3, 7)` 一条时间线就达到了它。
  这也是「穷举的证书」与「下界碰上界」两条路的不同之处：后者要靠运气（下界得刚好紧），
  前者只要空间装得下就一定给得出。
- A10：它会给出一个**为 `makespan` 找出来的解**的拖期读数。这个数有两个问题：
  第一，它是一个为别的目标找出来的排程，本模块没有为那个目标核对过任何东西；
  第二，报告读者看到「`total_tardiness = X`」会以为这是一个为拖期优化的结果。
  两个问题叠在一起，就是一个「目标名与实际优化对象不一致」的结论 ——
  宁可拒绝，也不要给这种结论。

## 11. 今日一句话总结

> **oracle 用「`Π_o |合格机器_o| × 拓扑序个数`」这个乘积当搜索空间，在 `96 / 486 / 6` 这类小实例上穷举出可以当证书的最优值（`2 / 10 / 7`），而它的全部价值建立在两条边界上：只枚举拓扑序（全排列会给出比真最优更小的假值 `4`，而真最优是 `5`），以及只证明它敢证明的东西（非 `makespan` 目标、本模块没有建模的约束、空间超过 `limit`，一律在枚举之前拒绝）。**
