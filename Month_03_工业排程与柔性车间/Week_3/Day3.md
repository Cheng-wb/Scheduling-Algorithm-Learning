## 2. 为什么必须归一化

Day 2 的 `(1, 1, 1)` 看起来最「公平」：三个分量一样重要。但把它展开：

```text
f = 1 · Cmax + 1 · ΣT + 1 · setup
```

这个式子在算术上没毛病，在业务上却偷偷做了一个极强的声明：

```text
1 分钟的完工时间  =  1 分钟的迟交  =  1 分钟的换型
```

三个量确实都写「分钟」，但它们是**三种不同的分钟**：

```text
Cmax   排程长度    —— 产线占用到什么时候
ΣT     迟交量      —— 客户承诺被违反了多少
setup  换型耗时    —— 机器与人工花在切换上的时间
```

而且数值尺度差得远：实例 `T` 上三个分量各自的最好值是 `9`、`2`、`1`。
`setup` 的整个取值范围只有 `1` 到 `9`，而 `ΣT` 可以到几十。
在这样的尺度下，原始加权和实际上由**数值最大的那个分量**说话——
把 `setup` 的权重从 1 调到 2，往往什么也改变不了。

**归一化的目的就是抹掉这个隐含声明**：让三个分量各自除以一个「参照值」，
使权重只表达**偏好**，不再兼职表达**尺度**。

## 3. 定义：口径、分母、两种加权和

**定义（归一化口径 `normalization`）**：三个分母 `d_cmax`、`d_ΣT`、`d_setup > 0`
与模式 `mode` 一起构成一组口径。加权和随之分成两层：

```text
原始加权和      = α·Cmax + β·ΣT + γ·setup
归一化加权和    = α·Cmax/d_cmax + β·ΣT/d_ΣT + γ·setup/d_setup
```

**理论结论 1（求解器最小化的是归一化加权和）**：`fjsp_cpsat_multiobj` 把后者
乘 `OBJ_SCALE = 1_000_000` 取整后交给 CP-SAT；`result.objective` 报的是**前者**
（由 `objective_breakdown` 从排程反算）。两者可以排序不同——这正是口径的作用。

**定义（三种口径）**：

| 口径 | 分母 | 来源 | 代价 |
|---|---|---|---|
| `none` | `(1, 1, 1)` | 不归一化 | 尺度由分量自身决定 |
| `trivial` | 三个平凡上界 | `trivial_bounds(instance)`，**不求解**就能算 | 分母很松，权重差一点看不出差别 |
| `ideal` | 三个单目标最优值 | 调用方先解三个单目标模型再传进来 | 要多解三个模型；最小值可能是 0 |

**理论结论 2（`trivial` 分母是上界、`ideal` 是下界）**：`trivial` 的三个分母都是
可行解的上界，所以归一化后的分量落进 `[0, 1]`；`ideal` 的三个分母是下界（最优值），
所以归一化后的分量落在 `[1, +∞)`。这两句话都能在下面第 7 节的表里直接看出来。

**理论结论 3（归一化只改交换率）**：把 `ΣT` 的系数除以 `d_ΣT`、`Cmax` 的系数除以 `d_cmax`，
等价于把「1 单位 `ΣT`」的定价改成 `d_cmax / d_ΣT` 单位 `Cmax`。所以
**口径真正决定的是两个分量之间的交换率**，其余什么都没变。

## 4. 推导：翻转点就是分母之比

设两条候选排程在 `Cmax` 上差 `ΔCmax = Cmax_R - Cmax_L`、在 `ΣT` 上差
`ΔΣT = ΣT_R - ΣT_L`（R 比 L 多花的 `Cmax`，换回来的迟交差额）。归一化后两条的
加权和相等给出：

```text
α·Cmax_L/d_cmax + β·ΣT_L/d_ΣT = α·Cmax_R/d_cmax + β·ΣT_R/d_ΣT
β · ΔΣT / d_ΣT = α · ΔCmax / d_cmax
β/α = (ΔCmax / d_cmax) / (ΔΣT / d_ΣT)
```

**理论结论 4（`ΔCmax = -ΔΣT` 时翻转点等于分母之比）**：实例 `T` 的两条候选排程
恰好 `ΔCmax = +7`、`ΔΣT = -7`（大小相等、符号相反），两者约掉之后

```text
β* = d_ΣT / d_cmax
   取 α = 1、γ = 0 时：翻转点 = 分母之比
```

这就是「**分母之比就是这两个目标的交换率**」的来历。它给出一个立刻可检验的预测：

```text
口径        d_cmax  d_ΣT    β* = d_ΣT/d_cmax
none             1     1    1.0000
trivial         50   115    2.3000
ideal            9     2    0.2222
```

三个 `β*` 相差十倍以上。于是 `β = 0.25` 这个权重：

```text
none 口径：0.25 < 1.0000  ->  还没到翻转点，选 S1
ideal 口径：0.25 > 0.2222 ->  已经翻过去了，选 S2
```

**同一个 `β`，换了口径就换了排程。**这不是数值噪声，是两组分母在说两件事。

## 5. 手算：三组分母从哪来

### 5.1 `trivial` 的三个分母

`trivial_bounds` 只看实例的静态数据，不求解：

```text
d_cmax = max r_j + Σ_o max_m p_om + max_setup × 工序数 + 1
       = 0 + (6 + 2 + 5 + 4) + 8 × 4 + 1
       = 0 + 17 + 32 + 1 = 50

d_ΣT   = Σ_j max(0, d_cmax - d_j)
       = max(0, 50-100) + max(0, 50-1) + max(0, 50-4) + max(0, 50-30)
       = 0 + 49 + 46 + 20 = 115

d_setup = max_setup × 工序数 = 8 × 4 = 32
```

三处都值得盯着看：

- `d_cmax = 50` 是「完全串行 + 最晚窗末端」的完工时间，很松——真实最优值是 `9`；
- `d_ΣT = 115` 利用了 `C_j <= Cmax`，每个订单的迟交最多是 `d_cmax - d_j`；
- `d_setup = 32` 是「每道工序前都换一次型」的极端，真实最优值是 `1`。

三个分母都远大于真实最优值，**这正是刻意的**：它们保证「不求解也能算出分母」，
于是 `fjsp_cpsat_multiobj` 的建模阶段与「另解三个单目标模型」完全解耦。

### 5.2 `ideal` 的三个分母

`ideal` 用三个单目标的最优值作分母，必须先解三个模型：

```text
min Cmax  = 9   （M0: A[0,6) B[7,9)；M1: C[0,5) D[6,8)）
min ΣT    = 2   （M0: B[0,2) A[10,16)；M1: C[0,5) D[6,8)）
min setup = 1   （M0: A[0,6) D[7,11) B[11,13)；M1: C[0,5)）
```

它们的排序是 `9 > 2 > 1`，所以 `ideal` 口径隐含的定价是

```text
1 单位 ΣT   值  d_cmax / d_ΣT = 9/2 = 4.5 单位 Cmax
1 单位 setup 值  d_cmax / d_setup = 9/1 = 9  单位 Cmax
```

也就是说：`ideal` 口径下「省 1 分钟换型」被定价成「省 9 分钟完工时间」。
这个定价**不是业务给的，是实例给的**——它只是三个最优值之间的比例。
这一点常被说成「理想点归一化最客观」，其实它只是换了一个隐含假设，并没有取消假设。

### 5.3 三个 `β*` 的手算

```text
none     : d_ΣT / d_cmax = 1 / 1       = 1.0000
trivial  : d_ΣT / d_cmax = 115 / 50    = 2.3000
ideal    : d_ΣT / d_cmax = 2 / 9       = 0.2222
```

与第 7 节的求解器行为对照：`β = 0 / 0.25 / 4` 三点在 `none`、`trivial` 下给出
`S1 / S1 / S2`，在 `ideal` 下给出 `S1 / S2 / S2`——三行都与 `β*` 的位置一致。

### 5.4 `ideal` 口径下的等权选择

`(α, β, γ) = (1, 1, 1)` 在三种口径下：

```text
口径       Cmax   ΣT  setup    归一化加权和     排程
none          9     9      2      20.0000      (9, 9, 2)
trivial       9     9      2       0.3208      (9, 9, 2)
ideal        13     9      1       6.9444      (13, 9, 1)
```

`ideal` 换成了 `(13, 9, 1)`。手算这一处的得失：

```text
从 (9, 9, 2) 换到 (13, 9, 1)：
  Cmax  +4   ->  归一化代价 4/9  = 0.4444
  setup -1   ->  归一化收益 1/1  = 1.0000
  净变化      = 0.4444 - 1.0000 = -0.5556  （更小，所以更优）
```

而在 `none` 口径下同样的换法是 `+4 - 1 = +3 > 0`，**不划算**。
两边的算术都没有错，差别只在「1 分钟换型值几分钟完工时间」这个定价：
`none` 说是 1，`ideal` 说是 9。

## 6. 实现：口径是怎么被解析和使用的

口径解析在 [industrial.py](../../projects/03_industrial_fjsp/fjsp_shop/industrial.py) 的
`resolve_normalization`：

```python
raw = spec.get("normalization") or {}
mode = str(raw.get("mode", "trivial"))
if mode == "none":
    return Normalization("none", {"cmax": 1.0, "total_tardiness": 1.0, "setup": 1.0})
if mode == "ideal":
    divisors: dict[str, float] = {}
    for key in ("cmax", "total_tardiness", "setup"):
        value = float(raw.get(key, 0.0))
        if value <= 0:
            raise ValueError(
                f'normalization mode "ideal" requires a positive {key!r} ideal value'
            )
        divisors[key] = value
    return Normalization("ideal", divisors)
if mode == "trivial":
    return Normalization("trivial", trivial_bounds(instance))
```

三处纪律：

1. **默认口径是 `trivial`**，不是 `none`。原始单位相加的隐含假设太强，不该当默认值。
2. **`ideal` 的分母必须由调用方传进来**。算它要另解三个单目标模型，
   那是驱动脚本的职责，求解器不该偷偷做。
3. **分母必须为正**。`ideal` 模式下某个分量最优值为 0 时直接报错，
   而不是用一个「差不多」的数顶替——这是理想点归一化的固有边界，见第 7.3 节。

系数换算在 `Normalization.scaled`，返回 `(α', β', γ', exact)`：

```python
scaled_value = raw[key] * OBJ_SCALE / self.divisors[key]
rounded = int(round(scaled_value))
if abs(scaled_value - rounded) > 1e-6:
    exact = False
```

`exact` 是这里的关键位。它只在 **`mode = none` 且三个系数都没被舍入**时为 `True`，
此时模型目标恰好是 `OBJ_SCALE × 原始加权和`，下界可以精确换算回原始单位。
归一化之后这条通道断了：求解器证明的是**归一化**加权和，
它对原始单位的加权和**不构成下界**。于是：

```text
best_bound = None（不是 0、不是目标值）
status     = FEASIBLE（从 OPTIMAL 降级）
detail["model_status"]                = 求解器的原话（可能仍是 OPTIMAL）
detail["optimality_scope"]            = "normalized weighted sum (not the reported objective)"
```

这条纪律在 `artifacts/month3_w3/report.md` 里可以直接看到：
`tiny_tradeoff` 的 `trivial`、`ideal` 两节，`状态` 列全是 `FEASIBLE`，
而`模型状态` 列全是 `OPTIMAL`；`none` 一节两列都是 `OPTIMAL`。
**两列一起看才是完整信息**：模型确实被证明最优了，但被证明最优的那个函数
不是报告里那一列。

### 7.1 这张输出里值得逐行看的四处

**第一处：`none` 口径下「原始加权和」与「归一化加权和」两列完全相同
（`9.00` / `9.0000`）。** 因为三个分母都是 1。这是个自检位：
如果这两列在 `none` 口径下不相等，说明分母或在别处被动了手脚。

**第二处：`trivial` 口径下的归一化值全部落进 `[0, 1]`**（`0.1800`、`0.1996`、
`0.3896`、`0.3208`）。这正是第 3 节的理论结论 2：分母是**上界**，
所以分量除以它之后不超过 1。数值偏小说明分母很松——`Cmax = 9` 除以 `50`
只有 `0.18`，而这个实例里 `Cmax` 的整个取值范围其实只有 `9` 到 `16`。

**第三处：`ideal` 口径下的归一化值全部 `>= 1`**（`1.0000`、`2.0278`、`5.7778`、
`6.9444`）。分母是**下界**（最优值），所以分量除以它之后不小于 1。
注意 `1.0000` 只出现在「该分量单独最优」的排程上——`cmax_only` 那一行的
`Cmax` 恰好等于 `9`，`setup_only` 那一行（在另一张表里）的 `setup` 恰好等于 `1`。

**第四处：`tardiness_light` 这一行在三种口径下的三个排程。**
`none` / `trivial` 给 `S1 = (9, 9, 2)`，`ideal` 给 `S2 = (16, 2, 9)`。
一行数据、同一个权重、同一个求解器，只换了分母——
**这就是「归一化不是技术细节，而是业务定价」的可执行证据**。

### 7.2 本日实验的三条结论

1. **分母之比就是交换率**：`β* = 1.0000 / 2.3000 / 0.2222`，与手算
   `1/1`、`115/50`、`2/9` 逐位一致；三行的「预测 vs 观察」都是「一致」。
2. **口径会改变选择**：`β = 0.25` 在 `none`、`trivial` 下选 S1，在 `ideal` 下选 S2；
   等权 `(1, 1, 1)` 在 `none`、`trivial` 下选 `(9, 9, 2)`，在 `ideal` 下选 `(13, 9, 1)`。
3. **`ideal` 的定价来自实例、不来自业务**：`d_cmax/d_ΣT = 9/2`、`d_cmax/d_setup = 9/1`
   都是三个最优值之间的比例。想用业务定价，就得显式传自己的分母，
   或者干脆用 `none` 并把权重设成业务给的交换率。

### 7.3 驱动的产物与一个真实边界

上面这些表不是只存在于终端里。`fjsp_experiments.weight_sensitivity.run(output)`
把它们落成四个文件，`output` 目录非空时**直接拒绝**，防止覆盖旧结果：

```text
artifacts/month3_w3/results.csv      36 行 = 2 实例 × 3 口径 × 6 组权重（21 列）
artifacts/month3_w3/metadata.json    实例、口径、设置、时间预算、源码哈希
artifacts/month3_w3/report.md        人读的表 + 每组口径的说明
artifacts/month3_w3/schedules.json   每行的完整排程（report 里只放指纹）
```

`results.csv` 里有一个字段值得单独说：`validation` 列恒为 `ok`——
每一行的排程都过了独立验证器 `validate_schedule`，不是「模型说它行」。

另有一个 5 订单的实例 `plant_batch` 也被跑过，它暴露了理想点归一化的固有边界：
`min setup = 0`（存在不需要任何换型的排程），于是 `d_setup = 0`，`ideal` 口径**不可用**。
驱动没有用一个「差不多」的正数顶替，而是把那一整列标成 `SKIPPED`。
两类「不可用」必须分开看：

```text
分成 0       理想点归一化的固有边界：分量能压到 0，分母就没了
没证明最优    只是时间预算不够，换更长的预算就能修好
```

前者是方法的边界，后者是工程的欠账。把它们混成一句「这一格坏了」，
就丢掉了「该换方法还是该加时间」这个决策信息。

## 10. 自测题

- Q1：`Cmax`、`ΣT`、`setup` 都是分钟，为什么不能直接相加？
- Q2：`none` 口径下「原始加权和」与「归一化加权和」两列为什么完全相同？
- Q3：`trivial` 口径下归一化值为什么不超过 1？`ideal` 口径下为什么不小于 1？
- Q4：`ideal` 口径下「1 分钟换型」被定价成多少分钟完工时间？这个定价是谁给的？
- Q5：两个口径下同一个 `β = 0.25` 选出不同排程。能不能说其中一个是错的？
- Q6：为什么 `resolve_normalization` 在 `ideal` 模式下拒绝 `<= 0` 的分母？
- Q7：`exact = False` 时 `best_bound` 为什么必须是 `None`，而不是照抄求解器的界？
- Q8：`trivial` 分母很松，会让权重区分不出差别。这是缺点，为什么还把它设成默认口径？
- Q9：如果一个实例的三个单目标最优值是 `(9, 0, 1)`，`ideal` 口径能直接用吗？
- Q10：想用业务给的交换率（比如「1 分钟迟交 = 3 分钟完工时间」）建模，
  应该用哪个口径、权重怎么设？

### 参考答案

- A1：因为它们是**三种不同的分钟**：排程长度、迟交量、换型耗时。
  直接相加等于额外声明「1 分钟完工时间 = 1 分钟迟交 = 1 分钟换型」，
  而这三件事在业务上的定价几乎不可能相等。它们的数值尺度也差得远
  （实例 `T` 上是 `9`、`2`、`1`），尺度大的分量会主导加权和。
- A2：因为 `none` 的三个分母都是 `1`，除以 1 不改变数值。
  这也可以当自检位：如果这两列在 `none` 下不相等，说明分母被动了手脚。
- A3：`trivial` 的三个分母都是可行解的**上界**，分量除以上界不超过 1；
  `ideal` 的三个分母是**下界**（各自的最优值），分量除以下界不小于 1。
  两句话只需要「上界/下界」的定义，不需要求解器行为。
- A4：`d_cmax / d_setup = 9/1 = 9` 分钟完工时间。这个定价由三个单目标最优值
  之间的比例决定，**是实例给的，不是业务给的**。想用业务定价，
  就得显式传自己的分母，或者用 `none` 口径并把权重设成业务给的交换率。
- A5：不能。两条排程在两个不同的目标函数下各自最优，两个判断都成立。
  差异来自分母在说两件不同的事（定价 1 vs 定价 4.5），不是求解器不稳定。
  要说谁「对」，先得回答「1 分钟迟交值多少分钟完工时间」这个业务问题。
- A6：因为理想点归一化的分母就是「该分量能取到的最小值」。它等于 0 时
  「除以它」没有定义，任何用正数顶替的做法都是在**悄悄改定价**。
  报错并让调用方决定，比塞一个「差不多」的数更诚实。
- A7：因为 `exact = False` 时求解器证明的是**归一化**加权和的最优性，
  它对原始单位的加权和不构成下界。照抄那个界会得到一个比真实下界
  **更大**的数（甚至超过真实最优值），从而谎称「已经证明到这个程度了」。
  与其报一个不能解释的数，不如报 `None`。
- A8：因为它的分母**不需要求解**就能算出来，代价是松。这个取舍是有意的：
  它让 `fjsp_cpsat_multiobj` 的建模阶段与「另解三个单目标模型」解耦，
  默认调用不需要事先做三轮求解。想要紧的分母就显式传 `ideal`。
- A9：不能。`ΣT` 的最优值是 0，分母为 0，`resolve_normalization` 会直接报错。
  这正是 `plant_batch` 上 `setup` 分量遇到的情形（`min setup = 0`），
  驱动把那一整列标成 `SKIPPED` 而不是用别的分母顶替。
- A10：用 `none` 口径，把权重设成业务交换率本身，例如 `α = 1`、`β = 3`
  （1 分钟迟交值 3 分钟完工时间）。`ideal` 口径的定价由实例决定，
  改不了；`none` 口径的权重就是原始单位的交换率，可以直接填业务给的数。

## 11. 今日一句话总结

> **归一化不是技术细节，而是业务定价**：三个分量都用分钟计，却**不是同一种分钟**；
> `none`/`trivial`/`ideal` 三种口径给出分母 `(1,1,1)`、`(50,115,32)`、`(9,2,1)`，
> 于是翻转点 `β* = d_ΣT / d_cmax = 1.0000 / 2.3000 / 0.2222`——同一个 `β = 0.25`
> 在前两种口径下选 `S1 = (9, 9, 2)`，在 `ideal` 下选 `S2 = (16, 2, 9)`；
> 归一化之后 `best_bound` 只能是 `None`、`status` 降级成 `FEASIBLE`，
> 因为被证明最优的那个函数已经不是报告里那一列。
