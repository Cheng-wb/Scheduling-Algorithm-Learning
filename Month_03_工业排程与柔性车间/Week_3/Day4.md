# Day 4：sequence-dependent setup

> 当日主题：换型时间不是工序的固有属性，它挂在**同一台机器上相邻两道工序**之间，且依赖两者的 `family` 组合；它既不是工时也不是等待，而是排程里一段**必须留出来的间隔**

## 2. 为什么换型要单独拿出来

Day 2 与 Day 3 里，`setup` 一直是加权和里的第三个分量。今天要问的是：
**这个分量到底怎么进模型？**

先看它和工时的区别。工时 `p_om` 是工序的固有属性——`A` 在 `M0` 上就是 2 分钟，
与别的工序无关。换型不是：

```text
A 在 M0 上加工 2 分钟            —— 与谁在它前后无关
A 与 B 之间的换型 3 分钟          —— 只在 A 与 B **相邻**时才发生
A 与 C 之间的换型 3 分钟          —— 若 B 夹在中间，这 3 分钟根本不存在
```

所以换型挂在**相邻关系**上，而不是挂在工序上。它也不属于任何一道工序：
不能算进 `A` 的工时（`A` 单独加工不需要换型），也不能算进 `B` 的工时
（`B` 的前一道换成 `C` 时可能不需要换型）。

排程里插在两道工序之间的间隔因此有三类：

```text
等待      机器闲着等前道工序的释放时间或交货节奏 —— 由约束决定，可为零
换型      机器在切换族，不能加工               —— 由顺序决定，同族为零
空转      机器的可用时间之外（日历、维护）       —— 由车间决定，与顺序无关
```

今天只看中间那一类。

## 3. 定义：族、换型矩阵、sequence-dependent setup

**定义（`family`）**：每道工序带一个族标记（`Operation.family`），
表示它需要什么样的装夹/程序/物料。

**定义（换型矩阵）**：`Setup(from_family, to_family, minutes)` 给出「从族 `A` 切到族 `B`
要花多少分钟」。矩阵**不对称**：`G1` 里 `F0 -> F1` 是 3 分钟，`F1 -> F0` 是 4 分钟。
这种不对称在真实车间里很常见（拆一套夹具与装一套夹具的耗时不一样）。

**定义（`sequence-dependent setup`）**：同一台机器上按加工顺序排列的工序序列
`o_1, o_2, …, o_k`，其换型总时间是

```text
setup(序列) = Σ_{i=1}^{k-1} Setup(family(o_i), family(o_{i+1}))
```

即**只累加相邻对**。同族相邻时该项为 0。

**理论结论 1（换型是零和的机器时间）**：换型的每一分钟都占用机器，
且与工序一样会被 `AddNoOverlap` 之类的约束管住。它不是「顺便做掉的事」。

**理论结论 2（未定义的换型方向不是 0）**：换型矩阵缺项时，`Setup` 查表会抛 `KeyError`。
模型对这种情况的处理是**禁止该相邻关系**（不建那条弧），而不是按 0 处理。
否则模型可能给出一个「只需要 0 分钟换型」的排程，而验证器会报错——
模型与验证器对同一个实例给出两种说法，是最难查的一类不一致。

**实验观察 1**：`G1` 的求解结果里 `detail["setup_encoding"]` 报的是
`immediate-predecessor circuit arcs`。下面第 6 节说明它为什么必须是「紧前弧」。

## 4. 推导：两条必须记住的结论

### 4.1 单机恒等式 `Cmax = Σp + Σsetup`

单台机器上，工序时间总和 `Σp` 是常数（不管什么顺序，都要加工这么多分钟），
换型时间只会在它之上**追加**。所以

```text
Cmax = Σp + Σsetup          （单机、无释放时间、无日历）
```

**理论结论 3**：由这条恒等式立刻得到——在单机上，`min Cmax` 与 `min setup`
**永远选同一个顺序**，两个目标同向，不构成取舍。想让换型真正改变决策，
必须有多台机器可选（`X` 可以走 `M0` 或 `M1`），或者有别的会占用时间的约束。

这条恒等式还是一个**手算校验位**：把 `Σp` 与 `Σsetup` 加起来，
必须等于模型报的 `Cmax`。第 7 节的实验里 `6 + 3 = 9` 正好对上。

### 4.2 为什么必须是「相邻对」

设顺序是 `A, C, B`。正确的换型是 `A -> C` 与 `C -> B` 两段：

```text
相邻对（正确）      = Setup(F0, F1) + Setup(F1, F1) = 3 + 0 = 3
```

如果偷懒写成「所有前后对」：

```text
任意前后对（错）    = Setup(F0,F1) + Setup(F0,F1) + Setup(F1,F1)
                    = A->C 3  +  A->B 3  +  C->B 0
                    = 6
```

多出来的 3 分钟是 `A -> B`：`A` 与 `B` 在顺序上确实一前一后，但**它们不相邻**，
中间隔着 `C`，机器从来没有从 `F0` 直接切到 `F1` 这件事。

**理论结论 4（成对编码必然高估）**：`Σ_{a≠b} x[a,b]·Setup(a,b)`（`x[a,b]` 表示
「`a` 早于 `b`」）在两个以上工序的链上一定**高估**总换型，
高估量恰好是所有「不相邻的前后对」的换型之和。后果不是「稍微不准」，而是
**模型优化的东西与 `objective_breakdown` 报告的东西不是同一个函数**——
两套数对不上，验收表就没法读了。

所以换型项必须落在**紧前关系**上。第 6 节会看到，`AddCircuit` 天然提供这种关系。

### 4.3 手算判据：换型省不省，要看它换回了什么

`G2` 上两个目标选出不同的机器位置。假设两条排程的成本是

```text
方案 P：Cmax = 100，setup = 5
方案 Q：Cmax = 101，setup = 0
```

要判优劣就得回答：**1 分钟换型值多少分钟完工时间**？

```text
方案 P 更好  <=>  α·100 + γ·5  <  α·101 + γ·0
             <=>  γ·5 < α·1
             <=>  γ/α < 1/5 = 0.2
```

所以 `γ/α < 0.2` 时选 P，`> 0.2` 时选 Q，恰好 `= 0.2` 时两者等值。
这个数只能由业务回答，算法答不了。**这就是 `γ` 必须由业务来定的原因**：
它是「1 分钟换型值几分钟完工时间」的报价。

## 5. 手算：`G1` 的六种顺序、`G2` 的两条排程

### 5.1 `G1` 全部枚举

```text
工序    机器    工时    族
A      M0     2     F0
B      M0     2     F1
C      M0     2     F1
换型：F0 -> F1 = 3；F1 -> F0 = 4；同族 = 0
```

三道工序、一台机器，只有 6 种顺序。`Σp = 6` 恒定，所以 `Cmax = 6 + setup`：

```text
顺序     相邻对                      setup    Cmax
A,B,C   F0->F1 = 3, F1->F1 = 0         3       9
A,C,B   F0->F1 = 3, F1->F1 = 0         3       9
B,A,C   F1->F0 = 4, F0->F1 = 3         7      13
B,C,A   F1->F1 = 0, F1->F0 = 4         4      10
C,A,B   F1->F0 = 4, F0->F1 = 3         7      13
C,B,A   F1->F1 = 0, F1->F0 = 4         4      10
```

**最优值是 `setup = 3`，有两条顺序达到它**：`A,B,C` 与 `A,C,B`。
两条的共同点是把 `A` 放在最前面——`A` 是唯一一个 `F0`，
放在最前面只需付一次 `F0 -> F1`（3 分钟），放在中间或最后就要付
一次 `F1 -> F0`（4 分钟）外加一次 `F0 -> F1`（3 分钟）。

**这是今天第二个「目标值相等、排程不唯一」的场合**（第一个是 Day 2 第 4.3 节的 `β = 1`）。
求解器返回的是 `A,C,B`：`M0 AA...CCBB`。手算的 `A,B,C` 同样拿 3，
两条都对。第 7 节的实验把求解器实际返回的那一条逐对拆开核算。

### 5.2 `G2` 的两条排程

```text
工序    可上机器(工时)          族
A      M0(100)             F0
B      M1(1)               F1
X      M0(1) 或 M1(1)      F0
换型：F0 -> F1 = 5；F1 -> F0 = 5（对称）
```

`X` 是唯一有选择的工序，两种放法：

```text
X 走 M1：M1 上 B[0,1) 换型5 X[6,7)；M0 上 A[0,100) 独占
        Cmax = max(100, 7) = 100     setup = 5 （B 是 F1，X 是 F0）

X 走 M0：M0 上 X[0,1) 同族 A[1,101)（X 与 A 都是 F0，换型 0）；M1 上 B[0,1) 独占
        Cmax = max(101, 1) = 101     setup = 0
```

两条排程的三个分量：

```text
方案     Cmax    ΣT   setup    X 在哪
P        100      0       5    M1
Q        101      0       0    M0
```

`ΣT` 都是 0（`G2` 没有交期），所以取舍只发生在 `Cmax` 与 `setup` 之间，
按第 4.3 节算的判据，翻转点在 `γ/α = 0.2`。

## 6. 实现：紧前弧、自环、以及「缺项即禁止」

换型编码在 [industrial.py](../../projects/03_industrial_fjsp/fjsp_shop/industrial.py)
的 `_add_machine_circuits`：

```python
for a, _ in members:
    for b, _ in members:
        if a.id == b.id:
            continue
        minutes = _setup_minutes(instance, a, b)
        if minutes is None:
            continue  # 换型矩阵缺项 -> 禁止这一相邻关系
        arcs.append(
            (machine_id, a.id, b.id, arc_literal(index_of[a.id], index_of[b.id]), minutes)
        )
model.AddCircuit(circuit)

for arc_machine, from_id, to_id, literal, minutes in arcs:
    if arc_machine != machine_id:
        continue
    # 换型间隔：紧前工序完工 + setup <= 后道工序开工（minutes = 0 时退化为不重叠）
    model.Add(start[to_id] >= end[from_id] + minutes).OnlyEnforceIf(literal)
```

四件事要看清：

1. **每台机器一条 circuit**。节点 `0` 是哑元（机器的起点与终点），
   节点 `1..k` 是可在这台机器上加工的工序。弧 `a -> b` 的语义是
   「`a` **紧接在** `b` 之前」。`AddCircuit` 保证每个节点恰好一条出弧、一条入弧，
   于是「顺序」这件事由一个置换而不是一堆先后字面量表达。
2. **自环表达「不在这台机器上」**。工序若没被分到这台机器（它的 `presence` 为假），
   就走自己的自环。于是 `流入(b) = 1 - 自环(b) = presence(b)` 自然成立，
   **不需要额外的流平衡约束**。哑元的自环 `machidle` 表达「这台机器完全不用」。
3. **换型间隔就是一条不等式**：`start[to] >= end[from] + minutes`，
   只在对应的弧被选中时生效。`minutes = 0`（同族）时它退化成普通的不重叠约束——
   同族换型不是「不约束」，而是「约束变成了不许重叠」。
4. **缺项即禁止**。换型矩阵缺项时那条弧根本不建。这样任何返回的排程都不会触发
   验证器的 `setup undefined`；如果禁止之后无解，那是模型如实报告的 `INFEASIBLE`，
   不是隐藏的建模缺口。

`objective_breakdown` 那边的 `total_setup_time` 也是按**相邻**对累加的，
两套数用的是同一条定义——这正是第 4.2 节那条纪律的落地。

## 7. 实验：`m3w3d4_setup_gaps`

脚本：[m3w3d4_setup_gaps.py](../../projects/03_industrial_fjsp/examples/m3w3d4_setup_gaps.py)。

在项目目录 `projects/03_industrial_fjsp` 下运行：

```bash
python examples/m3w3d4_setup_gaps.py
```

实际输出（原样粘贴）：

```text
== G1：单机、两族、换型 F0->F1 = 3、F1->F0 = 4 ==
status=OPTIMAL  objective(setup)=3  breakdown={'cmax': 9.0, 'total_tardiness': 0.0, 'setup': 3.0}
建模方式：immediate-predecessor circuit arcs

时间线（首字母 = 工序，'.' = 间隔）：
  M0 AA...CCBB   (0 -> 9)

第几对     前一道       后一道       族变化               间隔
1       A         C         F0 -> F1           3
2       C         B         F1 -> F1           0
相邻对合计 = 3（求解器报的也是这个数）

== 为什么不能用「任意前后对」代替「相邻对」 ==
  同一顺序 ACB：
    相邻对累加（正确）   = 3
    任意前后对累加（错） = 6
    多算                 = 3
    多出来的是不相邻的组合：
      A(F0) -> B(F1) = 3  —— 两者之间还隔着 C，不是相邻对
  所以模型的换型项用**紧前工序**（circuit 弧）而不是成对的 before 变量：
  成对编码会让目标值大于 `objective_breakdown` 报的 `setup`，两套数就对不上了。

== 单机恒等式：Cmax = Σp + Σsetup ==
  Σp = 6，Σsetup = 3，和 = 9，Cmax = 9
  单机上工时总和是常数、换型只能往上加，所以「少换型」与「早完工」永远同向；
  想让换型真正改变决策，必须有多台机器可选（或别的会占用时间的约束）。

== G2：换型与完工时间真的打架 ==
目标                   Cmax    ΣT  setup   X 在哪台机器
makespan              100     0      5   M1
total_setup_time      101     0      0   M0

  手算两条排程：
    X 走 M1：B[0,1) 换型5 X[6,7)；M0 的 A[0,100) -> Cmax 100，setup 5
    X 走 M0：X[0,1) 同族不换型 A[1,101)；M1 的 B[0,1) -> Cmax 101，setup 0
  两条都不占优：`min Cmax` 拿 100 但要付 5 分钟换型，`min setup` 省下换型
  却要多等 1 分钟。**这就是 γ 必须由业务来定的原因**：
  加权和里 γ 取多少，等价于问「1 分钟换型值几分钟的完工时间」。
```

### 7.1 这张输出里值得逐行看的四处

**第一处：时间线 `M0 AA...CCBB   (0 -> 9)`。** 三个 `.` 就是 `A -> C` 的 3 分钟换型，
`CC` 与 `BB` 之间没有点，因为 `C` 与 `B` 同族。**换型在时间线上是一段可见的空白**，
不是记账上的一笔数。求解器返回的顺序是 `A, C, B`，
与手算的 `A, B, C` 并列最优（见第 5.1 节）。

**第二处：`相邻对合计 = 3（求解器报的也是这个数）`。** 两处一个数：
一处由脚本按相邻对逐项累加，一处由 `objective_breakdown` 反算，
还有一处是模型目标 `objective(setup)=3`。**三处相等**，才说明编码没跑偏。

**第三处：`相邻对累加（正确）= 3` 与 `任意前后对累加（错）= 6` 的并排。**
脚本刻意把错误做法实现出来（`naive_pairwise`），让「多算了多少」变成一个能打印的数
——`3`，正好是 `A -> B` 那一项。这不是一句「成对编码会高估」的断言，
而是一个可以被重复出来的数。

**第四处：`G2` 两行的 `X 在哪台机器` 列分别是 `M1` 与 `M0`。**
同一个实例、同一个模型，只换目标函数，`X` 就换了机器：
`min Cmax` 把它塞进 `M1`（付 5 分钟换型换回 1 分钟完工时间），
`min setup` 把它留在 `M0`（省下换型，多等 1 分钟）。
**这是「换型要单独进目标」的硬证据**——如果只优化 `Cmax`，换型的 5 分钟
只是被当成一个数字接受了，没有任何机会被拿出来讨论。

### 7.2 本日实验的三条结论

1. **换型是顺序相关的相邻间隔**：`A, C, B` 上只有两段间隔，合计 3；
   同族相邻的间隔是 0（`CC` 与 `BB` 之间没有空白）。
2. **单机恒等式成立**：`Σp 6 + Σsetup 3 = Cmax 9`。在单机上
   `min Cmax` 与 `min setup` 同向，不会打架——要造出取舍必须有机器选择。
3. **`G2` 上两条排程互不占优**：`(100, 0, 5)` 与 `(101, 0, 0)`，
   翻转点在 `γ/α = 0.2`。这个价只能由业务报。

## 10. 自测题

- Q1：换型时间为什么不能算进它前面那道工序的工时里？
- Q2：`G1` 的最优 `setup` 是 3，有两条顺序达到它。为什么求解器只返回其中一条？
- Q3：`A, C, B` 上「任意前后对」多算的那 3 分钟，具体是哪一对贡献的？
- Q4：单机上 `min Cmax` 与 `min setup` 同向。那为什么还要把 `setup` 写进目标？
- Q5：换型矩阵缺 `F1 -> F0` 时，模型为什么禁止 `F1` 后面接 `F0`，
  而不是按 0 分钟处理？
- Q6：`minutes = 0`（同族相邻）时那条不等式 `start[to] >= end[from] + 0` 还有用吗？
- Q7：哑元节点 `0` 的自环 `machidle` 表达什么？如果一台机器完全不加工任何工序会怎样？
- Q8：`G2` 里 `X` 走 `M0` 时与 `A` 同族，所以换型是 0。
  如果 `X` 是 `F1` 而 `A` 是 `F0`，两条排程的 `setup` 各变成多少？
- Q9：`G2` 的翻转点是 `γ/α = 0.2`。若业务说「1 分钟换型值 10 分钟完工时间」，
  该选哪条？
- Q10：`G1` 的换型矩阵不对称（3 vs 4），这对第 5.1 节的枚举有什么影响？
  如果改成对称的 4/4，最优值会变成多少？

### 参考答案

- A1：因为换型只在两道工序**相邻**时才发生。`A` 单独加工不需要换型，
  所以这 3 分钟不属于 `A`；`B` 的前一道若是同族的 `C`，也不需要换型，
  所以它也不属于 `B`。把它算进任何一道工序的工时，都会让
  「同一道工序单独加工」与「它在序列中加工」占用不同的机器时间，
  而机器时间必须是个确定的数。
- A2：因为两条的 `setup` 都是 3，**目标函数无法区分它们**。
  返回哪一条由搜索路径决定，不是「求解器觉得哪条更好」。
  要挑，就得再加一个次级准则（例如优先排交期早的）。
- A3：`A(F0) -> B(F1) = 3`。`A` 与 `B` 在顺序上一前一后，但中间隔着 `C`，
  机器从来没有从 `F0` 直接切到 `F1`。
- A4：因为在单机上它们是同向的，一旦有多台机器（`G2` 的 `X` 可选 `M0`/`M1`）
  或别的占用时间的约束，两者就可能打架。把 `setup` 写进目标是为了在
  **能打架的场合**把它的代价摆到桌面上；在不能打架的场合它是冗余的，
  但保留它不会改变最优解。
- A5：因为按 0 处理等于替车间宣布「这两个族之间不需要换型」，
  而矩阵缺项的真实含义是「我们不知道要多久」。模型给出一个排程、
  验证器按同样的矩阵一查却查不到这个方向，两边就会对同一个实例给出两种说法。
  禁止相邻关系后若无解，那是模型如实报告的 `INFEASIBLE`——
  该由业务补上矩阵，而不是由求解器猜。
- A6：有用。`minutes = 0` 时它退化成 `start[to] >= end[from]`，
  也就是普通的**不重叠**约束。如果没有它，两条同族工序就可能被排成重叠的，
  而重叠会被验证器报成 `overlap`。
- A7：表达「这台机器整段空闲」——哑元的自环被选中时，机器起点直接回到终点，
  没有任何工序落在它上面。一台完全不加工的机器就是它的所有工序都走自环。
- A8：`X` 走 `M1` 时：`M1` 上 `B` 也是 `F1`，同族换型 0，于是
  `M1: B[0,1) X[1,2)`、`M0: A[0,100)` → `(Cmax 100, setup 0)`；
  `X` 走 `M0` 时：`A` 是 `F0`，`F1 -> F0 = 5` → `X[0,1) 换型5 A[6,106)`
  → `(Cmax 106, setup 5)`。
  与原来正好**反过来**：现在 `X` 走 `M1` 在 `Cmax` 与 `setup` 上**同时**更好，
  取舍消失了——两个目标都会把它放进 `M1`。
  **一条实例上的取舍是数据的性质，不是方法的性质**：把 `X` 的族从 `F0` 改成 `F1`，
  `G2` 就不再是一个「换型与完工时间打架」的实例了。
- A9：`γ/α = 10 > 0.2`，所以选 `Q`（`X` 走 `M0`，`setup = 0`，`Cmax = 101`）。
  按加权和验算：`P: 1·100 + 10·5 = 150`；`Q: 1·101 + 10·0 = 101 < 150`。
- A10：不对称让「把 `F0` 放在最前面」比「把 `F0` 放在最后」便宜 1 分钟，
  所以 6 种顺序的 `setup` 分成 `{3, 3, 4, 4, 7, 7}` 六个数而不是三个值。
  改成对称的 4/4 之后，六种顺序的 `setup` 是
  `A,B,C: 4`、`A,C,B: 4`、`B,A,C: 8`、`B,C,A: 4`、`C,A,B: 8`、`C,B,A: 4`——
  最优值从 3 变成 4，而达到它的顺序从 2 条变成 4 条。
  **换型矩阵的对称性直接决定并列解有多少条**。

## 11. 今日一句话总结

> **换型是顺序相关的相邻间隔，不是工序的固有属性**：`G1` 的六种顺序全部手算枚举，
> 最优 `setup = 3` 由两条顺序并列达到（求解器返回 `A, C, B`），
> 时间线上 `AA...CCBB` 里那三个 `.` 就是换型本身；同一顺序上
> 「任意前后对」会把总换型从 `3` 高估到 `6`（多算的是不相邻的 `A -> B`），
> 所以模型用紧前弧（`immediate-predecessor circuit arcs`）而不是成对变量；
> 单机恒等式 `Cmax = Σp + Σsetup`（`6 + 3 = 9`）说明单机上两个目标同向，
> 而 `G2` 的 `(100, 0, 5)` 与 `(101, 0, 0)` 才是真取舍——翻转点 `γ/α = 0.2`
> 只能由业务来报。
