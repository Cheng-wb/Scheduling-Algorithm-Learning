## 2. 为什么单目标不够

Day 1 的 `D1` 实例留下一个刺眼的结论：`Cmax = 12` 的最优排程里，`ΣT` 可以是 5，
也可以是 0。`Cmax` 这个目标函数在它们之间**没有任何偏好**，于是「求解器证明了最优」
这句话只对 `Cmax` 成立，对迟交一个字都没说。

工厂里没有一个车间主任会接受「我们 `Cmax` 最优，至于迟到多少不关我事」。
真实的目标是**同时**关心的几件事的折中：

```text
Cmax  ->  产线什么时候能空出来接下一批
ΣT    ->  客户答应的时间守没守住
setup ->  换型耗掉的机时与人工
```

把这几个分量塞进同一个数里，是最常见的做法：**加权和**。

---

## 3. 定义：加权和，以及权重到底是什么

**定义（加权和 `weighted sum`）**：给定权重 `α, β, γ >= 0`，一条排程 `S` 的加权和是

```text
f(S) = α · Cmax(S) + β · ΣT(S) + γ · setup(S)
```

模型最小化 `f(S)`。三个分量都由 `fjsp_core.objective.objective_breakdown` 从排程反算，
不由求解器直接报出。

**定义（Pareto 最优）**：若不存在另一条排程 `S'` 使三个分量**都不劣于** `S` 且至少一个**严格更好**，
则称 `S` 是 Pareto 最优的。

**理论结论 1（加权和一定是 Pareto 最优的）**：若 `α, β, γ > 0` 且 `S*` 最小化 `f`，
则 `S*` 是 Pareto 最优的。论证是三行反证：若存在 `S'` 在三个分量上都不劣且至少一个严格更好，
乘上正权重相加就得到 `f(S') < f(S*)`，与 `S*` 最小化 `f` 矛盾。

**理论结论 2（加权和覆盖不到全部 Pareto 点）**：加权和只能取到落在可行结果集**凸包**上的
Pareto 点（称为支持性的）。凸包内部的 Pareto 点，无论怎么调正权重都取不到。
所以「扫一遍权重」是探索，不是穷举——想拿到凸包内部的点需要换方法（例如把某个分量写成约束再优化另一个）。

**理论结论 3（权重是价格，不是换算）**：`β` 与 `α` 的**比值**才是信息：
`β / α` 说的是「1 分钟迟交值多少分钟的完工时间」。把 `α` 固定为 1 之后，
`β` 就是这个价格。所以：

- 把 `(α, β, γ)` 整体乘以 2，不改变最优解（加权和是正齐次的）；
- 但把 `β` 单独改一点，就可能换一条排程——这才是有信息量的方向。

**实验观察 1**：在实例 `T` 上，`(α, β, γ) = (1, 0, 0)` 选出的排程里 `ΣT = 9`，
而 `weighted_tardiness = 25`。两个数差两倍多，只因为订单 `J1` 的权重是 3。
下面第 5.3 节会说明这两个量在模型里的地位完全不同。

## 4. 推导：两条候选排程在 `β` 轴上的决胜条件

### 4.1 为什么只需要看两条排程

实例 `T` 只有 4 道工序（每单 1 道）、2 台机器，机器选择的空间极小：
`A`、`B` 只能在 `M0`，`C` 只能在 `M1`，只有 `D` 可选 `M0`（4 分钟）或 `M1`（2 分钟）。
把「`M0` 上的顺序」与「`D` 去哪台机器」组合起来枚举，会得到两条**互相不占优**的候选：

```text
S1 = (Cmax 9,  ΣT 9, setup 2)   M0: A[0,6)  换型1 B[7,9)   M1: C[0,5) 换型1 D[6,8)
S2 = (Cmax 16, ΣT 2, setup 9)   M0: B[0,2)  换型8 A[10,16)  M1: C[0,5) 换型1 D[6,8)
```

两条排程的 `D` 都在 `M1`（2 分钟更快），差别在 `M0` 上的**顺序**：
`S1` 先做长的 `A`（同族 `D` 在 `M1`，`M0` 上只需一次 1 分钟的换型），
`S2` 先做急的 `B`（把 1 分钟的换型换成 8 分钟的换型，换来 `B` 提前 7 分钟完工）。

### 4.2 决胜条件

令两条排程的加权和相等，解出 `β` 的临界值：

```text
α·9  + β·9  + γ·2  =  α·16 + β·2  + γ·9
       7β          =  7α + 7γ
        β          =  α + γ
```

```text
β < α + γ   ->  S1 严格更好（Cmax 与 setup 都占优）
β > α + γ   ->  S2 严格更好
β = α + γ   ->  两条排程的加权和**完全相等**
```

**理论结论 4（翻转点等于分量差额之比）**：这个结论不是实例特有的。
若两条排程满足 `ΔCmax = -ΔΣT`（一个变好多少、另一个就变差多少，方向相反、幅度相同），
那么决胜条件就是 `β / α = ΔCmax / ΔΣT = 1`。本例的差额是 `+7` 与 `-7`，
再叠上 `setup` 的 `-ΔCmax` 关系（`S2` 的 setup 多 7 分钟），就得到 `β = α + γ`。
**权重之比就是两个分量的交换率**，这句话在下面第 5.2 节的表里会变成一个逐行可核对的数。

### 4.3 并列不是翻转

`β = α + γ` 时两条排程的加权和相等（取 `α = 1, γ = 0` 就是 `β = 1`，两条都是 18.00）。
此时**两条都是最优解**，求解器返回哪一条都合法。所以：

- 「`β` 从 0.5 增到 1.0，排程从 `S1` 翻到 `S2`」是一句错话；
- 正确的读法是「`β = 1` 是并列点，两侧才是各自的严格最优区」。

这条纪律和 Day 1 的 `Cmax` 并列解是同一条：**目标函数值相等的地方，排程不由目标决定**。

## 5. 手算：实例 `T` 的逐项核算

实例 `T`：

```text
工序   订单    可上机器(p)         族     交期 d   权重 w
A      J0    M0(6)              F0     100     1.0
B      J1    M0(2)              F1       1     3.0
C      J2    M1(5)              F0       4     1.0
D      J3    M0(4) M1(2)        F1      30     1.0
换型：F0 -> F1 = 1 分钟，F1 -> F0 = 8 分钟
```

### 5.1 三条排程的 `breakdown` 核算

`S1`（`M0: A[0,6) 换型1 B[7,9)`，`M1: C[0,5) 换型1 D[6,8)`）：

```text
Cmax  = max(9, 8) = 9
ΣT    = (6-100)^+ + (9-1)^+ + (5-4)^+ + (8-30)^+
      = 0 + 8 + 1 + 0 = 9
setup = 1 (A->B 跨族) + 1 (C->D 跨族) = 2
```

`S2`（`M0: B[0,2) 换型8 A[10,16)`，`M1: C[0,5) 换型1 D[6,8)`）：

```text
Cmax  = max(16, 8) = 16
ΣT    = (2-1)^+ + (16-100)^+ + (5-4)^+ + (8-30)^+
      = 1 + 0 + 1 + 0 = 2
setup = 8 (B->A 跨族) + 1 (C->D 跨族) = 9
```

两条的三个分量都对上了第 4.1 节给出的元组。

### 5.2 `β` 轴上的胜负（手算）

固定 `α = 1`、`γ = 0`，只让 `β` 变：

```text
β      S1 的 1·9  + β·9     S2 的 1·16 + β·2     谁赢
0.0    9.00                 16.00                S1
0.5    13.50                17.00                S1
1.0    18.00                18.00                并列
2.0    27.00                20.00                S2
4.0    45.00                24.00                S2
```

这张表有两个用途：一是验证 `β = 1` 是并列点；二是说明**权重不是「重要性打分」**：
`β` 从 0.5 到 2 只变了 4 倍，胜负就翻了过来——因为这个实例里两条排程的
`Cmax` 只差 7 分钟、`ΣT` 也只差 7 分钟，交换率本来就在同一个数量级。

### 5.3 `ΣT` 与 `weighted_tardiness` 是两个量

在 `S1` 上：

```text
ΣT                  = 9    （每个订单的迟交分钟数直接相加）
weighted_tardiness  = 25   （J1 权重 3：它的 8 分钟迟交要乘 3，其余按 1：8×3 + 1×1 = 25）
```

模型最小化的是**前者**。`Job.weight` 目前只进 `weighted_tardiness`（一个独立的复核函数），
**不进** `fjsp_cpsat_multiobj` 的目标。这件事必须说清楚，否则很容易误以为
「我给急单设了权重，模型就会优先它」——不会。

```text
想让订单权重真的影响排产      ->  要改目标表达式（把权重乘进 ΣT 的每一项）
只想事后看一眼带权迟交是多少   ->  用 weighted_tardiness，它不改选择
```

### 5.4 为什么第三条排程会出现

权重取 `(0, 0, 1)`（只看换型）时，求解器返回的是**第三条**排程：

```text
M0: A[0,6) 换型1 D[7,11)  B[11,13)    M1: C[0,5)
setup = 1 (A->D 跨族) + 0 (D->B 同族) + 0 (M1 只有 C) = 1
```

`D` 从 `M1` 挪到 `M0` 之后，`M1` 上只剩 `C` 一道工序，换型总量降到 1 分钟——
这是 `setup` 的最小值。这条排程的 `Cmax` 是 13、`ΣT` 是 13，都不好看，
但「只看换型」的目标对它们无感。**换一个目标就换一条排程**，这是多目标的常态。

## 6. 实现：目标是怎么被建出来的

模型在 [industrial.py](../../projects/03_industrial_fjsp/fjsp_shop/industrial.py)。
三个分量各由一个变量（或表达式）承载，最后交给 `Minimize`：

```python
cmax: Any = None
if job_end:
    cmax = model.NewIntVar(0, horizon, "Cmax")
    model.AddMaxEquality(cmax, list(job_end.values()))
tardiness: dict[str, Any] = {}
for job in instance.jobs:
    if job.due_date is None or job.id not in job_end:
        continue
    var = model.NewIntVar(0, horizon, f"T[{job.id}]")
    model.AddMaxEquality(var, [job_end[job.id] - job.due_date, 0])
    tardiness[job.id] = var
```

`setup` 那一项不是变量，而是换型弧上的**常数和**：

```text
目标 = α·Cmax + β·Σ_j T_j + γ·Σ_(换型弧) setup(弧)
```

权重从 `spec` 里解析出来（`fjsp_core.objective.parse_weights`），乘一个常数再取整
（`OBJ_SCALE = 1_000_000`）成为 CP-SAT 的整数系数。取整这一步引入了今天唯一需要留意的
实现细节：

```text
mode = "none"     ->  系数 = 权重 × OBJ_SCALE，权重是整数倍时**没有舍入**
                      => 模型目标与报告目标有确定的换算关系，best_bound 能报数
其他归一化口径     ->  系数要除以分母，一般会舍入
                      => 模型目标与报告目标之间没有确定的换算关系，best_bound 只能报 None
```

本日全部用 `mode = "none"`，把归一化的问题先放在一边。

另外两处纪律：

1. **报告值与模型值分开**。`result.objective` 是求解器在它自己的整数目标上算出来的，
   `objective_breakdown(instance, schedule)` 是**另一条路径**——从排程的时间线反算三个分量。
   两者逐行相等，才能排除「目标函数写错了但没人发现」。
2. **权重不接受负值**。负权重会让「加权和最小化」变成无下界或无意义的优化，
   `parse_weights` 直接拒绝。业务上想表达「这项越少越好、没有下限」是另一类问题。

### 7.1 这张输出里值得逐行看的四处

**第一处：候选排程的「指纹」与求解器返回的完全一致。** 脚本把 `S1`、`S2` 的机器顺序
**手写**成指纹 `M0:A@0-6,B@7-9;M1:C@0-5,D@6-8`，再和求解器实际返回的排程对读。
只有两边相符，后面「求解器的选择与手算预测对照」那张表才成立——
否则它只是在比较两段互不相干的文字。

**第二处：`模型报的 obj` 与 `手算` 两列逐行相等。** 五个设置、五个数对，全部相等。
这不是自动成立的：模型里 `setup` 那一项是换型弧上的常数和，`ΣT` 是一组 `AddMaxEquality`
推出来的变量，任何一处写错都会让两列分岔。

**第三处：`β = 1` 那一行的 `18.00` 与 `18.00`。** 这是**精确**相等，不是「显示成两位小数
恰好一样」。它对应第 4.3 节的纪律：并列点上不能谈翻转。

**第四处：`只看 setup` 那一行的 `第三条排程`。** 预测列写「不适用」而不是硬猜，
是因为 `β <= α + γ` 这个规则只在 `α = 1, γ = 0` 的族里推导过。
把 `S1`/`S2` 之外的排程标成「第三条排程」而不是强行归类，也是同一条纪律：
**没有推导过的情形不预测**。

### 7.2 本日实验的三条结论

1. **权重就是交换率**：`β = α + γ` 是 `S1` 与 `S2` 的并列点，与手算的 `7β = 7α + 7γ` 一致。
2. **模型与手算没有分岔**：五个设置的 `objective` 与 `αCmax + βΣT + γsetup` 逐行相等。
3. **带订单权重的迟交不在模型里**：`ΣT = 9` 而 `weighted_tardiness = 25`，
   模型最小化的是前者。想让权重影响排产，必须改目标表达式。

## 10. 自测题

- Q1：`α`、`β`、`γ` 里把哪个固定成 1 是随意的吗？固定 `α = 1` 与固定 `β = 1` 有什么区别？
- Q2：`S1` 的 `ΣT = 9`，其中 `B` 迟到 8 分钟、`C` 迟到 1 分钟。为什么 `A` 与 `D` 的迟交都是 0？
- Q3：`S1` 的 `Cmax` 是 9，`M1` 上的完工时刻是 8。`Cmax` 取的是哪个数？
- Q4：把 `(1, 1, 1)` 整体乘以 3 得到 `(3, 3, 3)`，最优排程会变吗？为什么？
- Q5：`β = 1` 时求解器返回 `S1`。能不能说「在并列点上求解器偏向 `Cmax` 小的那条」？
- Q6：`只看 setup` 那一组的排程 `Cmax = 13`、`ΣT = 13`。它是不是 Pareto 最优的？
- Q7：如果给 `Job.weight` 设成 `J1 = 100`，模型会优先 `J1` 吗？为什么？
- Q8：`S2` 的 setup 是 9，其中 8 分钟来自 `B -> A` 的跨族换型。能不能让换型发生在
  `M0` 空闲的时候，从而「藏起来」而不计入 `setup`？
- Q9：`best_bound` 在 `mode = none` 下能报数。这对「模型报的 obj」与「手算」的对照有什么帮助？
- Q10：加权和只能取到支持性的 Pareto 点。在本日的实例上，你能说出一个「凸包内部」的点吗？
  如果说不出来，这说明了什么？

### 参考答案

- A1：固定哪个都行，但**固定 `α = 1` 最省事**：加权和是正齐次的，整体缩放不改变最优解，
  所以可以把 `α` 归一成 1，用 `β`、`γ` 两个数表示「相对完工时间，1 分钟迟交/换型值多少」。
  固定 `β = 1` 也可以，只是解读时要反过来算 `α` 的含义。
- A2：因为 `A` 在 6 分钟完工，交期是 100；`D` 在 8 分钟完工，交期是 30。
  两者都远早于各自交期，`max(0, C_j - d_j) = 0`。
- A3：取 9。`Cmax = max_j C_j` 是所有订单完工时刻的最大值，`M0` 上 `B` 在 9 完工，
  虽然 `M1` 早就空了，`Cmax` 仍由最晚的那个订单决定。
- A4：不会变。`f` 整体乘 3，任意两条排程的大小关系不变，最优解集合完全相同。
- A5：不能。求解器返回 `S1` 可能是因为它先找到了 `S1` 并且 `18.00 = 18.00` 已经满足最优性，
  也可能因为搜索顺序、编码方式。**并列点上没有任何信息能推断偏好**——
  要拿到偏好，就得打破并列（例如给 `Cmax` 加一个极小的次级权重）。
- A6：是。它的 `setup = 1` 已达到最小值 1，任何排程都不可能更低；
  而 `Cmax = 13` 的最优值是 9、`ΣT = 13` 的最优值是 2——它的另外两个分量都差，
  但没有一条排程能在三个分量上都不劣于它且至少一个严格更好（因为 `setup` 已经到底）。
  这正是 Pareto 最优的含义：**不占优，不代表各项都好**。
- A7：不会。`Job.weight` 目前不进模型目标，它只进 `weighted_tardiness`，
  那是一个事后复核函数。把 `J1` 的权重设成 100 对求解器没有任何影响。
- A8：不能。换型是**顺序相关**的：只要 `M0` 上 `B` 在 `A` 之前加工，`B -> A` 这个跨族转换
  就必然发生，那 8 分钟必须落在 `B` 的完工与 `A` 的开工之间。
  「藏在空闲里」是文字游戏——它本来就发生在空闲里，但机器的可用时间照样少了 8 分钟。
- A9：有帮助。`mode = none` 下模型目标与报告目标有确定的换算关系，
  所以 `best_bound` 能换算回原始单位，可以与 `objective`、与手算值三方对照。
  归一化之后这条通道就断了。
- A10：本日实例上说不出来，因为两条候选排程互相不占优、各自都在某个方向上最优，
  凸包就是连接它们的线段，没有内部 Pareto 点。这说明「支持性」这个限制
  在很小的实例上往往看不出来——要构造一个反例，需要至少三个分量同时参与、
  且存在一条「各项都居中」的排程。**说不出反例不等于限制不存在**，
  只说这个实例太小，照不出来。

## 11. 今日一句话总结

> **加权和把三个分量压成一个数：`f = α·Cmax + β·ΣT + γ·setup`，而权重之比就是交换率——
> 实例 `T` 上两条排程的决胜条件是 `β = α + γ`（差额各 7 分钟），`β = 1` 那一刻两条的加权和
> 精确相等（都是 `18.00`），所以那一行只能读成「并列」；五组权重下模型报的 `objective`
> 与手算的 `αCmax + βΣT + γsetup` 逐行相等，而 `ΣT = 9` 与 `weighted_tardiness = 25`
> 的差别提醒我们：带订单权重的迟交**不在模型里**。**
