# 第 7 章　综合实训：从实例到可信的工业排程报告

[教材目录](../README.md) · [上一章](06_资质资源与锁定工序.md)

M3 的交付不只是一个 `Cmax` 数字，而是一条可复核链：输入实例、方法及配置、求解结果、独立验证、目标分量、KPI 和实验来源。本章用三个小任务把前六章连起来，再说明如何读取项目的完整批次。

## 7.1 实训一：选机和排序同时决定工期

两个订单：J1 有 A→B，A 在 M1/M2 工时为 2/4，B 只能在 M2 用 2；J2 只有 C，C 在 M1/M2 工时为 2/3。三道工序均在 0 释放，无其他约束。求一份工期不超过 4 的排程，并说明为何 3 不可能。

**逐步解答。** 选 A@M1 `[0,2)`、C@M2 `[0,3)`、B@M2 `[3,5)` 得 5；还不够。换为 C@M1 `[0,2)`、A@M1 `[2,4)`、B@M2 `[4,6)` 更差。尝试 A@M1 `[0,2)`、B@M2 `[2,4)`、C@M1 `[2,4)`，得到工期 4，且三道工序、两台机器都满足要求。J1 最短链 A+B 为 4，所以任何排程都不能在 3 完工。上下界同为 4，最优性已证明。

这个例子里同机相接允许，M1 的 A `[0,2)` 与 C `[2,4)` 不重叠。若把 C 分给 M2 并排在 B 前面，J1 会等待机器，工期变成 5；“给独立订单并行机器”也未必最优。

## 7.2 实训二：逐层加入真实约束

沿用上一题的工序，并假设 M1 在 `[2,3)` 维护。原工期 4 的排程是否仍可行？如果又把 A 锁定为 M1、开始时刻 0，怎样重新排？

**逐步解答。** 原排程把 C@M1 放在 `[2,4)`，与维护 `[2,3)` 相交，因此无效。A 仍可在 M1 `[0,2)`，B 在 M2 `[2,4)`；C 若选 M2，需要 3 分钟，最早可在 `[4,7)` 加工，工期 7。也可让 C 在 M1 `[3,5)`，与维护相接后加工，工期 5；因此当前找到上界 5。A 锁 M1@0 后，这份工期 5 的排程仍满足锁定。J1 链给下界 4，但是否存在工期 4 还须排除其他选机和时序：C 若选 M1，只能排在 A 前、A 后或跨维护。排在 A 前会与锁定 A 冲突；排在 A 后最早 3 开工，完工 5；不能跨维护。C 若选 M2 且工期≤4，需最晚 1 开工；它从 0 到 3 会阻挡 B `[2,4)`，而 B 必须在 A 完成后的 2 开工才能在 4 前完成。故 4 不可达，5 最优。

这里特意把手算分成“先找可行解”和“再排除更好解”两步；只算出工期 5 不是证明。

## 7.3 实训三：读一条求解记录

假设一个工业实例在 15 秒预算下，方法 X 返回 `FEASIBLE`、目标 80、下界 60；方法 Y 返回 `FEASIBLE`、目标 78、下界 62。两者的排程都经独立验证，但 X 使用精确换型，Y 使用保守换型膨胀。应该怎样报告？

**逐步解答。** 可以报告“在这次预算内，Y 找到的可行排程目标 78，小于 X 的 80”，并附上状态与预算。不能说 Y 的模型更准确，也不能由这两行断言 Y 的全局最优值更小。两模型的可行域不同，`best_bound` 只对各自模型和目标有效；比较原问题的最优性时，需要明确哪一条界真正适用于原问题。把每份排程重新送入原问题的独立验证器，可以比较它们作为**真实可行上界**的质量。

## 7.4 一份报告至少记录什么

| 项 | 要回答的问题 |
|---|---|
| 实例与输入 hash | 两种方法是否真的解同一份输入 |
| 方法、目标、约束覆盖 | 算的是同一个问题吗 |
| 时间预算、种子、线程 | 这次运行的条件是什么 |
| 状态、目标、有效下界、gap | 有解吗，证明到什么程度 |
| 独立验证诊断 | 排程真的满足业务约束吗 |
| `breakdown`、KPI | 哪个分量改善、哪个分量付出代价 |
| 运行文件与源码版本 | 别人能否定位这次结果 |

KPI 不等同于优化目标。工期、总迟交、资源利用率、机器负载与换型占比各有口径；利用率尤其要说明分母是机器可用时间、总跨度还是别的区间。项目的 [kpi.py](../../projects/03_industrial_fjsp/fjsp_io/kpi.py) 集中计算指标；[json_bundle.py](../../projects/03_industrial_fjsp/fjsp_io/json_bundle.py) 把实例、结果、KPI 存成版本化 bundle，读回后逐字段比较。归档中的 KPI 是当时的报告数据，读回时不应悄悄重算成另一口径。

## 7.5 运行与复核

在项目目录先安装依赖，再运行测试；具体版本和环境要求见[项目指南](../../projects/03_industrial_fjsp/PROJECT_GUIDE.md)。以下命令从仓库根目录运行月度批次，并把结果写到一个新的输出目录：

```powershell
python projects/03_industrial_fjsp/examples/m3_month3_benchmark.py --output projects/03_industrial_fjsp/artifacts/my_month3_review
```

该命令会实际执行跨方法实验，求解可能耗时；输出目录须为空或不存在。先读 `config.json`、`metadata.json` 和 `instances/*.json`，再读 `results.csv`；挑一行到 `runs/*.json` 核对完整排程及验证诊断。不要把 `summary.csv` 的最好可行值当作最优证书。

各周笔记与项目脚本的入口见[项目指南](../../projects/03_industrial_fjsp/PROJECT_GUIDE.md)。建议先完成第 1–2 章的纸笔小例，再运行 Week 1；第 3–4 章对应 Week 2；第 5、6 章分别对应 Week 3、Week 4。原有每日笔记保留更细的实例和实验输出。

## 7.6 结业自测

1. 同一 FJSP 工序在 M1 用 3、M2 用 5，排程选 M2 时，应以哪个工时核验？**答：5。**
2. `Job.operation_ids` 和 `Schedule.operations` 的顺序都表示工艺先后吗？**答：前者表示订单内先后；后者的元组顺序不表示时间或工艺先后。**
3. 机器无重叠、订单有序是否足以证明工业排程合法？**答：不足，还要检查日历、维护、资质、人员、锁定和换型等实例实际启用的约束。**
4. `FEASIBLE 78, bound 62` 能否写“最优 78”？**答：不能；78 是已知可行上界，62 是该模型和目标下的下界。**
5. 两个模型使用不同换型编码，为什么不能只按目标值评价建模质量？**答：可行域和有限预算内的搜索难度都不同；应先核查原问题语义，再比较经独立验证的排程与有效证书。**
